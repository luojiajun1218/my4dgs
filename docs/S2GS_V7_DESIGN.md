# V7：在 S²GS 上做按需细化的 gate 层级

## 一眼看懂当前方案

```text
首帧：原 S²GS 训练；两组实验从同一首帧快照出发
后续每帧：按 S²GS 原 root 分组训练 Gate（前 100 step）
         → 只对仍需更新、内部动静混杂且有预计净收益的区域 SPLIT
         → 子 Gate 继承父 Gate，继续优化；最多到四层
         → 最终 OFF/UPDATE 只决定逐点位置 offset 是否启用
         → 颜色、尺度、旋转、透明度维持 S²GS residual 更新路径
```

共享运动目前关闭；它和 Gate 是两个不同模块，不把「区域 UPDATE」误认为「区域所有点共用同一个位移」。每帧重新从 root 判断，因此上一帧 OFF 不会永久锁死本帧。当前要证明的也不是“树越深越好”，而是相同首帧、相同预算下，至少一个完整序列指标改善，其他指标不明显退化。

## 要解决的事

V6 在第 184 帧停止。它的测试 PSNR、估算存储、FPS、训练时间均未超过 S²GS。明确的表示成本是：每个终止 UPDATE 区域保存 3 维平移和 3 维旋转（均为 FP32），同时大量 Gaussian 还保存逐点 offset。第 184 帧约 6875 个 UPDATE 区域只覆盖约 23473 个点，平均每区约 3.4 点；共享运动没有摊薄到足够多的点。首帧独立训练也有超过 1 dB 的波动，因此 PSNR 的因果比较必须先固定同一个首帧模型。

V7 保留用户的核心：从粗区域开始；静态区域 OFF；只有动静混杂、细分可能有用的区域 SPLIT；最多四层。首轮实现先收缩到 **S²GS 原有 residual + 原有 Gate 的可变空间分组**：这里的 OFF/UPDATE 先只控制 offset residual；颜色、尺度、旋转等属性继续走 S²GS 原有更新路径，不把 OFF 误写成「所有属性均冻结」。共享运动不是每个 UPDATE 的默认负担；仅当大区域确有共同运动且画质收益足以支付新增 bit 时，才作为后续可选扩展。V7 首轮试跑不开启共享运动。

## 首轮 V7 的决定

1. 首帧使用同一个可信快照启动 S²GS 对照和 V7，不能只靠相同 seed。首帧训练、数据、增密仍保持 S²GS 原样。快照应在首帧的 `prev_atts` 等顺序状态建立之后保存；第二帧恢复数据加载位置及随机状态。
2. 每个后续帧从 S²GS 的 root 分组开始，用原有 view-space gradient difference 形成动态线索。粗区域内如果动态性一致，就停在这一层。只有至少两个点、动静混杂、空间子格子真正不同，并且预计关闭静态点节省的 offset bit 超过新增拓扑/gate 开销，才按空间格子分出下一层。递归最多四层；不能为了凑层数拆。首帧场景的实测 root 占用为：38,005 个 root 对应 62,275 个 GS，其中 21,832 个 root 恰有 2 个 GS，1,195 个恰有 3 个，只有 16 个有 4 个，最大为 4。因此“至少 8 点才拆”会完全失效，V7 需要允许有收益的二点区域细分。
3. 终止区域使用原版 S²GS `Gate` 的优化和 offset residual；在不同区域上只是共享 gate 的范围不同。新帧先取出上一帧**实际渲染过的逐点属性**作为 residual 基线，再按当帧线索重建分组，不能让旧 gate 关闭的隐含 residual 在下一帧突然出现。子区域从父区域所代表的状态出发，保留可重新开启的能力。记录明确的 OFF/UPDATE/SPLIT 拓扑，而不是只留下 point-to-gate 映射。基线 S²GS 的初始化和 residual 路径必须保持原样，V7 专用的状态修正不能泄漏到对照组。
4. 后续帧沿用 S²GS 的 400 step 正常 GS 优化，不再拿前 100 step 冻结全部 GS 来拟合大量区域运动，也不默认增点。这样训练和渲染路径尽量贴近基线。首轮的 SPLIT 主要由动态线索异质性和预计 bit 收益决定；若需要，再引入图像误差的逐层验证，不把新复杂度一次加满。
5. 所有新增拓扑 bit 必须计入与 S²GS 同口径的 `size()` 估算。子格子应由上一帧已知的 GS 位置、root ID 和固定网格规则重建；若采用这种隐式编码，就保存分裂节点标识/状态，不能一面声称无需坐标，一面依赖 `.pt` 中的全精度坐标才可解码。报告要明确区分理想 bit 估算与调试用 `.pt` 文件的实际字节数，也不能把两种方法含义不同的 `Active gates` 直接相减。另一个基线局限是 S²GS 的 `size()` 本身不计入动态帧仍可训练的 anchor 变化；V7 首轮保持同样的 anchor 更新路径，让漏计尽可能在两边相同，但不能把这个估算称为真实码流大小。

实现上，root 占用和动态点数必须用一次 `bincount`/scatter 求出；只遍历少量真正混杂的候选 root。对约 3.8 万个 root 逐个执行一次全点扫描，会把省下的训练时间全部耗掉，属于验收前必须排除的性能错误。

## 自动实验的闸门

先做同一首帧快照出发的短跑检查正确性，再做到至少 120 帧看后段趋势；10 帧的早期优势不能作为跑满 300 帧的依据。只有长段结果接近目标才跑满 300 帧，并用完整序列判断是否达标。

暂用以下可操作标准定义“提升且其余接近”：至少一项达到测试 PSNR +0.2 dB、估算动态帧存储 −10%、FPS +5% 或训练时间 −5%；其余指标控制在 PSNR −0.2 dB 以内、存储/时间不高于 1.1 倍、FPS 不低于 0.9 倍。比较采用首帧单列、动态帧同区间平均，并查看前/中/后段，避免前 10 帧掩盖后半段退化。这些是实验筛选阈值，不是方法本身的 loss 权重。

若 V7 首轮没有达到闸门，先检查 OFF/UPDATE/SPLIT 的实际点数、offset 非零点数、分裂次数和存储分解。优先修正过宽的 UPDATE 或错误的 split 收益估计；不通过盲目增加层数、训练步数、共享运动参数来掩盖问题。

## 首轮配对结果与下一步（2026-09-25）

同一首帧快照恢复 F2–30，V7 与当前工作树的 S²GS 对照分别为：测试 PSNR `31.710 / 33.128 dB`，S²GS 口径的估算动态帧存储 `0.0286 / 0.0307 MB`，测试视角 FPS `288.90 / 249.38`，训练帧时间 `9.07 / 9.02 s`。V7 的速度、估算存储改善伴随 `−1.417 dB` 画质退化；F11–20 的差值达到 `−2.637 dB`，**不通过验收闸门，不继续跑 120/300 帧**。两条 30 帧结果在 `output/paired_30_20260925_{baseline,v7}`；首帧快照 SHA256 为 `d96835a8d33d9505d1944e31e94244dcaa4eca88a4948dfc1ae7dae9debeb30e`。

问题更可能在时序决策，而非 400 step 数量：当前 V7 在优化前，便把约 3000 个 cue 混合的 root 拆开，并假设每个 cue-negative 点可省 96 bit；但原 root Gate 可能本来就会 OFF，此时“节省”是虚构的。子 Gate 从低概率开始时，真正需要更新的点也可能过早关闭；上一帧 Gate 还会影响下一帧 `sq_res` 属性 decoder 的残差通路。后段画质恶化与这些机制相符，但因果尚需后续实验确认。

下一候选 V7b 保持每帧 400 step 总预算：先按原 S²GS root Gate 正常优化约 100 step，得到粗层 OFF/UPDATE 与局部未解释 residual；只对仍 UPDATE、子区域动态性不均匀、静态候选 residual 较低、且预计节省大于拓扑/新 Gate 成本的 root 做 SPLIT；新子 Gate 继承父 logit，再用余下约 300 step 正常优化。上一帧 OFF 区域在本帧出现新动态线索时，必须可以重新启用所有需要的 residual 属性，不能因旧 Gate 永久冻结。每帧重新判定 OFF/UPDATE/SPLIT，最多四层，不为凑层数细分。实现和试跑须重新做同首帧、同区间配对，不复用 V7 失败结果作为对照。

更具体地，V7b 只在本方法分支解除一个不合意的耦合：S²GS 的 `LatentDecoderRes` 把上一帧 offset Gate 乘到所有 `sq_res` 属性上，即使该属性没有配置 Gate；这样旧 OFF 可能把下一帧颜色、旋转、尺度、不透明度的 residual 永久乘零。V7b 对未开启相应 Gate 的属性不再传旧 offset Gate，仍由原 RGB loss 和原 residual decoder 更新；对照组代码行为不变。由于这些属性的 latent 仍被原 `size()` 逐维估算，不引入未计的 cue-side mask。当前方法的终止 OFF/UPDATE 状态也应严格解释为 **offset Gate 状态**，不宣称 OFF 会冻结全部属性。

层级真正的先粗后细过程拟按 step 100、200、300 检查各级终止 UPDATE 节点，每次最多深入一层，step 400 完成当前帧；无候选时不重建 Gate。每次重分组时子 Gate 直接继承父 `log_alpha`，切换前后逐点 gate 值应一致，避免把“细分初始化冲击”误当作质量变化。若实现先只覆盖第一轮细分，日志/文档必须明示实际最大层数，不能把配置上的四层写成已经发挥作用。

存储报告必须分三栏：S²GS 原 `size()` 口径的估算、必要拓扑/门控的紧凑码量、实际输出目录字节。当前逐帧 `.pt` 是包含节点字典、所有 terminal、point-to-group 映射等重复信息的 **verbose 调试件**；V7b 的 F2/F3 烟测分别写出约 5.50/5.48 MB，而日志的估算仅 0.05188/0.04181 MB，绝不能把后者称为前者的磁盘占用。若推进完整 300 帧，应默认只保存紧凑 sidecar，verbose 显式 opt-in；紧凑 sidecar 仍需存 split path 和足以重现渲染的 gate 等级（当前 Gate 量化到 0.1 档，只有二值 OFF/UPDATE 不够）。S²GS `size()` 也漏计每帧 anchor 变化，故现阶段与它比较的存储只能标注为同口径代理指标，非真实可解码码流。

V7b 已按上述 staged gate + 属性解耦实现。相同首帧快照的完整 F2–30 配对：V7b / S²GS 测试 PSNR `34.352 / 32.597 dB`（+1.755），估算存储 `0.0330 / 0.0309 MB/帧`（约 +6.6%），测试视角 FPS `278.90 / 242.38`（约 +15.1%），训练帧时间 `9.20 / 9.10 s`（约 +1.0%）。早/中/后段 PSNR 差分别为 +1.26/+1.66/+2.31 dB；V7 的后段塌陷没有在这个短区间复现。V7b 每帧实际仅接受 27–153 个 split，平均约 92；35 次细分切换均通过逐点 Gate 连续性检查。**30 帧达到筛选闸门，但不是 300 帧结论**；先解决 verbose sidecar，再做至少 120 帧配对，观察后段 PSNR 与实际磁盘开销。

## 紧凑编码复验与当前判定（2026-09-25）

V7b 的默认 sidecar 已改为紧凑表示：基于上一帧固定的 root ID、GS 位置和体素规则重建分组，只另存拆分路径以及量化到 `0, 0.1, …, 1` 的终止 Gate 档位；完整节点字典改为显式调试选项。保存前立即解码核对逐点 group ID 与 Gate，31 次连续性检查全部通过。F2–30 的 29 个 sidecar 合计 `554,876 B`，平均约 `19.1 KB/帧`，远小于之前约 `5.5 MB/帧` 的逐帧调试件。这个数字只代表额外的 gate 层级 sidecar，**不是完整动态帧可解码码流**。

改动后重新从同一首帧快照跑完 F2–30，V7b / 本工作树 S²GS 对照为：测试 PSNR `33.714 / 33.812 dB`（`−0.098 dB`），原 S²GS `size()` 口径的估算动态帧存储 `0.03415 / 0.03102 MB/帧`（`+10.10%`），测试视角 FPS `276.41 / 240.58`（`+14.9%`），训练帧时间 `8.67 / 9.17 s`（`−5.5%`）。成功的输出目录分别是 `output/paired_compactfix30_20260925_v7b_retry` 和 `output/paired_compactfix30_20260925_baseline_retry`。首个 30 帧配对与本次复验的 PSNR 差距很大；两次之间源码有变动、也没有记录逐次源码哈希，因此不能仅凭日志归因为随机波动或方法改进，更不能挑更漂亮的一次宣称画质优势。本次存储略高于暂定的 `+10%` 容忍线。

**架构决策保持不变，但尚未验收。**先冻结代码做同快照的 120 帧配对，查看早/中/后段；若 PSNR 后段明显退化或估算存储继续扩大，再从分组与 residual 的证据修正方法。300 帧完整结果和官方 S²GS 对照才是最终判定。首帧共用快照使动态帧比较公平，但该快照首帧约 `33.11 dB`，历史官方 S²GS 首帧约 `35.15 dB`；二者的绝对差异未定位，不能声称已经复现官方首帧成绩。

## 设计审计：120 帧后优先核对的两个偏差

1. **四层是上限，不是当前实际用到四层。**当前细化只检查该步目标层已有的终止区域；如果根区域在第 100 step 没有分出不同一级子格，就不会在第 200/300 step 尝试更细的格子。此前 29 个动态帧中，一级细分累计接受 2,635 次、二级 2 次、三级 0 次。若后段效果不佳，应让未分开的混合区域可继续向更细尺度试探，同时对跳过的层级计算编码代价，而非机械地强开四层。
2. **Gate 的跨帧优化器状态还没有完全对齐。**S²GS 每帧重置 root Gate 的 logits，但保留 Adam 动量与 step；V7b 每帧新建 Gate，Adam 历史归零。拆分当帧的子 Gate 已继承父 Gate 参数和状态，但跨帧仍不同。它可能影响 OFF/UPDATE、画质和大小，方向未知。120 帧这版仍照既定代码跑完以观察趋势；后续若要把收益严格归因于空间分组，需要单独控制这一差异。

另外，当前 split 的 `predicted_saved_bits` 是准入估算，不等于真实关闭的点数：新子 Gate 首先继承父 Gate，后续是否变成 OFF 要看训练结果。判断存储应以最终 active offset、`size()` 及 sidecar 实测为准。

## V7c 单变量短跑（2026-09-25）

V7c 在 V7b 上只增加 `--adaptive_gate_sqres_floor 0.1`：未配置独立属性 Gate 的 `f_dc/sc/rot/op` 使用 `max(上一帧 offset Gate, 0.1)` 作为 `sq_res` 输入系数；首帧、树划分、offset Gate、训练步数和 compact sidecar 格式均不变。参数默认 0，故原 V7b 行为可复现；S²GS 对照路径不受此参数影响。17 项针对性单测和 F2–3 烟测通过。

同一 F1 快照的 F2–50 短跑 `output/v7c_floor01_50_20260925`，与前述 S²GS 120 帧运行取共同 49 帧比较：V7c PSNR `34.247 / 33.912 dB`（`+0.335`），估算存储 `0.0374 / 0.0348 MB/帧`（约 `+7.5%`），测试视角 FPS `280.82 / 247.73`（约 `+13.4%`），帧时间 `8.77 / 9.21 s`（约 `−4.8%`）。在 F31–50，V7c / S²GS PSNR `34.675 / 34.967 dB`（`−0.292`），但比同区间 V7b 高 `0.448 dB`；该段存储估算甚至略低于对照、FPS 更高。**这是短段的积极信号，不是长期胜出**；继续冻结源码做 F2–120，再决定是否跑满 300。

V7c 的完整 F2–120 运行在 `output/v7c_floor01_20260925`（目录名略去 `_120_`，实际 `max_frames=120`）。119 帧 JSON 相对同区间 S²GS：PSNR `34.315 / 34.419 dB`（`−0.104`），估算存储 `0.0348 / 0.0323 MB/帧`（约 `+7.7%`），FPS `253.29 / 250.64`（约 `+1.1%`），帧时间 `9.26 / 9.15 s`（约 `+1.2%`）。F31–120 的 PSNR `−0.407 dB`、FPS `−3.2%`；拆开后 F31–80 的 PSNR `−0.723 dB`，而 F81–120 画质几乎持平（`34.653 / 34.665 dB`），但 FPS 仅 `225.49 / 249.79`。119 个紧凑 sidecar 共 `2,274,612 B`，144 次连续性检查均通过。它比 V7b 整体稳定，但**没有形成足够明确的完整区间指标提升，不推进 300 帧**。

F50 与 F120 两次 V7c 从同一快照、相同源码出发，配置除 `max_frames`/输出目录外相同；共同 F2–50 的输入图像、相机顺序、每帧 step 和全局 RNG 恢复路径按代码应一致。然而实测 F31–50 的 PSNR 两次相差约 `0.655 dB`，主要从 F38 起分叉。现有证据不能证明是 `max_frames` 导致，也不能把它确认为纯随机波动。此后不再用单次 50 帧短跑宣称长期效果；必要时用**同一 `max_frames` 重复**量化变异。

V7d 的下一条因果更窄的候选是：保留 S²GS 对其他 `sq_res` 属性的上一帧 Gate 抑制，只对“上一帧 OFF 且本帧已有 gradient/image 动态线索”的点给一个 0.1 的非零输入下限。旧 UPDATE 点不变，无 cue 的旧 OFF 仍严格 OFF；这样允许新动态重新激活，却不放开约六万个点的属性残差。此候选应与 V7c 全点 floor 互斥，先跑完整 120 帧再判，仍不提前恢复共享运动或增加树层数。

## V7d 的表示约束与实验判据

V7d 的本帧动态线索来自训练图像，不能假定解码端也拥有它。因此，若训练时用它把旧 OFF 点的 `f_dc/sc/rot/op` residual 输入重新打开，本帧 sidecar 必须保存**实际重开的逐点集合**，而不是只保存树的 OFF/UPDATE/SPLIT 和 Gate。该集合按进入本帧时的 Gaussian 顺序编码，解码时与上一帧 Gate 共同恢复属性 decoder 的输入系数；其码量只计一次，不能一面漏算，也不能把整个 sidecar 再叠加到已计 Gate/拓扑的 `size()` 上。紧凑 Gate 本身是 0.1 档的有损表示，所以现阶段的校验是对该表示的重建校验，不能据此声称已有 bit-exact 的完整 GS 视频码流。

先冻结源码与配置，从同一 F1 快照各跑一次 S²GS、V7d 的 F2–120。按共同帧索引比较完整 119 帧，并单列 F2–30、F31–80、F81–120；报告测试 PSNR、同口径估算存储、测试视角 FPS、训练时间，以及重开点数、sidecar 字节与解码校验。放行 300 帧的筛选线仍是：完整区间至少一项达到 PSNR `+0.2 dB`、估算存储 `−10%`、FPS `+5%` 或训练时间 `−5%`；其余保持在 PSNR `−0.2 dB`、存储/训练时间 `+10%`、FPS `−10%` 内，且后段不能明显塌陷。这是筛选标准，不是显著性保证。若结果只是边缘通过，应再做一组相同 `max_frames=120` 的独立配对；此前 F50/F120 的共同前缀未稳定复现，不能据一次边缘结果直接宣称胜出。若明显失败，就停止该候选，不浪费一次 300 帧训练。
