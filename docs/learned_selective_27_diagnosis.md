## 2. 层级大部分没有用起来

- 每帧都有 1920 个候选节点，但最终平均只有 4.89 个有效 SPLIT。
- 27 帧共 1140 个终止 SHARED 区域，其中 953 个在最粗层，占 83.6%；最细层只有 28 个。
- 第 15 帧没有任何有效 SPLIT。
- 平均 29.7% 的已有 GS 属于 SHARED；这个比例表示允许共享运动，不代表它们都是实际动态前景。
- 全部候选节点都有渲染器的几何支持，本轮没有走“完全无观测”的默认分支。

最可疑的是细层训练机会不足：硬采样时，父区域没有选 SPLIT，子区域运动就得不到这次图像损失的梯度。细层候选因此可能在没拟合好前就输给粗层。当前日志没有记录每个节点实际得到多少次运动更新，不能把这个推断当成已完成消融的结论。

还有两个实现特点需要处理：

1. 联合阶段一直使用等幅 Gumbel 噪声。降低温度只改变连续近似，不能让前向随机选择自动停止。第 27 帧最粗层最大动作概率平均只有 0.568。
2. 每帧重新建树、重新初始化选择分数和运动，上一帧的划分没有直接继承；已提交的几何误差会带入下一帧。

第 350 步软混合相对确定选择的 PSNR 优势平均只有 0.023 dB。因此，最后一次转成确定选择本身，不能解释全部画质差距。

## 3. 加步数和新增 GS 带来了多少收益

同帧测试 PSNR 的平均变化：

| 阶段 | 平均提升 |
| --- | ---: |
| 100 → 350，联合选择 250 步 | +0.066 dB |
| 350 → 400，固定划分精修 50 步 | +0.016 dB |
| 400 → 450，新增 GS 50 步 | +0.023 dB |

新增 GS 在 27 帧中有 25 帧改善 PSNR，最终平均每帧新增约 357 个。现有证据不支持把新增阶段作为主要退化来源。

但下一帧的合并裁剪仍会删除旧 GS，其中包含前一帧 KEEP 的 GS：累计记录 6839 次这样的删除操作。KEEP 目前只保证运动阶段保留原值，不能保证后续拓扑处理也保留。删除次数并不直接证明它导致了画质下降，需要独立对照。

## 4. 慢和占盘大，有明确的实现原因

每帧平均：训练 27.35 秒，评估 2.91 秒，绘图 14.62 秒，保存 3.53 秒，整帧 48.96 秒。分项计时口径见原 JSON，不能简单认为它们必然精确相加。

当前每帧四个评估点都画区域图和 GS 图，仅绘图约占总时间 30%。运动计算也仍遍历所有深度和全部 GS，即使已经固定划分，未采用的候选仍参与计算。

## 5. 建议下一步

1. 先用同一个首帧、少量相同后续帧做“固定细层 SHARED、关闭选择和结构代价”的能力上限对照。若仍拟合不好，先处理运动表达；若明显改善，再处理门的训练。步数和其他条件保持可比。
2. 给细层连续的拟合机会，随后再学习压缩划分；记录各层有效更新次数。减少联合阶段末期持续随机切换方案。
3. 固定划分后只计算实际 owner 的一份运动；诊断图主要保留每帧最终结果，中间详细图只抽少量帧。
4. 降低完整 checkpoint / PLY / 调试状态的保存频率，再单独实现包含划分、运动、增删信息的紧凑输出。不能仅靠少保存文件来宣称方法实现了压缩。

这些建议尚未实施，也没有替用户启动下一轮实验。当前结果不足以区分所有质量原因，但已经能确认细层使用不足、计算没有随选择变稀疏、输出仍是完整训练产物。
