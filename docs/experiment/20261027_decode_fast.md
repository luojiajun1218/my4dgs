# CPU 稀疏解码加速：完整序列一致性核验

本次是已经完成的解码诊断与优化，不是新的训练实验。目标是在保持码流、量化和解码状态不变的前提下，降低 Python 解码开销。

## 核心改动

- `pipeline/model/sparse_integer_codec.py`：批量读取 canonical uint32 varint 与 zigzag 数值，批量恢复原始逐行字节布局；保留截断、非规范整数、越界、非法标志和 trailer 检查。
- `pipeline/model/rigid_tree_codec.py`：用 NumPy 批量结果替代逐行创建小 Torch tensor；空间运动格式跳过实际不参与计算的 `region_pivots`。
- `tests/test_sparse_bulk.py`：新增整数边界、非法包、混合平移/旋转稀疏数据、删除索引边界及空间运动分支测试。

编码端的量化网格、布局选择和输出协议没有改动。解码仍恢复原来的字节，再执行原有运动与属性更新。

## 分析与限制

改善来自减少 Python 符号循环、小 tensor 分配及无用的聚合计算。它是实现效率改进，不是新的压缩算法，也不降低包大小或提高 PSNR。

优化后的约 153 ms/帧仍远达不到含解码的 200 FPS。计时不含 GPU 上传和渲染，因此不能作为完整播放速度。已解码场景的渲染 FPS 必须单列；后续若需要实时逐包播放，还需要面向播放的批量/GPU 解码与状态更新实现。
