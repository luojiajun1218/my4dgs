# Coffee：选点不额外按透明度加权，30 个动态帧

沿用 `coffee_early_joint_rmse_1pct_31frames_20261108.yaml`：共享 SH1 首帧、每步一个随机训练相机、101–104 四视角探测、最多 1% 点、提前联合修复、50% RMSE、运动相对残差权重 0.8 和固定 storage loss 0.008。只取消选点得分上额外乘以透明度平方根；真实渲染和图像梯度仍包含透明度。`FullUpdateConfig.probe_opacity_weight` 新增开关，默认为 true 保持旧行为。配置 `config/coffee_early_joint_rmse_noopacity_31frames_20261108.yaml`。

动机是确认透明度是否被选点分数重复强调：原方案保存的第 1、10、29、30 帧 step200，1600 个已选点中约 4%–6% 的透明度低于 0.1，而总体点约 19%；这些是 step200 时的透明度，不是选点时的直接因果证据。第 1 帧两方案各选 1600 点，1120 点重合、不加权方案有 480 个新点；step200 选中点透明度低于 0.1 的数量为 92 / 337。不能把低透明度点直接等同于玻璃、有效点或误选。

首帧共享，各自真实训练并递推动态帧 1–30；cam00 已用于开发选型，不是独立测试。动态 KB 为 1000 字节且包含 manifest，首帧另计。

关闭加权相对原方案平均 −0.00661 dB，11/30 帧上升，最差帧 −0.0658 dB，动态包增加 0.457 KB/帧。两组训练的 30 帧相机序列一致，但状态各自递推且使用单个随机种子，微小差异不足以确认普遍趋势；当前数据不支持取消加权。

每帧均选择 1600/160000 点，训练前向与解码图像最大差均为 0；独立顺序解码至第 30 帧并逐帧核验摘要，末状态 SHA256 `5b1ea61e24bd10b9499ada13fcefae8e5406a40f426b029d850e6909654f2649`。平均训练 18.85 秒/动态帧；未测已解码渲染和完整播放 FPS。相关 34 项 CPU 测试通过。
