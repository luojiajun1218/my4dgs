# STE gate：storage 权重 0.002 的完整 300 帧实验

已完成共享首帧加 299 个动态帧训练，并从首帧参考与增量码流独立解码、渲染全部 300 帧。全序列平均 **33.0724 dB**，完整动态更新平均 **127.338 KB/帧**，纯渲染 **199.494 FPS**。当前配方未达到画质和存储目标，渲染速度也略低于 200 FPS。

## 目的与代码范围

前一轮 [STE 短测](20261017_learnable_gate_ste_first6.md) 已确认 gate 能变化，但五个动态帧不能说明长序列的效果。本次按作者要求，先用 storage 权重 0.002 完成 300 帧；配对的第二组仅将该权重改为 0.003，以比较完整序列的画质和更新量。

本次没有继续修改算法代码。使用上一轮的 `joint_motion_v2`、`hard_value_soft_path_v1`：二值 gate 前向、软路径目标反向；区域更新后补偿 GS 残差，保留完整运动更新。新增两份实验 YAML，以及仅放在 output 中的顺序运行、状态监控和结果汇总脚本。两次从同一个固定源码目录执行，C++/CUDA 源码也包含在内。

## 固定设置

- Flame Steak，300 帧，1600×1199，测试视角 cam00，随机种子 0；训练视角顺序按帧固定。
- 共享已训练的原生首帧，214996 个 GS 按 opacity 0.0075 保留 206237 个；首帧不重新训练。数据通过原有软链接访问。
- 树深度 4，`robust_median` 初始化，远点关联最近非空叶区域；首个动态帧细分 gate 全关，后续继承上一帧 gate 和运动。
- 每个动态帧 70 步联合优化、30 步固定 gate，运动每步 2 个视角；随后普通新增 GS 优化 100 步，每步 1 个视角。
- storage 权重 **0.002**；相对运动权重 1.0，量化步长等保持正式配置。
- RTX 3090 Ti，350 W；两组顺序运行，不同时占用 GPU。

配置：[rate002 YAML](../../config/fs_ste_depth4_rate002_full300_20261017.yaml)。基础 Git 提交为 `2090febdf246076acdae01a471049213cdeaef67`，工作区已有修改，因此实际代码以 [源码哈希清单](../../output/fs_ste_rate_sweep_full300_20261017/source/source_manifest.json) 为准，共 493 个源码/配置文件。

## 分析与核验

1. 短测画质不能代表全序列。前 30 个动态帧为 34.2577 dB，最后 29 帧降至 31.8033 dB；对应更新量从 105.353 KB 增至 152.197 KB。后段同时出现画质下降与更高的数据量，单靠短帧结果无法判断压缩效果。
2. Gate 确实会调整。活动区域范围为 8–438，末帧 197 个，不能把这次结果归结为 gate 全程保持初值。但区域数变化本身不证明运动划分已足够好。
3. 新增阶段平均只提高约 **0.0255 dB**，中位数约 **0.0189 dB**；GS 数从 206237 增至 278476，增加 72239 个。新增对后段细节和后续帧的作用还需区分，但当前这 100 步的即时 PSNR 收益较小，值得后续优先检查。
4. 运动包占完整动态更新约 **96.1%**。因此存储超标主要来自运动编码，新增属性和几百字节的 manifest 不是主要来源。同条件 0.003 已完成：全序列 PSNR 提高 0.2178 dB，完整更新减少 6.00%；详见 [两组完整对比](20261017_ste_storage002_vs003_full300.md)。
5. 300/300 帧从码流成功解码并核验状态哈希；299 个动态帧的 PSNR、SSIM、L1 与训练保存值最大差异均为 **0**；渲染属性缓存开启/关闭的像素最大差异为 **0**。独立核验没有训练更新，cam00 阶段诊断不参与训练或模型选择。
6. 全程完成，无中途换配方、绕过解码校验或从短测前缀拼接。上述退化原因仍需进一步定位，当前结果不能单独证明是量化、运动拟合或新增阶段中的哪一项造成。
