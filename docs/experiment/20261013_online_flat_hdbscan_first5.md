# 在线平面共享运动：HDBSCAN 前 5 帧

## 想法与运行范围

让密度聚类从完整 GS 运动历史中找平面区域，noise 保持独立运动，不预设区域数量。历史只包括当前及最多 5 个过去转移，frame1 即开始每帧重聚类，不利用未来帧。新旧划分拟合同一当前目标，再经过相同量化误差检查和完整、可解码、实际压缩 motion 包比较；仅更省字节才接纳，没有建树。

代码共同使用 `online_motion_clustering.py`、`online_flat_motion.py`、`online_motion_diagnostics.py`；本次只将方法配置切换为 HDBSCAN，没有根据实验结果修改算法。最小区域 8 点、min_samples=8；HDBSCAN 对每个有效观测模式的全部运动点聚类，此路径不使用 Kmeans/GMM 的 8192 点抽样预算。

- 配置：`config/fs_online_flat_hdbscan_first5_20261013.yaml`
- 完成目录：`output/fs_online_flat_hdbscan_first5_20261013/20261013T183116_80f067`
- 命令：`conda activate ReConGS` 后 `python main.py --config=config/fs_online_flat_hdbscan_first5_20261013.yaml`
- exit=0，进程 wall 148.92 s；5 帧配置，其中共享 frame0 不重新训练，动态帧 1–4 各 100 motion + 100 birth 步。
- resolution=-1，随机种子 0；共享 reference 为 16,656,569 B，初始 206,237 个 GS，首帧只计一次。

## 完成结果

只对动态帧 1–4 求平均，不包含共享 frame0，也不是完整 300 帧结果。motion 包含 codec 帧头、归属、区域及出生位姿；birth 另存出生属性，payload=motion+birth，manifest 单列，训练产物不计传输量。文件实际大小已与 summary 校验。

| 帧 | test PSNR dB | motion B | birth B | payload B | manifest B | 帧训练 s |
|---|---:|---:|---:|---:|---:|---:|
| 1 | 34.39570 | 142875 | 2995 | 145870 | 436 | 35.27 |
| 2 | 34.29820 | 71531 | 4566 | 76097 | 436 | 33.28 |
| 3 | 34.31250 | 55627 | 4550 | 60177 | 436 | 35.58 |
| 4 | 34.19194 | 48759 | 4250 | 53009 | 436 | 39.29 |
| 平均 | **34.29959** | **79698** | **4090.25** | **83788.25** | **436** | **35.85** |

平均 **83.79 kB payload/帧**，加 manifest 为 **84.22 kB/帧**（kB=1000 B），未达到约 50 kB/帧目标；PSNR 超过 34.2 dB 的结论仅适用于前 4 个动态转移。训练日志没有 FPS，35.85 s/帧是训练时间，不能作为渲染速度。

## 残差与原因

以下是实际区域 0 中有观测存活 GS 的组合残差：平移为场景世界坐标，旋转为最短角度 rad。

| 帧 | 平移 mean / p50 / p90 / max | 旋转 mean / p50 / p90 / max rad |
|---|---|---|
| 1 | 0.001213 / 0 / 0.005661 / 0.016871 | 0.000369 / 0 / 0 / 0.015033 |
| 2 | 0.000549 / 0 / 0 / 0.016871 | 0.000151 / 0 / 0 / 0.015033 |
| 3 | 0.000418 / 0 / 0 / 0.015773 | 0.000117 / 0 / 0 / 0.015033 |
| 4 | 0.000363 / 0 / 0 / 0.015033 | 0.000093 / 0 / 0 / 0.015033 |

首帧候选确实把 raw 残差减少约 203.66 kB，但另引入 142.59 kB raw 归属、25.26 kB layout 和 16.71 kB 共享运动。其整个 raw 包从 411,068 B 降至 391,966 B，压缩后却从 138,119 B 增至 184,227 B：压缩结构改变使 raw 节省没有兑现。这说明完整压缩包门控必要，不能用残差或 raw 总量代替传输体积。随后残差节省迅速减少，归属/layout 成本仍大。

最小区域仅 8 点且运动已经量化，密度聚类可能把离散运动台阶切成许多小组，这是大量区域的一种可能原因；尚未做单独验证，不能当成确定结论。全部点聚类加上上千次共享变换重拟合，也使平均训练时间约为 Kmeans 的 2.13 倍。优先应筛选当前量化收益足以支付归属/layout 成本的区域，并允许部分接纳，再判断 HDBSCAN 是否真正能改善共享运动。现在较高的早期 PSNR 仍来自独立 root 回退，不能评为最佳共享方法。

## 统一速度测量补充

训练全部结束后，独占 RTX 3090 Ti，1600×1199 cam00，开启冻结 GS 属性缓存。sequence 每帧 10 次预热、50 次 CUDA 同步计时，统计完整渲染+clamp，排除解码、上传和质量评估；缓存图像与不缓存完全一致，重放 PSNR 与保存值逐帧一致。

- 动态帧 1–4 纯渲染 **201.509 FPS**，最低单帧 200.702 FPS；含首帧 0–4 聚合 201.689 FPS。
- frame4 物化渲染，30 次 × 3 轮：200.682 FPS。
- 2 轮从共享参考依次读取、CPU 校验解码、上传并渲染动态帧 1–4：**4.261 FPS**。平均读取/解码 226.78 ms/帧，上传+渲染 7.93 ms，解码占计时约 96.62%；不含一次性 reference 加载、相机/GT 加载、manifest 预检查和质量评估，文件预读可能受 OS 缓存帮助。
- frame0 PSNR=34.011318 dB，含 frame0 的 5 帧平均为 **34.24193 dB**；仅动态帧平均仍是 34.29959 dB。

报告：`output/online_flat_first5_benchmarks_20261013/hdbscan_sequence.json`、`hdbscan_frame4_playback.json`，精确命令见 `benchmark_commands.json`，全部 exit=0。约 202 FPS 是短序列缓存物化渲染，不代表 codec 的端到端播放或全 300 帧速度。
