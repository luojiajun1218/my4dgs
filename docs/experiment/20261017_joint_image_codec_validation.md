# 区域/gate 图像联合优化与实际码率校准

两处机制修复已通过真实渲染、独立解码和 192 项回归：区域及 gate 收到图像梯度；运动码率目标使用实际编码流的统计和真实包长校准。**短验证的画质变化很小，完整更新量反而增加，尚不能声称 gate 的独立压缩优势已经解决。没有重跑完整 300 帧。**

## 核心改动

1. `spatial_gate.joint_image_gradients: true`：实际渲染使用硬划分，gate 用 soft-path STE 反传。区域平移/旋转与 GS 残差均接收图像梯度。
2. 去掉新模式下每步区域更新后的抵消式重编码，gate 切换也不再自动修改 GS 残差。硬划分变化与反传定义对应。
3. 前 70 步联合优化 gate、区域运动和 GS 残差；step70 更新后固定 gate。后 30 步区域运动与 GS 残差继续联合训练，仍每步两个视角。新增 GS 的 100 步保持原配方。
4. 未选中的候选区域通过当前完整运动的停止梯度目标拟合，辅助项只训练候选区域。目标、选择权重均停止梯度，GS 和 gate 不能通过改变目标或权重降低该辅助损失。gate 的主目标为图像误差和编码代价。
5. 新联合模式的 GS 码率按实际 GS 残差计费，去掉“每个替代区域均假定 GS 自动补偿”的旧反事实残差目标。当前 GS 残差对 gate 的瞬时码率不变，其后续压缩效果通过区域/GS 联合优化实现。
6. 保留图像梯度 GS Adam、连续 L1 近端收缩及周期性块选择。块选择也改用编码统计估价；新模式不调用旧 raw-block 目标的区域代表重估。

区域仍存完整帧增量，GS 存相对所选区域的残差；旋转仍只改变高斯方向。树深度 4、robust_median、远点最近区域、前帧热启动、α＜0.01 删除、量化步长均保持原设置。

代码入口：

- [spatial_gated_motion.py](../../pipeline/model/spatial_gated_motion.py)：图像梯度、联合更新、冻结语义、实际残差目标。
- [motion_rate.py](../../pipeline/model/motion_rate.py)：正式包长、字节上下文模型、校准及恢复。
- [rigid_residual_tree.py](../../pipeline/model/rigid_residual_tree.py)、[spatial_gate.py](../../pipeline/model/spatial_gate.py)：配置、旧实验兼容、块保留代价。
- [rigid_tree_codec.py](../../pipeline/model/rigid_tree_codec.py)、[sparse_integer_codec.py](../../pipeline/model/sparse_integer_codec.py)：批量编码，保持原始字节格式。
- [联合优化与码率回归](../../tests/test_joint_image_rate.py)：图像梯度、更新不抵消、冻结后继续训练、真实包长、删除后前缀、校准及恢复。

旧配置默认保留原优化行为。此前 codec 检查点缺失校准参数时，按当时的实际策略补全：逐步实测版本为 interval=1，缺失 initial_steps 的版本为 0。新旧实验不静默混用训练策略。

## 码率如何对齐

编码器仍自动选择原始、zlib、XZ 以及 planar/zigzag-varint 布局。新代理考虑真实间隔编号、T/R 标志、各轴变长符号，并分别统计区域与 GS 的前一字节上下文，替代固定“每个运动块 6 字节＋绝对编号”的价格。

实际压缩器不可导，反向依然是估计梯度。最终配置为：

```yaml
rate_model: codec
codec_rate_initial_steps: 20
codec_rate_interval: 20
spatial_gate:
  joint_image_gradients: true
```

每帧前 20 步逐步实测，之后在每 20 步及 step70/100 校准，其余步预测当前硬码流字节；诊断调用强制实测。字节模型及其训练统计不需要传输，正式码流格式和解码器保持兼容。

这里校准的是**当前旧点运动包，含当前 gate/映射/元数据，不含未来新生 pose、opacity 或新增属性**。完整更新仍按实际 motion、opacity、新生属性和 manifest 文件合计。opacity 的训练码率代理本次没有更换。

启动验证从同一个共享首帧训练第 1 帧，λ=0.002；后段从同一个旧第 269 帧检查点训练第 270 帧，λ=0.003。比较对象是此前近端稀疏方案，双方使用同一正式无损编码器。以下每行是单帧，不能解释为 300 帧均值或独立消融。

| PSNR / dB | 34.3781 → 34.3874 | 32.3242 → 32.3780 |
| SSIM | 0.974642 → 0.974627 | 0.967071 → 0.967143 |
| LPIPS | 0.111750 → 0.111748 | 0.123488 → 0.123242 |

KB=1000 B，完整更新含 manifest，排除一次性共享参考。新配置 λ 数值相同，但从 raw-block 改为真实压缩字节口径后，**有效稀疏代价已经改变**，不能把新增残差全部解释成 gate 故障。原始逐步编码原型耗时约 90–126 s/帧；批量编码及窗口校准降低了这部分开销，但本轮仍比旧方案慢。耗时包含梯度诊断、检查点及验证，仅是本次运行观察。

两个最终帧独立回放的纯渲染 FPS 为 202.88 / 197.17。每帧预热 10 次、计时 50 次，不含文件解码、上传与核验；后段该帧未达到 200 FPS，不作为整体达标证据。

另外完成逐步实测版本的 1–3、270–272，以及 initial_steps=0 的窗口版本 1–2、270–271，共 10 个有重叠的动态帧验证。各版本均独立解码通过，结果保存在对应 JSON，不能与最终两个帧合并计算序列均值。

| 检查 | 帧 1 | 帧 270 |
|---|---:|---:|
| step69 gate 梯度绝对值之和 | 2.26e-5 | 1.30e-5 |
| step71 gate 梯度 | None | None |
| step71 区域平移梯度绝对值之和 | 0.5587 | 0.4287 |
| step71 改变的区域平移分量 | 423 | 276 |
| step71 改变的 GS 平移分量 | 82,626 | 99,792 |

step71、99 的 gate 参数均保持不变，区域和 GS 继续更新。step70 是最后一次 gate 更新，然后进入冻结状态。

最终版本在 step5 的实测包长与 loss 字节值完全一致。未触发实测的 step69/71/99 使用独立副本比较，不改变训练校准节奏：帧 1 的误差为 +3.91% / −0.02% / +5.93%，帧 270 为 +3.18% / +0.13% / +5.76%。这证明差距缩小，但不是每一步的精确压缩梯度。

## 下一步依据

固定完整整数运动，只改变编码划分并按旧代表搜索给出诊断候选：

| 编码诊断 | 帧 1 旧点运动包 / KB | 帧 270 旧点运动包 / KB |
|---|---:|---:|
| learned gate | 81.470 | 72.822 |
| 全细分并重估代表 | 82.214 | 73.478 |
| 仅八个大区域并重估代表 | 169.994 | 279.832 |

learned 相对全细分只省约 0.9%。这仍不能支撑“learnable gate 已产生显著独立压缩收益”。它是固定整数运动的编码诊断，部分重分组浮点位置差不超过 3.82e-6，不是严格训练消融。

剩余异常主要是平移：最终 step100 的非零平移块为 39,326 / 34,010，旋转块只有 254 / 290。单轴 ±1 平移块中，连续值位于 0.50–0.51 bin 的仅 4 / 8 个，没有重现此前大量旋转卡在半 bin 的现象。

即使细分到全部叶子，平移的非众数点仍为 39,299 / 33,987，与当前残差规模基本相同。每叶子的第二常见平移模式合计只覆盖其中约 12% / 16%。简单最小二乘位置旋转/仿射容量探针也未明显减少非零数；该探针不是穷尽最优模型，未计额外参数和分配成本，不能据此排除所有运动分组方法。

因此下一步优先做**剩余平移残差的真实图像贡献诊断，并按新字节口径标定稀疏强度**：确定多出来的独立更新究竟带来多少必要的图像收益，再决定如何让共享区域吸收可共享部分。仅继续改 STE、增加树层或直接扩大归零阈值，目前缺少依据。共享结构/gate 的第一贡献仍需实际率失真优势证明。

## 核验与证据

- 192 项回归通过，覆盖硬值/软梯度、冻结、编码边界、校准和恢复。
- 最终两帧与此前 10 个短帧都独立解码；初始参考匹配来源，最终 raw 逐张量匹配检查点，保存指标差和缓存像素差均为 0。
- 矢量化前后的包字节与字节模型统计一致；独立编码微基准只衡量 CPU 码率测量，不代表端到端训练提速。
- 执行源码与 `source_snapshot_v5/source_manifest.json` 核对；输入历史检查点只读，数据未复制。两份当前入口使用新的 `fs_joint_image_codec_rate00x_full300_20261017` 实验名。
- 验证脚本曾修正快照 CUDA 扩展路径、以及先恢复原 trainer 配置再改变保存帧的顺序，失败日志保留；不涉及修改历史结果。

产物根目录：`output/fs_joint_image_codec_validation_20261017/`。最终入口为 `calibrated_status.json`、`calibrated_comparison.json`、`calibrated_verification.json`；`calibrated_frontier.json`、`motion_structure.json`、`motion_capacity.json` 保存诊断，`source_snapshot_v5/` 保存最终源码。此前版本分别在 `training_status.json`、`calibrated_status_v4.json` 及对应版本快照中记录。
