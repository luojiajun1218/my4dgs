# ReCon-GS 分层压缩项目路线 — 2026-10-03

## 当前证据

- ReCon-GS 的 299 帧原生流已成为可重放的参考。共享训练后 frame-0 base 只计一次；训练质量为 33.94978 dB PSNR、0.968486 SSIM，200 步同步训练均值 9.44936 s/动态帧。
- Exact-index-delta 是已经接入在线保存、可顺序解码的无损工程格式。相对同 ZIP 压缩器的完整索引流，它节省约 35.25% 实际总文件字节；REF 状态的全 299 帧播放画质和末态逐元素一致，端到端回放与 FPS 持平或略快。一次完整在线 299 帧训练也完成：cam00 平均 PSNR 33.90519 dB（REF 33.94978，差 −0.04459 dB；原配置没有显式 seed），同步训练时间 −0.12%，但含验证与 I/O 的帧循环 +3.51%。它没有改训练拓扑或 loss，不能算作自适应分层或 storage loss 的论文结果。详见[在线写盘与验收](20261003_recongs_exact_index_delta_online.md)。
- 拓扑继承少存 36.17%，但 held-out cam00 PSNR 低 0.01560 dB，训练时间多约 0.325%；不作为当前方案。详见[299 帧拓扑继承验证](20261003_recongs_topology_reuse_full299.md)。
- GradHet 的共享 child-index 表 v3 在同方法内少 6.84%，仍比 ReCon-GS 同格式大 16.41%，且纯 CPU 解码多约 3.58 ms/帧。它解决的是结构重复，不是当前四项目标。
- 已有 warm50 试验比 hard-path control 低约 0.8175 dB，参数存储估算约扩大 14.7 倍；不重复该 warm50 路径。此前十帧结果是估算字节，不能替代实际文件口径。

## 尚未证明的目标

项目的研究主张仍是“让需要变化的层变化，并把存储代价纳入训练”。后续需要验证学习到的结构能否减少实际码流字节，同时保持重建质量和端到端播放速度。参数估算不等于实际落盘大小。

## 建议的下一步

1. 把学习到的结构按实际文件边界核算：base/index、层级行映射、motion、birth、deletion、transition、manifest 都要计入，并测真实顺序解码与端到端播放/FPS。exact-index-delta 是此阶段的序列化基线，不作为学习算法收益。
2. 再研究 attribute-specific gate；颜色/位置等属性门仍是后续问题。

目前应把 exact-index-delta 标记为“验证通过的工程基座”，把拓扑继承和 warm50 标记为“有明确负面边界的候选”。这还不是完整论文贡献。
