# 稀疏运动 ID 改存相邻间隔

运动码流原来给每个活跃区域和 GS 保存绝对 row ID。8192 区域实验的首个动态帧有 5,969 个活跃区域，大量绝对 ID 要占两字节。此次只把两个稀疏段各自的 row ID 改成相对前一活跃 row 的正间隔，首项按前一 row 为 -1 计算。运动符号、树编辑、量化步长、出生来源与姿态不变。新写入使用 RSD1/RSD2 原始格式，并在原始包、RSC1/RSC2（zlib）和 RSL1/RSL2（XZ）三者中选实际文件最小者；旧 RRT/RRC/RRL 格式仍可解码。

正在运行的完整 300 帧训练使用启动时冻结的旧源码，未被本次改动影响。新增的无损转码工具读取旧实验，把必要的 frame0 参考和出生包复制到独立目录，重写运动包，并更新 manifest 与 frame summary 的真实字节数。训练 checkpoint、数据和图像不复制；原训练指标与来源路径保留。工具默认要求配置中的全部连续帧齐全，只有显式指定 `--through` 才会生成标为 partial 的部分结果。

已对该训练完成的帧 1–10 做 CPU 部分验收。每个旧包先通过 SHA 校验；转码后旧、新解码状态摘要和完整 GS 属性摘要都与原 manifest 一致。正式 replay 至帧 10 通过，benchmark 的配置与存储元数据预检 10/10 通过。数字为真实写出的文件大小：

| 口径 | 原格式 | 正间隔格式 | 减少 |
|---|---:|---:|---:|
| 帧 1–10 运动包 | 215,458 B | 188,326 B | 27,132 B |
| 帧 1–10 运动 + 出生包 | 230,802 B | 203,670 B | 27,132 B |
| 共享 frame0 参考，单列 | 17,121,493 B | 17,121,493 B | 0 B |
| 参考 + 帧 1–10 增量 | 17,352,295 B | 17,325,163 B | 27,132 B |

首个动态帧的运动 + 出生包为 54,356→46,992 B；其余九帧各省 1,736–2,464 B。前十帧都选 XZ，也都实现正收益。参考文件只存一次，未摊入每帧增量平均值。

代码中的 `rate_bytes_hard_uncompressed` 已按两个稀疏段的真实正间隔长度精确计算。smooth rate、proximal 和 GS 归属候选的局部估计仍采用绝对 ID 长度代理。换父候选的整体 raw 费用已随 hard 统计按间隔 ID 计算，但实际压缩包大小仍不是同一优化目标。正在运行的冻结训练继续使用旧源码与旧评分；本次实验未重新训练，不能把转码收益解释成画质或优化收益。

验证使用 `CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1`：数值检查 304/304、unittest 58 项（跳过 1 项）、压缩检查 13/13，`git diff --check` 通过。完整 299 个动态帧的无损转码、总存储和渲染质量仍待源训练完成后验证；前十帧结果不能代表 300 帧目标已达成。
