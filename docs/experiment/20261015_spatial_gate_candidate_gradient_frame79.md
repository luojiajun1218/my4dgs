# 第79帧候选梯度检查：局部指标略好，但行为测试暴露错误，撤回

生产基线为已核验worldroute版本。代码检查发现shared-field阶段使用`hard + soft - soft.detach()`路径权重，因此gate有soft导数，候选区域参数却乘硬路径；未选中候选同时被屏蔽梯度和Adam。候选是否有机会在gate比较之前学习，是一个应检查的核心规则。

候选使用相同frame79-step20状态重放21–100步。41–60保持单一硬frontier前向，但反向对gate和候选区域都使用soft字段导数，并放开所有有观测支持的候选参数。没有新增参数、渲染、优化步骤或损失。step41确认未选中候选平移梯度L1为0.071832895，说明梯度通路已改变。诊断session37017正常退出0。

单帧提升很小，未证明长期收益。之后将该候选作为实验修改接入并新增闭合候选学习、无观测候选冻结和checkpoint规则测试；完整116项检查中115项通过，原有`test_shared_field_gate_learns_image_resolution_without_individual_residuals`失败：目标MSE须低于1.6666678e-7，实际5.9999948e-6。没有放宽该测试或删掉旧行为要求来接受新方法。

失败案例的子区域初始化已接近其正确运动，但gate尚选父区域。把父区域当前渲染的图像梯度直接分配给未选子区域，会继续推着这些已接近正确的候选向错误方向走，最终造成过冲。给候选非零梯度不等于在候选自己假设下正确拟合图像。该soft导数方法不能仅凭单帧略好指标就采用。

已从训练前验证的source_snapshot精确恢复本次实验修改的两个文件：spatial_gated_motion.py与test_spatial_gated_motion.py；恢复后逐字节与原worldroute文件相同，没有恢复用户其他改动、历史删除或修改旧产物。当前仍是原113项检查已通过的基线源码，不宣称刚才116项通过。没有启动这项候选的短序列实验。

下一项局部检查改为在更粗/更细的合法frontier下分别真实渲染同一训练视角，使用各自图像误差，仅更新对应未选区域参数。当前实际frontier和gate的梯度保持原规则，点残差仍在shared阶段冻结，额外候选渲染不进入出生点梯度统计。这个方式增加训练渲染次数而不增加优化步数，不是零额外开销，尚未修改生产代码。

## 真实候选图像拟合检查：仍无明显收益，暂不采用

该检查已完成，session37825正常退出0。每个shared-field训练视角额外渲染下一层更细和上一层更粗的合法frontier，将各自图像误差只反传给对应未选区域参数；当前实际frontier和gate的梯度不变，点残差仍冻结。仅把当前cut、两种替代cut中有观测支持的参数交给优化器，未参与的区域动量仍冻结。额外候选渲染共160次，总优化步数不变，这不是同等计算量的比较。

最终全部20训练视角图像损失0.015238144，原规则0.015249028，改善约0.071%；图像+rate+relative目标0.015677660；测试PSNR33.613064，原规则33.613083，几乎相同。纯运动包26963 B vs原27651 B，小幅下降。当前结果不足以解决终帧约0.36 dB差距，因此不将该额外候选渲染方案接入正式序列，也不再围绕候选梯度做参数扫描。生产源码仍精确恢复为worldroute基线。
