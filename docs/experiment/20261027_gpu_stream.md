# 稀疏码流的增量 GPU 播放：完整300帧一致性核验

本次完成的是播放实现与独立解码/渲染诊断，不是新训练。性能等待独占 GPU 计时，本文不把共享GPU检查耗时当作播放FPS。

## 实现

原播放路径先在CPU上重建整帧GS，再整帧上传。本次保留原始 SPG5/6 量化码流，在GPU上直接执行存活映射、固定空间树路由、共享平移、逐点平移残差和新点位置重建。浮点乘/加明确分开舍入，nearest-leaf 使用与CPU相同的float64距离和相等时的叶序规则。

旧点不变化的尺度、旋转和SH保留在稳定ID属性库中；按码流更新透明度和新增点属性，随后按当前存活顺序提供完整标准渲染输入。ID从删除/出生顺序推导，不是新增传输信息。两个缓冲区服务逐帧渲染；最多提前解析两个稀疏包，不缓存未来帧的稠密GS或图像。

- `stream_packet.py`：独立于稠密几何的读包、解压、校验和、计数及符号解析。
- `gpu_stream.py`：持久属性库、原量化预测、CPU精确定义的透明度与新四元数、GPU增量更新和渲染视图。
- `extensions/stream_update/` 与 `stream_cuda.py`：前向CUDA更新、空间路由、源路径隔离的编译缓存。
- `benchmark_gpu_stream.py`：完整300帧核验与三轮299次更新的独占播放计时，分开运行。
- `sparse_integer_codec.py`：批量读取pose尾部varint，并复用已解析的透明度行/符号，仍恢复并校验原始字节。

加速实现明确针对当前方法的平移运动、SPG5/6新点offset、SH0/SH1。非零旧点旋转更新会明确拒绝，历史格式仍由原CPU解码器支持。训练方法、量化精度、实际包字节和候选数量没有因此改变。

## 校验口径

包的原始校验和与元数据每次播放都检查；帧间几何digest链接与CPU透明度predictor哈希也检查。完整状态/raw SHA和逐帧实际RGB对照在计时前的独立全序列核验执行。不能把排除了这项启动核验的播放速度说成每帧都包含完整状态下载/哈希的调试速度。

## 性能与限制

单线程稀疏解析全299包的诊断平均6.307ms/帧，尚未包含GPU更新、属性预测和渲染；不能据此声称200FPS。正式播放将两个CPU解析线程与GPU工作重叠，保留最多两个未来稀疏包。真实吞吐仍须由独占GPU下的墙钟计时证明。

属性库会保留已退休ID对应的内存，换取稳定索引与稀疏更新；它增加运行时内存，不增加传输字节。FPS不包括一次性参考包载入、JIT、相机/GT读入与完整预检；包含逐动态帧读包/解压/检查、预测、上传、GPU更新和一次真实完整渲染。
