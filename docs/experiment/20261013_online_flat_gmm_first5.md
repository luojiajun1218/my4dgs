# 在线平面共享运动：GMM 前 5 帧

## 想法、代码与完成范围

用 GMM 对当前及至多 5 个过去转移的完整 GS 运动分组，允许低概率成员留作独立运动；不按历史区域标签锁死归属，不使用未来帧。其余训练、量化和实际压缩 codec 门控与 Kmeans 实验一致：frame1 开始每帧重新提案，候选和旧划分拟合同一目标，通过误差限制且完整 motion 包更小时才采用。此次只做平面区域，没有建树。

核心实现为 `online_motion_clustering.py`、`online_flat_motion.py` 和 `online_motion_diagnostics.py`；本轮只把配置的 `online_clustering.method` 改为 `gmm`，没有针对结果调整算法。共同设置为 100 motion + 100 birth 步/帧、history_frames=5、resolution=-1、5 帧、种子 0、8192 点最大拟合预算、GMM 成分候选 1/2/4/8。

- 配置：`config/fs_online_flat_gmm_first5_20261013.yaml`
- 完成目录：`output/fs_online_flat_gmm_first5_20261013/20261013T182944_18954d`
- 命令：`conda activate ReConGS` 后 `python main.py --config=config/fs_online_flat_gmm_first5_20261013.yaml`
- 进程 exit=0，wall 72.20 s；动态帧 1–4 的 summary 和存储文件齐全。
- 共享 frame0 保留 206,237 个 GS，reference 为 16,656,569 B，只计一次；下面平均只含动态帧 1–4。

候选四帧均量化有效，全部因 `complete_packet_not_smaller` 拒绝。门控包在出生阶段前计算，不能代替最终 payload。raw 分项未压缩；决定使用整包压缩字节。GMM 第 1/2 帧虽减少少量残差，收益远小于归属成本；后两帧残差收益转负。

实际只有身份区域 0，全部 206,398 / 206,612 / 206,820 / 207,030 个 GS 归属该区域，各占所有 GS 的 100%；共享平移 xyz=`[0,0,0]`、范数 0，旋转 wxyz=`[1,0,0,0]`、角度 0°，实际归属变化 0%。因此本实验验证了 GMM 候选和门控能运行，但没有兑现区域共享收益。

## 残差与结果解释

区域 0 只统计有观测的存活点；平移单位为场景世界坐标，旋转为组合后的最短角度 rad。

| 帧 | 平移 mean / p50 / p90 / max | 旋转 mean / p50 / p90 / max rad |
|---|---|---|
| 1 | 0.001213 / 0 / 0.005661 / 0.016871 | 0.000369 / 0 / 0 / 0.015033 |
| 2 | 0.000549 / 0 / 0 / 0.016871 | 0.000151 / 0 / 0 / 0.015033 |
| 3 | 0.000419 / 0 / 0 / 0.015034 | 0.000118 / 0 / 0 / 0.015033 |
| 4 | 0.000363 / 0 / 0 / 0.015033 | 0.000094 / 0 / 0 / 0.015033 |

历史相似可以把过去曾移动、当前已零残差的点继续放入运动区域，拟合非零共享变换后需要新增抵消项；GMM 的概率过滤并没有消除这个问题。观测模式增多也分摊拟合预算，较小的新生模式仍可能产生区域，但成员的字节收益没有参与候选选择。

与 Kmeans 的平均 PSNR 差仅 -0.00911 dB、payload 差 -246.75 B/帧。四帧 raw-state SHA256 与 PSNR 均不完全相同，不能假称两个运行逐字节相同；但两者最终都退回独立 root，这些微小差异也不能证明 GMM 的共享运动效果更好。下一步应改善候选的当前量化收益和部分区域接纳机制，再评价真正被采用的区域。

## 统一速度测量补充

训练全部结束后，独占 RTX 3090 Ti，1600×1199 cam00，开启冻结 GS 属性缓存。sequence 每帧预热 10 次、50 次 CUDA 同步计时，缓存与不缓存图像一致，重放 PSNR 与保存结果逐帧一致。纯渲染只含完整 forward+clamp，不含解码/上传/质量评估。

- 动态帧 1–4 纯渲染 **201.476 FPS**，最低单帧 200.553 FPS；含共享 frame0 的 0–4 聚合 201.360 FPS。
- frame4 物化渲染，30 次 × 3 轮：200.684 FPS。
- 依次播放动态帧 1–4 共 2 轮，包含本地文件读取、CPU 校验解码、上传和渲染：**4.201 FPS**。平均读取/解码 229.99 ms/帧，上传+渲染 8.04 ms，解码占计时约 96.62%。排除一次性 reference、相机/GT 加载、manifest 预检查和质量评估，预读文件可能受 OS 缓存帮助。
- 共同 frame0 PSNR=34.011318 dB，含首帧的 0–4 平均为 **34.23286 dB**；动态平均仍为 34.28824 dB。

报告位于 `output/online_flat_first5_benchmarks_20261013/gmm_sequence.json`、`gmm_frame4_playback.json`；精确命令见 `benchmark_commands.json`，全部 exit=0。约 201 FPS 是短序列物化渲染结果，不能替代端到端播放或全 300 帧结果。
