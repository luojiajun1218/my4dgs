# Coffee：区域与逐点全属性、属性感知 gate，300 时间点

## 实验和恢复

共享首帧 frame 0 加动态帧 1–299；16 个训练相机，每步随机使用一个，cam00 用于评估且已用于此前开发选型，不是独立最终测试集。首帧保留 160,000 个 GS；候选层级 depth 5，每动态帧 200 步，无新增或删除点。前 100 步训练运动主干，第 101–200 步联合更新区域与逐点全属性；运动、透明度、尺度和 SH 变化均以量化残差编码。gate 在前 100 步接收运动的渲染梯度；151–180 步接收区域属性的渲染梯度，以及运动和属性的码率等代理梯度。本次 `gate_refine_image_ste=false`，因此后段运动位置和旋转的渲染梯度没有直接进入 gate；运动参数本身仍接收渲染梯度。属性码率采用固定代理。图像损失中 RMSE 混合比例 0.8，运动码率权重 0.008，逐点运动近端收缩权重 1.0，逐点尺度额外码率倍率 2，`point_dc_rate_scale=4` 实际作用于逐点尺度及 SH 和区域非透明度属性的码率代理，区域透明度 L1 权重 0.005。这里的逐点属性更新不设稀疏选点预算，非零行通过量化与正则化形成。

原运行 `output/experiments/coffee_fullattr_gate_alpha005_200step_300frames_20261109/20261109T131529_409a68` 在 frame 208 完成时的前向与解码图像一致性检查处退出。前向量化与编码取整使用不同设备，在半格点附近存在可复现的 CPU/CUDA 取整不一致隐患；后续让编码使用训练设备上的量化结果，并修复区域透明度相同的设备差异。原 frame 208 的现场未保存各属性差异，不能断言该隐患就是此次报错的唯一原因；一致性阈值没有放宽。

完整序列通过 checkpoint 安全接续：frame 0–199 沿用原结果，frame 200–207 从 frame 199 checkpoint 重新训练，frame 208–210 及其后用修正后代码训练。最终运行 `output/best/coffee_martini`，配置 `config/coffee_fullattr_gate_alpha005_resume210_300frames_20261109.yaml`。因此这是带恢复的单条递推序列，而非原始运行不间断完成。旧输出未修改；每次恢复都核验前缀码流、数据身份和 checkpoint。

## 码流与机制观察

本次动态码流平均：运动 27.838 KB（57.5%），逐点透明度 4.854 KB，逐点尺度/SH 13.736 KB（28.4%），区域属性 0.234 KB，manifest 1.729 KB。对照收缩 1.0 的稀疏方案，运动和逐点属性分别多约 2.055、4.806 KB/帧，是增加的主要来源。运动包仍是最大的压缩空间，不能只盯区域属性包。

逐点每帧非零尺度、DC 和高阶 SH 平均分别约 2491、1841 和 14 行；这三个数各自统计，可能存在重叠。高阶 SH 活跃很少，其学习率、量化步长和近端收缩都可能影响结果，现有数据不足以判断单个主因或断定需要更强更新。区域透明度平均每帧约 0.78 个活跃区域，117/299 帧非零；不能仅凭区域分支稀疏就说透明度无用，因为逐点透明度也参与训练和编码。

平均活跃区域 134.3 个，范围 29–752；平均约 14,644 个点带非零逐点运动残差。151–180 步记录中，36/299 帧出现区域归属变化，累计 56 次变化事件，同一点可多次变化。说明后阶段存在实际硬切换，但这不是 gate 收益的因果证明；要验证自适应层级或属性梯度的独立贡献，需要控制其它训练设置和码率的对照。

可优先检查两处：运动残差为何仍占近六成存储，以及高阶 SH 的量化与学习率是否把有价值的更新过度压小。对前者先分析活跃点与空间分布，再做小规模固定参数调整；对后者先观察训练期梯度和量化前后幅度，再决定是否调整。已有日志不能保证这两处调整一定提升 PSNR。

## 进一步检查：梯度与 gate

根据每帧记录的 101、150、151、180、181、200 步、Adam 更新前的逐点尺度参数梯度范数，共 1,794 个样本。中位数在各个步骤约为 0.0023–0.0039，但其中 216 个样本超过 1，涉及 124 个帧；阈值 1 只是用来统计异常幅度，不是稳定性的理论边界。frame 50 的 step 151 尺度梯度范数达到 104,935.7，同一步逐点运动位置为 21,353.8；对应训练相机 cam01，最终 cam00 PSNR 29.8734 dB。44–52 帧出现多个大幅度梯度，不能仅凭这些日志断定它们造成了画质损失，也不能根据范数推断 Adam 实际更新同样放大。

同一尺度参数的采样梯度还表现出明显视角差异：cam04 的 103 个边界步骤样本中位数为 2.200，cam08 的 111 个样本中位数为 0.00146；两个样本集合来自不同帧和训练步骤，并非同一模型的严格视角对照。这个现象值得优先对固定训练状态做逐相机梯度和投影几何检查，分离少数 GS、可见性、协方差数值和实际渲染误差的影响，而不是直接删除相机或做梯度裁剪。注意现有 `stable_tail_covariance_backward` 只在 step 大于 `motion_steps` 时生效，当前 200 步路径结束于 step 200，直接在配置中打开该选项不会覆盖当前 101–200 步；其是否能解决梯度现象尚未验证。

gate 日志显示第 151 步平均有约 124 个可达 gate，其中约 7.8 个满足 `|logit|<1`；到 step 165 有 192/299 帧一个这样的可达 gate 都没有。这里的 1 只是人为设定的接近零边界的参考，不代表能否实际切换的判据。整个 151–180 阶段只有 36/299 帧记录到归属变化。第 151 步属性码率代理的梯度在可达节点上普遍非零，但总梯度有 168/299 帧在所有可达节点上都未指向零边界；这是某一步梯度方向的快照，Adam 动量和后续梯度仍可能使归属变化。上述数据提示全属性开始训练后 gate 可能较早固定，而非证明它没有收到渲染或码率梯度。

逐点高阶 SH 在每帧上述六个采样步骤都有非零梯度；在 step 151，其参数梯度范数中位数为 0.00107，但最终每帧平均只有约 14 行非零。该分支配置的学习率是 DC 的 1/20，量化步长为 0.001，并受统一的属性码率与 L1 收缩影响；这些现象不能单独识别是哪一项造成最终稀疏。应先比较量化前更新幅度与半步长，再决定是否调整该分支。整体只有 31/299 动态帧测试 PSNR 达到 30 dB，接近目标但尚未整体达到。

## 核验与速度

299 帧均记录 200 个训练步、训练前向和解码图像最大像素差为 0；其中 100 帧额外记录了逐属性状态检查。独立从首帧顺序解码至 frame 299，逐帧 manifest 摘要通过，最终 decoder SHA256 为 `e9cb1fb4402212269d4de66b7274b0425fd732a30f1aae32be42068ba058b48e`。

本次未测纯渲染 FPS 和包含读包、解码、更新与渲染的完整播放 FPS。现有 `scripts/benchmark_rigid_residual_tree.py` 的存储校验未计入 `regional_full_attributes` 包，直接对本次序列运行会与实际码流口径不符；应先补齐该计数并验证后再基准测试。以前其它方案的 FPS 不能直接作为本次结果。
