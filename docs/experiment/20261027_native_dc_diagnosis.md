# 新增点的原生合成DC初始化：已完成诊断与代码核验

本次完成的是冻结step70状态的诊断与实现验证，不是新训练完成报告。完整v25继续运行；新的300帧配置是`config/fs_v26_300.yaml`，尚未启动。

## 出发点

当前新点的几何和SH复制源GS，alpha约0.03..0.1；保守颜色修正最多约0.025 RGB。源点颜色不一定适合偏移后的子核，在多个子核和旧场景重叠时，颜色、遮挡和alpha还会共同改变图像。只把候选位置移向残差重心的冻结检查收益不稳定，保留在研究分支3e405a2，未采用。

本次不增加候选、不改删除阈值、不降低量化精度。先在已有1000个候选的实际量化几何/alpha下，用原来的两个训练提案相机求一个更合适的DC起点，再继续原有70/200/300训练轨迹。

## 方法与代码

固定几何和alpha后，native alpha合成对预计算颜色是线性的。使用完整旧场景与所有子核的真实颜色Jacobian，通过JᵀJ算子联合拟合公共RGB/DC修正，从而计入遮挡和子核之间的重叠。

- `adaptive_birth_dc.py`：16次固定预算的对角主化FISTA迭代；主化对角由H1得到，不另设颜色学习率。这里只拟合未clamp的native RGB平方误差，不等同于最终训练的clamp/RMSE/SSIM目标。
- 只有两个训练视角有实际响应、初始梯度同向且全方向SH1不为负的通道参与。修正约束在全向非负、且不增加超过max(1,继承HDR上界)的颜色范围内；不符合的通道保持原DC。该约束仅用于初始化，后续所有新点属性继续自由优化。
- 结果对齐原parent-predicted SH DC量化格点，步长仍为0.001，其他属性、格式、storage loss和统一population loss保持原配置。
- `adaptive_birth.py`：在挂接原共享Adam之前写入颜色、初始化快照与transaction；没有新增Adam步。统计中真实计入额外原生调用。
- `BirthConfig.native_dc_init`默认False，旧配置与checkpoint恢复逻辑保持原路径；新配置显式启用。

正常非空求解额外36次前向、36次反传，重复使用同两张训练图；没有20视角候选筛选、逐组验收或最终质量回滚。这是真实的初始化拟合开销，不能称为零额外计算。解码与播放不保留求解器状态。

## 核验与证据边界

完整CPU检查640项：628通过、12项GPU相关检查跳过，73.007秒。相关31项检查30通过、1项跳过。新增真实CUDA检查单独通过，验证普通native与稳定协方差训练后端都能改善颜色误差，求解结果在一个DC量化格点内一致。CPU检查还覆盖已知耦合box最优解、零响应不渲染、相反视角拒绝、HDR/SH范围、测试相机隔离、两视角控制器接入、共享Adam与checkpoint初态一致性。

这些证据支持把该机制作为下一轮完整训练候选，不支持PSNR或存储已经达标。更好的颜色起点也可能使更多新点存活、增加码率；只有完整300帧和实际码流能回答净收益。像素误差驱动增密已有明确先例，例如[Revising Densification in Gaussian Splatting](https://arxiv.org/html/2404.06109v1)，也不能由这项局部实现直接推断论文创新性。
