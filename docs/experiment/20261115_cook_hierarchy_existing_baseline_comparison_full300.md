# Cook Spinach：现有自适应 baseline 与固定深度消融（300 时间点）

按用户要求，以 SSD 上已有的自适应结果为主对照；三个固定深度组均从相同共享首帧独立训练。depth 4 的首次完整训练中断，本次使用从首帧独立重新开始的完整重试。29 个动态帧的短实验通过训练、相机和码流核验后才启动完整训练。

四组每动态帧 200 步，前 100 步共享平移，原代码冻结区域旋转；后 100 步训练区域运动、逐点运动和属性。baseline 还在 151–180 步训练 gate；固定深度组始终冻结 gate，且每帧按上一解码位置路由到固定深度，训练中保持归属。四组逐帧的 200 个训练相机顺序和非 gate 参数的关键步骤冻结状态均一致。

## 画质、区域数和存储的权衡

- 相对 depth2，baseline 的 PSNR 为 +0.3379 dB，动态存储为 -0.592 KB/帧，活动区域为 +134.3。运动包差 +0.239 KB/帧，逐点属性包差 -0.797 KB/帧。
- 相对 depth3，baseline 的 PSNR 为 +0.1411 dB，动态存储为 -1.876 KB/帧，活动区域为 -300.2。运动包差 -1.425 KB/帧，逐点属性包差 +0.068 KB/帧。
- 相对 depth4，baseline 的 PSNR 为 +0.1152 dB，动态存储为 -20.809 KB/帧，活动区域为 -3215.7。运动包差 -17.406 KB/帧，逐点属性包差 -0.397 KB/帧。

按文件字节拆分，depth 4 比 baseline 多 20.809 KB/帧，其中运动包多 17.406 KB/帧（约占差额 83.6%），区域属性包多 2.682 KB/帧（约占 12.9%）；该组活动区域约为 baseline 的 17.2 倍。这个对应关系表明本次额外开销主要记录在这些文件中，但不单独证明区域数量是唯一原因。depth 2 的逐点属性包比 baseline 大 0.797 KB/帧，而运动包更小；它的 PSNR 也更低，提示较粗的共享粒度在此序列上可能更难兼顾画质和压缩。各文件内容和训练状态共同变化，不能据此断言单一因果。

完整结果均核验实际包大小、每个动态帧选取一个训练视角的训练态/解码渲染一致性、从首帧顺序回放的状态摘要、200 步相机轨迹与关键步骤冻结状态。baseline 与固定组的配置除实验名和 checkpoint 保存帧外一致，首帧文件 SHA256 一致。baseline 训练时的 Git 版本早于本次工程重构，且未保存当时完整工作区源码快照，因此不能仅凭配置和抽查就证明其他实现逐行完全相同。

区域数、运动与属性码流的变化与共享粒度影响编码成本的假设有关，但画质和码率同时受到图像内容、量化、优化及递推状态影响；这些数值不能单独证明唯一原因。仅为一个场景和一个随机种子，不能推广为跨场景结论。
