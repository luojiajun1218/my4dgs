# 图像尺度版长前缀：因共享代表裁决冲突停止

运行：`fs_spatial_gate_coarsefit_300_first60_20261015/20261015T051202_244a08`。计划 60 帧，从完成的前 5 帧继续，实际完整输出 frame0–32；下一帧中途 SIGINT，退出码 130。frame29 终态 checkpoint 已保存。停止原因是发现与区域众数语义直接冲突的稀疏裁决，优先修正该机制，不是程序故障。运行使用启动时冻结的原代码，后来修正未混入此进程。

机制与前 5 帧一致：首次 100 步中先用 1/4、1/2 图像拟合轮廓，然后全图调细节；learnable gate 控制细分，窗口内拟合运动，硬 cut 之后按完整运动刷新区域众数再稀疏裁决。没有透明度修正或其他辅助模块。

实际完成的动态 frame1–32 平均 PSNR **34.332559 dB**，motion+birth 平均 **47.444375 KB/帧**，新增 3624 GS。前 frame1–29 平均 **34.351338 dB、46.468138 KB/帧**。上一轮相同 29 个动态帧为 34.351712 dB、46.030138 KB/帧，因此目前没有看到图像尺度调整带来的明显整体收益，也没有完成原计划的后段验证。存储口径不含帧索引与共享首帧。

新发现的核心冲突：硬区域的运动刚按 GS 当前完整量化运动统计成众数，随后的 Adam-metric L0 投影却可能因梯度接近零将该区域清零。这会删除全部成员的真实共享运动，不是保持位姿的重编码。

数值例子使用当前量化、参考点数、rate 权重和平移学习率。128 个点由一个非零区域运动（50 个量化格，约 0.00974 世界单位）完美解释，点残差为零，图像误差项为 `0.001*sum((xyz-target)^2)`。在这个正确解上，区域图像梯度为零；原投影把区域运动清零，产生约 **1.2144e-5** 的误差代价，仅省约 **5.4549e-8** 的区域存储代价，误差约为省下代价的 223 倍。因为代表由统计重编码得到，不能以其优化器梯度历史的小值断定运动不需要。

修正：窗口版硬 cut 下，众数刷新后保留区域代表；继续对 GS 局部残差执行原有稀疏裁决。区域编码成本仍进入 gate 的目标，若完整运动本来就是零，众数自然为零，不需发送。软估计阶段及旧默认逐步路径保持原处理。没有新增损失或模块。86 项检查通过，新增覆盖完美拟合共享运动不会被零梯度删除、相消运动自然归零且位姿不变。此前检查只验证众数刷新本身保持位姿，没有验证其后的区域投影，现已覆盖完整更新流程。

验证范围：第 29 帧 checkpoint 与从共享首帧重放到第 29 帧的码流核验通过，PSNR 34.182236 dB，单帧纯渲染约 200.788 FPS。包含读包与校验的播放约 4.545 FPS。未测此实际长前缀的全序列聚合 FPS。结果 JSON 位于 `/tmp/my4dgs_coarsefit_frame29_benchmark_20261015.json`。历史运行目录仅读取，原代码保存在 `source_snapshot`。
