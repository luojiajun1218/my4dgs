# 相对区域修正＋关闭分支拟合：270–272帧短测

## 结论

**本轮组合机制未改善效果，不作为默认配方。** 同一旧第269帧起点、相同270–272帧窗口，近端基线为 **32.426898 dB / 107.623 KB**，相对区域版为 **32.406921 dB / 114.020 KB**：PSNR下降0.01998 dB，完整更新增加5.94%。

作者提到的 **33.466945 dB / 87.874 KB** 是近端基线整个270–299帧的均值，不是这三个检查帧的均值。本轮没有训练完整300帧，也没有将三帧结果当作30帧结果。

## 核心想法与代码改动

尝试让父区域保留共同运动，子区域只学习相对修正，GS保存例外残差。gate仍通过参数、梯度和硬值/软梯度STE学习，未加入手工按收益开关的策略。

- `SpatialGateConfig.region_motion` 增加 `absolute / relative` 开关，默认 `absolute`。相对模式以87.9 KB版的联合总运动坐标为基础：图像拟合GS总运动，区域/gate由候选残差与码率目标学习，区域更新后重新表达GS残差，再做近端收缩。
- 相对模式沿树累加量化后的整数修正，支持完整和超过int16范围；每个局部修正与GS残差仍受int16范围约束。旋转继续采用旋转向量相加后作用于GS朝向，不是绕区域中心旋转或SE(3)变换的逐层复合。
- 被关闭祖先挡住的候选分支仍拟合“当前完整运动减父级运动”。辅助目标停止对GS、gate和父级目标求导，只更新候选修正；有效gate由主目标学习。
- 为真实存储相对修正增加独立`SPG2`语义与对应压缩封装；保存实际路径上的祖先修正，逐节点计费，不仅保存连接GS的末端节点。原`SPG1`绝对运动兼容保留。
- 增加9项相对模式检查，覆盖整数累加、祖先掩码、gate实际学习、关闭候选梯度、迁移/热启动、checkpoint恢复和出生/删除后的独立解码。

保留最大深度4、robust_median、上一帧热启动、前70步联合加30步固定gate、每步2视角、随后100步新增GS、α＜0.01删除；保留旋转更新。storage权重0.003，计费仍采用近端基线的`raw_blocks`，没有混入前次实际压缩估计改变罚价的因素。

## 原因诊断

1. 增加的完整更新约6.40 KB/帧中，约6.07 KB来自运动包。GS残差数量增加15.89%，主要多出旋转例外，未达到“更多GS完全由区域解释”的目标。
2. 固定第270帧完整整数运动，两种存储均为57,662 B；第272帧相对存储47,734 B，绝对存储47,666 B，只差68 B。将同一运动重新拟合绝对区域代表也没有减少GS残差。因此本轮主要问题是训练得到的运动/分解，而不是额外13个祖先节点本身占据了大量空间。
3. gate在70步之前有非零梯度，但有效划分仍为13次分裂。本轮未证明相对区域能增强gate核心收益。
4. 相对参数化会让祖先更新同时影响多个后代的累计预测，可能改变优化与近端收缩的耦合。本轮同时加入了关闭候选辅助拟合，**没有隔离两项因素，不能据此认定相对表示在所有配方下都无效**。
5. 第270帧4,086个单bin旋转残差中，仅11个连续值位于0.50–0.51 bin；第272帧对应为1,573个中的15个。这不是此前大量半bin堆积的同一现象。

这些观察支持保留绝对区域＋近端基线，后续重点仍是相关运动的共享与低收益例外更新的消除；相对参数化自身没有解决这件事。

## 核验与已修正的问题

**201项检查通过。** 三帧独立顺序解码后，测试图像PSNR与保存结果差为0，缓存开关像素差为0；第270、272帧全部原始GS属性与最终checkpoint逐张量完全相同，起始参考匹配源第269帧，源文件哈希保持不变。纯渲染均值197.98 FPS，10次预热、50次计时，不含解码与上传。

v1检查发现祖先遍历经过根的父编号`-1`后，误将末尾两个无效节点纳入字典支持。已修正为在根终止，增加混合深度掩码检查，并从原第269帧重新执行三帧训练。**本文和默认`comparison.json`均使用v2结果；v1的三帧数据只保留为排错记录。** 修正后保存节点为112，与99个末端节点加13个有效内部节点一致。没有将v1、v2当作六帧有效结果。
