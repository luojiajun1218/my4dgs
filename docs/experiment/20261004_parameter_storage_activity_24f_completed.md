# 参数存储与 GS activity loss：24 帧完成记录

## 本轮想解决什么

让需要改变的 GS 改变，其余 GS 保持上一帧位姿。本轮启用 `storage_loss_weight=0.001` 和 `gs_activity_loss_weight=0.001`，检查能否在保持画质的同时减少运动参数，并观察训练时间和 FPS。

保留区域和逐 GS 的直接平移、旋转残差，没有新增 latent 或 MLP。每帧仍是 100 步运动拟合、60 步学门、40 步硬门精修、100 步补点，共 300 步。loss 预热 100 步，在随后 20 步逐渐达到目标权重。

## 核心改动

`sparse_hierarchical.py` 按推理所需数组统计存储：开启的区域和逐 GS 运动行使用六个 float32 数值，另外计入完整 bool 门、int32 层级归属与父表、float32 旋转中心。学门阶段用期望开启行数求可导成本，硬化后按实际开启行数计数。activity 项惩罚旧 GS 的平均运动开启概率，只在学门阶段更新门。

`module.py` 另计保留新增 GS 的属性和删除索引；共享首帧单独计一次。`raw_parameters` 使用普通、未压缩的 NPZ 保存选中运动行和层级数组，不依赖熵编码。报告另列完整运动/门训练参数字节，避免把推理参数节省误认为训练张量已经缩小。

本次分析没有改模型或配置，没有启动训练，也没有写入两个历史输出目录。没有找到本轮归档的 source snapshot；代码解释结合保存的配置、输出数组和当前工作区实现，不能将其视为独立归档的代码版本对照。

## 存储到底下降在哪

不能直接比较旧报告的 3,110,869 B 和新报告的 1,783,808 B。旧报告计 packed 门和运动整数符号，漏计完整路由与旋转中心；新报告计普通推理数组。两轮都换算成“选中 float32 运动行 + 普通门 + 必要层级数组 + 新增属性 + 删除索引”，才得到表中的 -61.14%。这里是统一表示下的参数字节比较，不是说旧文件实际占用了 4.378 MiB。

## 为什么 FPS 和训练速度没明显改善

门关闭减少的是需要保存和改变的运动行，目前没有把训练计算同步改为只处理开启行。逐 GS 平移、旋转和门仍按全部 214,996 行分配；前向仍计算完整运动张量。硬门精修中只是给关闭行的梯度和 Adam 状态乘零，再调用普通 dense Adam。本轮报告的完整运动/门训练参数仍为 7,278,272 B，不含基础 GS、梯度和 Adam 状态。

| 每帧阶段耗时 | 前一轮 | 本轮 |
|---|---:|---:|
| 100 步拟合 | 5.069 s | 5.122 s |
| 60 步学门 | 3.081 s | 3.316 s |
| 40 步精修 | 2.043 s | 2.052 s |
| 100 步补点 | 4.194 s | 4.415 s |
| 上述四段合计 | 14.387 s | 14.906 s |
| 最终状态整理 finalize | 0.918 s | 0.254 s |

训练各阶段没有出现随开启行数下降而加速的现象，学门还增加了 loss 计算。finalize 明显缩短，与跳过旧 gate/layout 保存处理的代码路径一致。报告的纯训练计时和阶段计时不是严格可加的同一分解，不能把纯训练 -2.99% 全部解释为 finalize 的收益；finalize 按语义被排除在纯训练之外。单次运行也不能排除设备状态和计时波动。

最终评测渲染的是已经合成好的完整 GS 模型，静态 GS 也参与成像。最终 GS 数仅减少约 42 个，占约 21.5 万个的 0.02%。因此运动开启比例从 55% 降到 4.3%，不会自动提高最终渲染 FPS。此次 FPS 反而低 3.14%，缺少重复测量和渲染覆盖诊断，暂不能确定这点波动的具体原因。

## 自适应分层的实际问题

24 帧中，所有与开启 m 相关的区域 z 都为开，所有开启 m 的局部 z 也都为开，相关 z 的关闭总数为 0。关闭 m 的 GS 位姿变化数为 0，符合“没必要动就不动”。但对仍需运动的 GS，模型始终使用全部区域层加局部残差，尚未形成“区域已解释运动，局部可以关”的层级选择。

第 160 步各类 z 门都有非零梯度，因此不能简单解释成门没有连接到训练图。一个需要验证的原因是：100 步拟合时所有层和局部残差一起优化；60 步学门又冻结运动参数。关掉局部残差后，区域运动无法同时重新拟合来接替它。再加上 activity 和 storage 都奖励关闭 m，优化可能优先选择整行不动，而没有形成区域替代局部的路径。这是机制假设，当前没有单项 loss 或不同调度的独立对照来证明。

软门到硬门也有明显差距。第 160 步平均软 m 概率约 30.05%，最终硬 m 开启比例仅 4.33%。训练探针的平均 PSNR 变化如下，探针使用 cam01、cam17–20，**不是留出 cam00**：

- 全开拟合后到软门结束：-0.09718 dB。
- 软门结束到硬化后：-0.10436 dB。
- 硬化后到 40 步精修结束：+0.06080 dB。
- 精修后到补点保留结束：+0.01498 dB。

说明关门和硬化引入的损失尚未被后续步骤完全补回。两项 loss 确实启用：第 160 步平均 storage loss 为 0.00060886，activity loss 为 0.00030046，合计约为当步 image loss 的 7.45%。最终阶段的 activity loss 为 0 是阶段设计，不能据此认为没有生效。

## 下一轮建议

不优先加大两项 loss。本轮已大幅减少运动行，再加大会进一步施压画质，却无法缩小当前固定层级开销。

1. **先让关门产生计算收益。** 硬门固定后，把运动计算与优化参数收集到开启行，再回填完整渲染位姿。先用同预算对照验证位姿和质量，再讨论缩短训练预算。这主要针对精修等运动计算；40 步精修只占部分时间，不能期望它单独解决整帧训练速度或最终 FPS。
2. **验证区域替代局部的训练路径。** 对比先拟合区域再开放局部残差，或学门时允许受控的区域重拟合。目标是让 z 真正关闭，并减少硬化的画质损失。候选调度和超参数需另行讨论，当前没有选定或运行。
3. **处理固定层级开销。** 检查稳定拓扑能否跨帧共享，以及旋转中心能否由已保存状态确定地重算。重点是少重复保存模型结构。拓扑重建、新增和删除的身份对应必须保留，不能直接假定每帧结构都相同。
4. **单独定位渲染 FPS。** 运动行计算优化不会改变已经合成模型的最终渲染工作量。需先查可见 GS、屏幕覆盖和栅格化耗时，再选择能够维持画质的渲染或 GS 数量优化。

本轮是单 seed、24 帧前缀，同时启用两项 loss 并修改计数/保存路径，无法分别归因。当前结论是：运动稀疏性和参数存储改善明确；层级选择与计算稀疏性尚未实现；PSNR 略降，FPS 没有改善。聚合核对结果暂存于 `/tmp/my4dgs_parameter_loss_24f_analysis_20261004/summary.json` 和 `frames.json`，原始证据为两个运行的 `frame_summary/`、`frame_storage/`、保存配置和完成日志。

### 已完成的离线检查

只读取本轮 24 个普通参数包，在 `/tmp/` 写入一个独立的稀疏数组原型。没有修改历史输出、训练代码或配置，没有重训。保留所有 float32 运动数值，不引入 latent、MLP、熵编码或新的量化：

1. 用运动 GS 的 uint32 行号替代完整 m 数组。
2. 只保存这些 GS 的最细区域归属和局部 z。当前区域编号范围允许用 uint16 无损保存；超出范围时需要使用更大的整数类型。
3. 根据这些归属和父表得到相关区域，只保存这些区域的 z 和旋转中心。区域运动行的顺序与数值保持不变。
4. 父表保留完整结构，但当前编号范围允许从 int32 缩为 uint16。没有跨帧依赖，也没有省略当前帧实际需要的路由。

静态 GS 继续来自上一帧完整 GS 状态，不需要为本帧静态位姿额外携带运动归属。它们仍参与渲染。将来的帧各自携带当帧运动 GS 的归属；这不等于从训练 checkpoint 删除完整拓扑。
