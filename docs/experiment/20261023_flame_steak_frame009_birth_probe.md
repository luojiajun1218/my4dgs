# Flame Steak：第009帧新增GS短验证

2026-10-23完成，帧编号009。验证用户提出的“直接在第9帧看新增收益”，使用已经实现的误差像素补点原型。上一轮提出的多视角三维候选搜索尚未实现，本次不将它作为已验证方法。

## 运行方式与核心逻辑

原300帧运行没有保存第8、9帧checkpoint。读取最近的`rigid-ckpt-3-300.pth`，恢复优化器、运动及随机数状态，按原配置连续训练4–9帧，保存第8帧终态和第9帧180/260/300步checkpoint。数据通过原软链接读取，不重新训练首帧，不改写原output。CUDA训练存在数值差异，因此新增收益统一相对于本次第9帧180步运动终态计算。

然后从第9帧运动终态独立测试补点：16台训练相机提出误差像素、用当前渲染期望深度反投影位置、图片取色、限制初始投影尺度；固定全部旧点属性，新点每步平均4个拟合视角，拟合120步。cam04/08/12/16作为训练集内部验收相机，不参与候选初始化或参数拟合；cam00只测试。参数维持前一轮已发布的诊断原型，没有针对第9帧调整。

本次没有修改训练主链路或验收标准。[诊断程序](../../scripts/probe_birth_revision.py)不执行完整新方案的码流编码、260步准入和40步运动幅值精修；其120步是新点属性拟合，不能直接标成正式完整流程的第300步。

## 结果

| 条件 | cam00 PSNR/dB | 相对本次运动终态/dB |
| --- | ---: | ---: |
| 本次运动180步结束，128,807旧GS | 33.728504 | 0 |
| 原型：新点拟合80步，仅加点 | 33.744125 | +0.015621 |
| 原型：新点拟合120步，仅加点 | 33.748974 | +0.020470 |
| 原型：再尝试删除749个低贡献旧点 | 33.748974 | +0.020470 |

生成832个候选，全部候选行在这个诊断中保留拟合，没有正式新点alpha/尺寸终剪。退役候选数749，在`ceil(0.9×832)=749`至`floor(1.1×832)=915`范围内；按真实合成权重排序，并保护新点预测来源。删除量比较749、832、915三个选择，训练集内部验收损失最低的是749。cam00上删除影响小于显示精度，新增收益没有被本次删除抵消。

## 验收指标存在冲突

| 内部4台验收相机平均指标 | 运动终态 | 加新并试删后 |
| --- | ---: | ---: |
| 平均PSNR/dB | 36.654780 | 36.682871 |
| photo loss，0.8L1＋0.2DSSIM | 0.013453601 | 0.013455588 |

验收相机平均PSNR增加0.028090 dB，但photo loss微幅上升约0.01477%。现有原型要求photo loss至少下降0.1%，因此这批增删被拒绝，模拟提交数为新增0、删除0，回退后的测试PSNR仍为33.728504 dB。33.748974 dB是候选效果，不能写成已通过验收的最终结果。

这里的“拒绝”不能被解释为PSNR无收益：判据优化的是L1＋DSSIM，目标与用户关心的平均PSNR存在差异。本次保持原判据，没有根据cam00决定接纳。后续验收需在训练集内对齐PSNR目标，同时保留SSIM等质量检查。

## 与原运行的区别及判断

原300帧日志第009帧为33.566998→33.558056→33.569832 dB，对应运动结束、增删结束和最终精修。恢复重跑原流程为33.728504→33.728466→33.712978 dB，新增201、删除221，动态负载33,370 bytes。这些是原流程的重跑结果，不是新原型的存储成绩。

两次运行的运动终态有差异，不能将本次原型33.748974减去原日志33.566998，称作新增算法提升0.182 dB。可归于本次固定运动输入之后的候选收益是0.020470 dB，仍然偏低；第9帧并未显示足以推广到300帧的明显收益。测试结论只覆盖这个帧和当前原型，不能判断尚未实现的多视角三维候选方案是否有效。

本次也说明：更换低贡献退役排序不能单独解决新生收益问题；仅有训练集内部验收也不够，验收指标必须与目标一致。三维候选位置和有效覆盖仍需要改进，不能把当前结果归咎于“只测试了运动较小的首个动态帧”。
