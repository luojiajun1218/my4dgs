# 共享细化与全GS残差联合：原生前三动态帧

## 想法与改动

上一版继承式gate在后期小幅改善，但原生早期画质下降，且大部分GS被禁止使用私有残差。本次保留父运动加子修正、随机学习gate和联合区域DC，让所有GS拥有必要的残差，由原有量化与近端决定稀疏支持。这样gate只控制共享细化。

提交`245572f`扩展既有模式组合：`region_motion: relative`、`joint_image_gradients: true`、`image_relaxation: stochastic_ste`，关闭`hierarchical_private`、`private_full_motion`及冻结坐标切换。实际运动始终为选中共享预测加GS残差，GS在粗区域也接收图像梯度。独立完整提案辅助渲染关闭，因为GS现在每步都参与主图像；颜色仍使用同一路径继承，并在gate冻结时转成原SDR1表示。

没有新增量化、出生或图像目标设置。仍是L1+SSIM、storage0.002、运动L1=0.5，运动200步（70步gate联合、30步固定gate、100步固定支持精修）再100步新增，每运动step2视角，全部旋转关闭。

新增两项检查覆盖所有GS在不同采样层级的图像梯度、零子修正继承、粗区域例外的冻结/精修/恢复及精确解码。目标检查10项通过，**320项完整检查通过，46.799秒**。

## gate与GS存储缺少联动

当前物理坐标是`总运动 = P(gate) + E_GS`，编码损失为区域成本加`R(E_GS)`。在保持GS残差参数不变时，后者对gate的偏导本来就是0；gate不能从这部分得知细化共享预测后能够少传多少GS数据。只把GS残差放开，未自动形成所需的共享激励。

只读梯度诊断恢复第1帧step70，在内存中重启可学习开关状态、固定区域参数，并分别保留/归零全部GS残差。原始字节代理由734309B降至751B，**gate的运动码率梯度逐元素差为0**，其范数均为1.957245e-9。该值是优化代理，不是实际压缩文件大小。诊断不更改checkpoint，也不用于选择gate。

这揭示的是参数化与目标之间缺少联系，不能简单给gate强行附加与实际前向不一致的梯度。下一步需要让gate的存储目标基于“完整运动减候选共享预测”的实际可编码残差，同时保留区域预测的真实图像监督，再核对冻结和重编码过程的一致性。尚未实现或取得这一步的效果。
