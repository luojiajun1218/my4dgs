# 节点操作动态树与固定树：30帧对照完成

两组均使用共享首帧、相同20个训练视角和cam00测试。每帧200步运动、100步新增GS，storage权重0.005，fixed16平移/旋转分块编码。初始3层，上限4层。固定树同样在第100步、每5帧重置优化器，避免额外重置造成比较偏差。

区别是动态组启用30%高分区域拆分。候选有80步gate压缩与20步精修机会，关闭的新拆分在编码前移除。本轮关闭合并与交换。

## 结果

| LPIPS | 0.118889 | 0.118789 |

| 被接受的编辑批次 | 0 | 5/5 |
| 最后一帧第4层节点 | 0 | 166 |

动态组平均PSNR增加0.0047 dB，动态必要字节增加0.45%。最差同帧差值为-0.1243 dB，最好为+0.1778 dB。

5次分别保留14、18、22、12、17个拆分，结构费用约百字节。树的修改已经能跨帧保留，没有再出现MB级归属表。

但画质收益太小。结构启动前的1–4帧，两次运行已存在约-0.025至+0.004 dB的差异。GPU训练和后续新增GS优化存在运行波动，不能把0.0047 dB当作稳定改善证据。日志FPS也不是完整播放FPS。

## 下一步依据

新分支通常在压缩阶段被关闭：每次近800个试拆，最终只保留十几个。这说明码率选择有效，也说明候选需要更充分的运动拟合机会。接下来试用正的候选路径gate初值，避免刚提出的新细节和祖先同时过早关闭，并提高运动量化精度、适度减轻存储惩罚。保持同协议对照，先检查是否有明显画质收益，再进入300帧。

本次没有新增训练代码之外的表示类型，没有开启attribute gate。
