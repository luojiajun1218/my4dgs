# 训练计时、冗余计算清理与终态残差检查

480 W 正式 300 帧结果已提交为 `2196e6a`，标签 `flame-steak-half-480w-final-20261019`。其 **34.211170 dB / 51.027672 KB / 292.205 纯渲染 FPS** 仍是正式结果。以下短测不能替代完整序列指标。

## 目的与改动

作者要求优先改善画质和动态存储，同时去除冗余计算。保持每帧 **200 步运动 + 100 步新增**、每运动步 2 个视角，以及原 20/70/100/200/300 阶段边界；不缩短训练，不调整 gate 的学习方式。

- `pipeline/trainer.py`、`pipeline/timing.py`：按 GPU 同步后的阶段边界，分别记录训练、评估、checkpoint、整帧墙钟时间。相同阶段内不逐步同步。保留历史 `elapsed_seconds` 的含义，新增独立字段，避免把旧统计直接改名为纯训练。
- `scripts/benchmark_rigid_residual_tree.py`：顺序解码报告增加分项计时汇总，分别统计全部动态帧及排除第 1 个动态帧的范围。旧报告或混合前缀缺少分项时，完整范围的均值为未知，并单列已测帧覆盖范围；不会用旧 `elapsed_seconds` 补作训练时间。
- `pipeline/module.py`：运动证据的两个诊断计数留在 GPU 累积，在 checkpoint 或阶段末再一次读回，避免每步同步；参与训练和新增的证据逻辑不变。
- `pipeline/model/contribution_renderer.py`：训练视角使用独立的屏幕空间叶子张量，移除多余的 `+ 0` 运算；无梯度渲染按尺寸、设备和类型复用全零缓冲。
- `rigid_residual_tree.py`、`spatial_gated_motion.py`：新增默认关闭的 `terminal_motion_proximal`。开启后仅在第 200 步完成幅值精修时，再执行一次既有的 GS 块成本检查；不重选 gate、不移动阶段边界。动机是精修阶段不使用稀疏惩罚，终态可能仍有收益较小的残差块。是否值得保留需要实验判断。

## 已完成：实现核查

全套 **356 项回归检查通过**，涵盖分项计时、每视角独立梯度缓冲、诊断整数恢复、终态检查时机及 checkpoint 恢复。真实 CUDA 场景采用第 3 帧解码状态：原屏幕空间创建方法与新方法的图像逐像素一致，可见性和实际合成证据一致；无梯度缓冲复用后也一致。

之后补充分项汇总功能，相关计时与顺序基准检查 **16 项通过**，包含首个动态帧单列、旧合计时间不冒充训练时间、部分覆盖及非法数值检查。冗余清理和基础计时已单独提交为 `c7c9e5d`。
