# Flame Steak：storage loss 从 3e-5 降至 2e-5

2026-10-22 完成。作者执行了完整第 0–299 帧，运行目录为 `output/n3dv/flame_steak_1020/full300_storage2e-5/20261022T110930_8fc210`。本记录统计结果，并分析 GS 增删、画质与存储的关系。当前训练机制未因本次分析而改动。

## 实验 idea 与改动

将 `module.rigid_tree.rate_loss_weight` 从 3e-5 减为 2e-5，固定 `rate_normalization: budget`、`rate_budget_bytes: 50000`，使每字节损失系数从 6e-10 降为 4e-10。目的是放松存储约束，让已有 GS 更充分拟合，再观察是否减少补点需求。

两轮配置快照的字段仅有上述权重及实验名不同。复用同一首帧；两轮解码参考 SHA-256 均为 `020119f664cf1e4b54ced2a7355e6521cf6f4157bd2b63f8f299305d955fbd9c`。图像均为 1345×1008、20 个训练视角、cam00 留出，区域共享颜色保留，每动态帧 200 步运动 + 100 步新增。此次运行也包含此前新增的终端自动汇总和验证时 FPS 采样；新增评估保持随机数状态，未更改训练算法。本次是两次独立运行的观察比较，未通过重复运行估计波动。

降低 storage 权重后，平均 PSNR 变化为 -0.00756 dB，未获得全序列平均 PSNR 收益；LPIPS 略降，SSIM 下降。动态存储增大 **10.79%**，末帧 GS 仅比前轮多 141 个。这一轮没有解决增删失衡问题。

## 增删机制的证据

每帧平均正式新增 **322.64** 点、删除 **59.06** 点，净增 **263.57** 点。相对上一轮，新增少了 1,238 点，但删除也少了 1,379 点，最终总数仍略高。

候选阶段累计克隆 436,147、split 净增加 1,949、剪除 341,628，正式保留 96,468。候选剪枝确实执行了；问题不是完全没有剪枝。全部帧均核对了 `当前数=上帧数-删除数+新增数`。

顺序解码全部 299 个运动包、追踪出生帧与 survivor 行号后，末帧组成是：

- 原首帧存活 **97,552** 点，原首帧累计删除 9,676 点。
- 后续新增存活 **88,484** 点，后续新增累计删除 7,984 点。

本轮正式新增中约 91.72% 仍在末帧，包含临近末帧新增的年轻点；有 21,717 次正式新增取自此前已经新增的源点。新点可以继续作为后续克隆来源。

对 12 个保存的 step300 checkpoint，保持拟合后的其他属性不变，仅临时移除当帧新增进行渲染：平均收益为 +0.01559 dB，7 个样本中新增后的 PSNR 更低，部分差异很小。另一方面，末帧移除所有后续出生的点会使 PSNR 从 **34.381130 降至 31.994400 dB**，说明累计新增中有重要的有效表示，不能全部视为冗余。上述均为固定其他属性的渲染诊断，不模拟从未新增点的训练。

当前机制的主要缺口：

1. 准入以梯度克隆为主，没有对当帧新 GS 的数量及完整出生代价施加直接损失；storage loss 约束已有运动/透明度/颜色更新，并不会自动控制 GS 总数。
2. 正式并入后，退出主要依靠当前量化透明度低于 0.01，缺少长期贡献、冗余和持久有效性的判断。透明度变化的稀疏惩罚鼓励少改 alpha，并不等于让无用 GS 的绝对 alpha 持续归零。
3. 删除发生在 step200、开始新增之前。后 100 步已有 GS 的几何固定，旧透明度也未参与优化（`opacity_update.joint_with_birth: false`），旧区域 DC 仍会更新。新点进入后，缺少旧点与新点竞争、旧点降低透明度并退出的过程。

静止且有贡献的点应保留并复用；不能把没有运动直接当作删除理由。低贡献、重复表示才是需要辨别的对象，临时遮挡也不能简单当作永久无效。

## 300 步的职责与建议

本轮实际调度：

| 步数 | 职责 |
| --- | --- |
| 1–20 | 共享运动与颜色预热，gate 不更新 |
| 21–70 | 学习共享区域及 gate，逐点运动残存保持为零 |
| 71–100 | gate 固定，释放 GS 残存并进行稀疏选择 |
| 101–200 | 固定运动支持的数值精修；step200 提交透明度、删除低 alpha 点、创建新候选 |
| 201–300 | 优化新增 GS 和共享 DC；step240、280 再增密，step300 仅剪枝并编码 |

动态帧 step200 平均 PSNR 33.997386 dB，step300 平均 34.015512 dB，后 100 步平均增加 **0.018126 dB**，121/299 帧下降。该阶段还改变共享 DC 并完成量化物化，因此不能把差值完全归因于新增；也不能由此断言出生阶段可以删除，后续帧已依赖累计新增。

建议下一步保留 300 步总预算，重点调整末段职责，而不是只继续扫描 storage 权重：

| 步数 | 候选职责（尚未实施） |
| --- | --- |
| 1–70 | 共享运动、颜色与 gate 学习 |
| 71–200 | 现有 GS 残存、透明度与颜色细化 |
| 201–250 | 按训练视角收益接纳候选新点并拟合；为出生设置显式成本 |
| 251–300 | 停止新增，固定拓扑精修，允许旧点透明度与新点、共享颜色协同调整 |

`birth.densify_interval: 50` 可将当前两次后续增密改为 step250 一次，给后续分裂点留下 50 步；`opacity_update.joint_with_birth: true` 可启用已有的旧透明度联合优化路径。但这些设置本身不提供贡献筛选，也不保证总点数下降；split 净增加只有约 2 千，主要增量仍来自初始克隆后被保留的点。核心仍需补齐新点准入及长期退出标准。帧末删除若新增实现，需要同步维护源点预测、survivor 映射和码流恢复。

贡献判断应基于训练视角，cam00 只用于评价。本次尚未改变上述配置或算法，也未启动下一轮训练。

## 两个 storage 的区别

`Storage (dynamic payload+index, excludes reference)` 是 **299 个后续帧完整增量的平均大小**。包含运动、出生属性、透明度、颜色和必需的每帧 JSON 索引，不含共享首帧：

`14,067,922 bytes / 299 = 47.049906 KB/动态帧`。

`Storage (including reference, amortized)` 是 **首帧参考与全部动态增量的总大小，除以 300 帧**：

`(9,225,985 + 14,067,922) bytes / 300 = 77.646357 KB/帧`。

首帧参考是一次性保存的首帧 GS 与解码信息，不是重复保存 300 份，也不是训练 checkpoint。本轮整段码流 23.293907 MB，首帧参考占 9.225985 MB。项目此前的“后续帧约 50 KB”看第一个数，整段存储成本则看第二个。

| 动态组成 | 3e-5 KB/帧 | 2e-5 KB/帧 |
| --- | ---: | ---: |
| 运动包 | 31.6033 | **36.2749** |
| 出生属性包 | 6.6466 | 6.5549 |
| 透明度 | 3.2787 | 3.2784 |
| 共享颜色 | 0.2802 | 0.2830 |
| 索引 | 0.6587 | 0.6587 |

此次存储增量主要来自运动包。每帧需要独立残存运动的旧 GS 从平均 9,392.81 增至 11,435.46，符合放松稀疏约束后更多点更新的方向。运动包还包含区域、删除映射、新点位置等，不能将其全部当作逐点残存字节，也不能把出生属性包当作新增点全部开销。
