# 稀疏数组与匹配 storage loss：24 帧完成记录

## 本轮想解决什么

上一轮已经让多数旧 GS 不动，但完整门、层级归属和旋转中心占参数存储的 84.43%。本轮只保存运动 GS 及其相关区域的信息，并让 storage loss 按这种表示计算成本。目标是减少重复结构信息，而不是引入 latent、MLP 或熵编码。

结论：必要模型文件从 **1.792 MB 降至 0.375 MB/动态帧，减少 79.06%**。PSNR 比上一轮低 0.03734 dB，仍高于本地原版同帧均值 0.07497 dB。FPS 和每帧训练时间基本不变。

## 运行与代码改动

- 配置：[fs_sparse_storage001_activity001_candidate_24f.yaml](../../config/fs_sparse_storage001_activity001_candidate_24f.yaml)。
- 本轮：`output/fs_sparse_storage001_activity001_candidate_24f/20261004T225710_d1fa51/`。
- 上轮：`output/fs_parameter_storage001_activity001_candidate_24f/20261004T205929_a23e9e/`。
- 动态帧 1–24 全部完成；完成日志时间为 2026-10-04 23:05:17。
- 两轮保存配置只差实验名和 `motion_export_format`。均为 storage/activity 权重 0.001，100 步拟合、60 步学门、40 步硬门精修、100 步补点；预热 100 步，渐增 20 步。
- 同一共享首帧、resolution=-1、SH degree=1、seed=0。cam01–20 训练，cam00 留出评测；24 帧训练视角抽样顺序一致。

`sparse_hierarchical.py` 新增 `sparse_parameters` 保存与读取：用 uint32 运动行号替代完整 m 数组；只保存这些行的最细归属、局部 z，以及相关区域的 z 和旋转中心。当前区域编号可以用 uint16 无损保存；父表保留完整结构。运动值仍是 float32，使用普通未压缩 NPZ，各帧独立携带必要结构。

storage loss 同步计入运动行号、局部归属和门、相关区域的旋转中心与门、运动数值，以及固定父表。学门阶段计算期望成本，区域相关概率由其后代 GS 的运动概率得到；硬化后按实际数组计数。

`module.py`、`trainer.py` 和 `summarize_experiments.py` 区分参数字节、必要模型文件字节和训练检查产物。新增确定性测试覆盖稀疏表示恢复、软硬成本一致性与统计读取。实现阶段通过 155 项检查；本次结果分析只读审计输出，未重训或修改模型/配置。

没有找到本轮归档的 source snapshot。方法解释依据保存配置、输出数组和当前工作区代码，不将它视为独立归档的代码版本对照。

结构信息减少 **92.66%**，占参数比例从 84.43% 降至 **30.11%**，是此次收益的主要来源。运动数值另减少约 7.8%。

此前把上轮同一批运动值离线改存稀疏数组，参数均值已能降至 395,196.79 B；本轮为 366,895.67 B，比该同格式对照再少 **7.16%**。所以不能把全部 79% 节省归因于重新训练的 loss：大部分来自保存表示，较小部分来自进一步减少运动行。

逐个审计 24 个 NPZ：必要数组字节与报告一致，成员使用 `ZIP_STORED`，运动行号为 uint32，当前最细归属为 uint16；加上新增/删除成本与硬成本一致，实际必要文件大小也与报告一致。

## 门与画质

24 帧中，m 关闭的旧 GS 实际位置或旋转变化数合计为 **0**，符合“没必要动就不动”。但相关区域 z 和运动 GS 的局部 z 全部开启，关闭数均为 0。目前实现了 GS 运动稀疏性，尚未形成“区域运动足够，就关闭下一层”的选择。

第 160 步平均软 m 概率为 28.53%，最终硬开启比例只有 3.97%。storage loss 为 0.00042425，activity loss 为 0.00028535，两项合计约为当步 image loss 的 5.79%，均已生效。

训练探针使用 cam01、cam17–20，不能替代留出 cam00。其阶段均值变化为：

- 拟合结束 → 软门结束：-0.11567 dB。
- 软门结束 → 硬化后：-0.11455 dB。
- 硬化后 → 40 步精修结束：+0.06158 dB。
- 精修后 → 补点保留结束：+0.02037 dB。

关门和硬化造成的下降没有被后续完全补回。相同的 0.001 权重也不意味着相同的关门压力：以前完整归属等成本是常数，本轮运动行号、归属和相关区域成本随门变化，产生了额外梯度。运动开启行减少 8.28%，可能解释部分画质变化；没有单项 loss 对照，不能证明它是唯一原因。

## 为什么速度持平，以及下一步

两轮完整运动/门训练参数均为 7,278,272 B。运动前向与 Adam 仍处理完整行，硬门精修只是屏蔽关闭行的梯度和状态。100 步拟合、60 步学门、40 步精修、100 步补点的阶段时间分别约为 5.126、3.293、2.056、4.381 s，与上轮基本相同。保存更小没有自动带来计算稀疏性。

最终渲染 GS 仍约 21.5 万个。静态 GS 也必须成像，因此运动行数减少不会自动提高最终渲染 FPS。

另有一个计时诊断问题：`tree_setup.action` 在第 5、10、15、20 帧记录重建，但 `stage_seconds.tree_rebuild` 始终为 0。当前代码没有单独填充这个字段，不能据此推断没有重建；后续应补齐诊断。

建议保留稀疏保存表示，暂不加大两项 loss。先在相同预算下让硬门后的运动计算与优化只处理开启行，验证数值和质量后再考虑缩短训练。另做独立对照，改善关门时区域运动接替局部残差的能力，以及软门到硬门的过渡，追回画质。最终 FPS 需要单独分析可见 GS、屏幕覆盖和栅格化耗时。完成这些后再验证长序列；本次不选择新超参数、不启动下一轮。
