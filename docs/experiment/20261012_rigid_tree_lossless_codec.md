# 量化后的整数直接存储

新增 GS 的属性已经按来源 GS 做预测和量化，但原 RTB1 文件仍保存解量化后的 float32。此次改为 RTB2：保存真实量化整数和四个量化步长，预测来源沿用运动文件中的 `birth_sources`。每个字段按范围选择 int16 或 int32。编码前在 CPU 上重建并逐字节比对；不能精确重建时回退 RTB1。旧格式仍可解码，不增加运动模式。

运动文件自动比较原始、zlib 和 XZ 三种完整包的实际长度，选择最小者。解码限制输出大小和 XZ 内存，并检查头部、长度、校验值及尾部。两项改动均不重新训练、不改变量化结果。

已完成两组独立 CPU 重编码。原文件只读，新文件写入独立目录。每组从原 frame49 参考开始连续解码帧 50–52；全部 GS 属性的 SHA256 和解码状态 SHA256 与原实验 manifest 一致，正式 replay 脚本也通过。下表是实际生成的 motion + birth 文件字节，不是估算。

L2 三帧合计从 140,140 降至 110,785 字节，减少 20.95%。L1 三帧合计从 120,303 降至 93,608 字节，减少 22.19%。六个运动包均选择 XZ，六个出生包均使用 RTB2，无精确性回退。

本实验只验证无损编码，不报告新的 PSNR 或 FPS，也不代表全 300 帧达标。后续训练应直接输出新格式，并和同格式的基线比较，避免把编码收益归因于训练改动。
