# Coffee：区域与逐点全属性，增强逐点尺度存储惩罚

## 背景与设置

上一版区域和逐点全属性更新在 Coffee 前 30 个动态帧达到 29.7708 dB、69.836 KB/帧，但逐点尺度平均 6,703 点非零；将尺度从属性包分离独立编码约 17.57 KB/帧。保持共享首帧、depth-5、每帧 200 步、每步一个随机训练视角和所有现有量化步长，单独增强逐点尺度的固定码率惩罚。

新增 `full_update.point_logscale_rate_multiplier`，默认值为 `1.0`；本次设为 `2.0`。原有全属性基础倍率 `point_dc_rate_scale=4.0` 不变，因此逐点尺度的有效倍率由 4 变为 8；逐点 SH、区域尺度和 SH、位置、旋转及透明度的惩罚不变。该倍率作用于训练时近端筛除逐点尺度块的字节价格，报表中的尺度代理损失同步计入该倍率；基础 `rate_loss_weight=0.008` 不变，无反馈目标。实际压缩字节与训练代理费用分别统计。

配置 `config/coffee_regional_point_full_scale_rate2_200step_30dynamic_20261109.yaml`；输出 `output/experiments/coffee_regional_point_full_scale_rate2_200step_30dynamic_20261109/20261109T115127_e5dc9b`。与上版输入配置仅实验名和逐点尺度倍率不同。frame 0 是相同的 160,000 点共享首帧，frame 1–30 为动态帧；cam00 已参与开发选型，不是独立最终测试视角。

## 全属性量化残差核对

区域与逐点位置、旋转均通过运动码流传输量化残差；旋转量化的是旋转向量并复合到前一解码帧的旋转。尺度、DC 和方向 SH 使用量化增量，逐点通过 `FUA`、区域通过 `RFA1` 编码。逐点透明度通过 `OVX` 传输相对上一解码帧的 alpha 量化增量；区域透明度通过 `RFA1` 传输 logit 量化增量，作用于逐点透明度结果。两层使用不同透明度参数域，不是同一个 alpha 残差直接相加。量化零值无需传输，所以开放某属性不代表它每帧都会非零。

区域属性随运动 gate 硬切分的所有权变化，叠加在逐点属性之后；区域属性误差和区域属性码率没有独立反传影响 gate 选择。位置、旋转、逐点和区域属性码流、透明度包及每帧 manifest 均计入动态存储。

上一版的离线检查中，只对已训练好的逐点尺度残差重新量化并按每帧原参考独立重编码：步长由 0.005 改为 0.01，平均属性包仅从 25.80 KB 降到 22.85 KB；步长 0.02 时约 19.74 KB。这不是重训练、重渲染或递推播放结果，无法作为画质预测，因此本次优先测试逐点尺度码率惩罚，不改量化步长。

新设置相对上一版低 0.0331 dB，动态存储减少 8.526 KB/帧（约 12.2%），5/30 帧 PSNR 更高；逐点尺度平均非零数从 6,703 降到 3,101，DC 平均非零数分别为 2,292 和 2,336。各运行的解码状态独立递推，单次 30 帧不能精确拆分因果效应或排除运行波动。新设置相对 300 步稀疏方案高 0.0407 dB，动态存储多 6.595 KB/帧；属性和训练路径不同，这不是单一因素消融。

新设置的区域尺度、DC 和方向 SH 平均有 24.9、31.5、11.6 个区域非零；区域透明度只有 4/30 帧非零。区域透明度开放更新但目前很少传输，原因可能是惩罚偏强、量化或场景需求不足，不能仅凭此实验确定。区域包平均 0.306 KB/帧。逐点旋转平均 140 个非零块。

## 核验

各组对照的共享首帧数组逐项一致。30 份 manifest 均记录 200 次优化、100 次全点和区域属性更新、零探测和零增点；每帧单视角训练采样 200 次。逐帧报表确认尺度倍率为 2，DC 和方向 SH 倍率均为 1；训练前向与解码图像最大差均为零。独立顺序解码至 frame 30 并核验各帧摘要通过，末状态 SHA256 `26f1b6df1d10b0df3dc48f502bdafcfc8a048f35f91b28cab884099870f80217`。定向数值检查验证尺度倍率只改变逐点尺度的块筛除，不改变颜色筛除；相关回归共 123 项通过。本次未测渲染或完整播放 FPS。
