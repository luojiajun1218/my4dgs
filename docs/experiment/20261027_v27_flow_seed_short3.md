# v27：两视角共享运动初始化的短程联调

本轮完成0..2帧训练、650项检查及三帧CPU/GPU独立重放；没有运行v27完整300帧，不作SOTA、完整码率或FPS结论。v26完整序列继续按原队列运行。v19恢复点仍为`895db0e`。

## 出发点与实现

已有冻结检查未支持直接放开旧颜色、朝向或尺度。这里转向一个文献已有依据的问题：仅用图像残差拟合运动，可能把外观变化解释成几何位移。[MoRGS](https://arxiv.org/abs/2603.25042)已采用稀疏视角光流、运动offset与confidence处理此问题；光流引导本身不能作为我们的新颖性。本轮只检验它能否提供更合适的共享平移起点。

在v26配置上增加`module.rigid_tree.flow_seed: true`，默认关闭。在每帧第一个Adam步骤之前：

- 只根据20个训练相机的已有位姿和固定参考支持中心，选择三角化角度较好的两个相机。本场景为cam11、cam20，约48.06°；不读取测试图像或用测试指标选择相机，也不渲染20视角。
- 使用固定torchvision RAFT权重，计算这两个相机前一帧到当前帧的双向光流。重复纹理会产生明显误匹配，因此比较光流对应与同像素静止假设，以观测图像噪声和一像素位移尺度作软收缩，并计入双向一致性及对应歧义。这是一个固定的证据模型，不是已校准的真实运动概率。
- 通过原生alpha/T颜色Jacobian，将像素光流和二阶矩聚合到源GS的实际可见支持。再用两个相机的投影Jacobian为已有空间树节点求平移初值；至少各有一个有效像素、数值条件合适且量化候选改善同一光流二次目标时才更新，否则保留继承预测。
- 初值仍使用原来的相对区域整数残差、量化格点和SPG5/6格式。之后每步两视角、70/200/300调度、旧透明度、新点全部属性、CF支持选择及storage/population loss保持原设置。初始化额外2次GS前向、4次颜色反传及4次光流网络推理，没有增加Adam步骤或解码状态。

实现位于隔离分支`research/v27_flow`，源码`64e3e0a15dca10ccb14377c95a4c5ea2cfd68a45`，目录`tmp/research_motion_20261027/v27_source`。主要改动为`motion_seed.py`、刚体配置的可选字段、`Module.prepare_frame`的一次性调用与数值检查。网络构造隔离CPU RNG，权重冻结且不注册进GS模型/优化器；实际加载检查确认RNG不变。

训练侧预训练权重为torchvision0.20.1的`RAFT_Large C_T_SKHT_V2`，21,106,607B，SHA256为`ff5fadd56d26b40647388883af1547351ea17868b765c05b27231e72dd16a322`，不进入解码器或动态码流。它仍是应披露的编码侧先验。

## 已完成诊断与结果

先在v25精确前一帧raw状态上做了frame1、99、199的冻结初始化检查。只使用两个训练相机拟合，随后评估全部训练相机及cam00，没有Adam拟合或按测试结果选步。仅用原提案的随机相机对，原始光流在重复纹理上存在大误匹配；加入静止证据后更稳定，但不能认定初始化普遍提高图像质量。最终按相机位姿选择两视角时，cam00相对继承共享初值分别变化+0.02101、−0.03234、−0.00989dB；全部训练相机均值变化约+0.04103、−0.21384、−0.01085dB。它只支持进一步联调，不是最终训练收益。
