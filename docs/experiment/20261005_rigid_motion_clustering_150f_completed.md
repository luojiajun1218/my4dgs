# 空间树与运动聚类树：150 个动态帧对照

## 本轮想解决什么

空间相邻的 GS 不一定一起运动。本轮尝试按“能否由同一个刚体变换解释”来分组，让区域运动更容易代替逐 GS 的局部运动。attribute gate 暂不加入。

**结果：聚类组平均 PSNR 高 0.112 dB，必要文件多 2.91%，采样渲染 FPS 基本持平。** 但建树诊断没有验证出更强的运动一致性：当前聚类目标高度偏向空间项。两组的层级 gate 也仍然几乎全开。这轮有画质收益，核心机制还需要修正。

## 两组具体有什么区别

| 项目 | 空间组 | 聚类组 |
|---|---|---|
| 建树依据 | 现有空间分区 | 用逐 GS 运动探针拟合共享刚体，再重新分配归属 |
| 根层候选 | 现有空间归属 | 8 个空间近邻区域，加当前归属 |
| 子层 | 现有空间树 | 在选定父区域内初始化子区，再按拟合评分分配 |
| 分配评分 | 不做运动聚类 | 位置拟合误差 + 朝向一致性误差 + 空间距离惩罚 |
| 区域预算 | 996 / 2,988 / 8,964 | 相同 |
| 刷新 | 每 5 帧重建，其他帧复用 | 相同，重建帧再运行运动聚类 |

两组都有 40 步逐 GS 的位置/旋转探针。探针结束后，都把其姿态投影成三层区域运动和局部残差，再继续训练。因此对照同时控制了额外训练预算和初始化方式。

两份 YAML 只差 `experiment_name` 和 `tree_builder`。150 帧的训练相机抽样序列逐帧完全一致，每帧均为 340 步。两组沿用相同稀疏保存格式。

## 结果

PSNR、SSIM 和存储均为动态帧 1–150 的算术均值；MB 使用十进制。必要文件包含运动 NPZ、补点 PLY、帧/删除清单，排除图片、checkpoint、日志和共享首帧。

| 指标 | 空间组 | 聚类组 | 变化 |
|---|---:|---:|---:|
| 留出 PSNR | 34.31290 dB | 34.42460 dB | +0.11170 dB |
| SSIM | 0.970467 | 0.970770 | +0.000304 |
| 必要文件/动态帧 | 0.432959 MB | 0.445560 MB | +2.91% |
| 增量参数/动态帧 | 0.423934 MB | 0.436613 MB | +2.99% |
| 采样渲染 FPS | 198.08 | 197.59 | -0.25%，基本持平 |
| 开启运动的旧 GS 比例 | 4.687% | 4.665% | 基本相同 |
| 最终渲染 GS 数 | 215,055 | 215,051 | 基本相同 |

110/150 帧聚类组 PSNR 更高。收益主要出现在后半段：

| 帧范围 | 聚类组相对空间组 PSNR |
|---|---:|
| 1–49 | -0.01224 dB |
| 50–99 | +0.08053 dB |
| 100–150 | +0.26133 dB |

最大改善为第 120 帧，+0.63478 dB；最大下降为第 21 帧，-0.25156 dB。这是单场景、单 seed 的序列前缀，尚不能判断完整长序列表现或对 S²GS 的胜负。

共享首帧必需 PLY 为 22,360,216 B。将其计入本次 151 帧并摊销后，两组分别为 **0.578173 / 0.590690 MB/帧**。动态增量指标不能直接当成包含首帧的完整序列指标。

### FPS 的口径

从两组已有的帧 5、24、50、100 checkpoint 只读恢复，在同一块 RTX 3090 Ti 上交替计时。每个样本预热 5 次、计时 30 次，共 4 轮，顺序交替。计时为已物化 GS 的 `module.forward`，不含 clamp、质量计算、磁盘读取、运动更新和解码。它是四个样本的渲染速度，不是 150 帧逐帧播放 FPS。

恢复后的 PSNR、SSIM、L1 与原始评测最大差值为 **0**。其他 session 的进程在测速期间保持暂停，只保留约 2,980 MiB CUDA 内存。训练时的在线 FPS 存在 GPU 争用，且计时口径不同，未用来判断两组速度。

## 核心问题一：空间项压过了运动项

在本窗口的 31 个初始/重建帧上，聚类前根层目标中，纯运动误差只占平均 **0.0717%**。空间惩罚约占 **99.93%**。根层总目标平均从 `6.9961e-5` 降至 `1.5634e-5`，但这个下降主要反映空间紧凑性，不能视为运动一致性提升。

再去掉空间项，只比较同一份探针姿态在重新分组前后的共享刚体拟合误差：

| 层级 | 重新分组后的纯运动拟合误差变化 | 重建帧平均归属改变比例 |
|---|---:|---:|
| 根层 | +0.68%，变差 | 48.11% |
| 中层 | +1.23%，变差 | 75.91% |
| 细层 | -0.88%，改善很小 | 89.16% |

这些误差针对当前训练探针，不是物体真实运动标注。目标占比也不等于每次归属决策的贡献。但结合前两层纯运动拟合没有改善，可以判断：**当前参数下没有获得期望的运动分组证据。** 画质收益可能来自空间划分、旋转中心或优化路径变化；缺少“相同新划分流程但去掉运动评分”的独立对照，暂时无法归因。

40 步探针也只提供了部分运动信号。聚类组训练视角 PSNR 从初始化的 34.7552 提升到探针后的 35.0270，再到拟合后的 35.9751。它尚未达到后续拟合的质量；只统计被至少两个训练视角看见，不能保证探针运动本身准确。

## 核心问题二：层级 gate 几乎没有选择深度

两组根层和中层相关区域的 z 全部开启。150 帧累计，细层只关闭了空间组 2 个、聚类组 6 个区域；局部 z 分别只关闭 1 个和 0 个。这说明当前主要在选择“哪些 GS 动”，还没有有效选择“动到哪一层”。

好的一点是，两组 m 关闭行的位置和旋转实际变化数都为 **0**，保持原姿态的约束生效了。

不能把 z 全开直接归因于某一个参数。偏高的初始 z、较短的学门阶段、区域运动对局部残差的接替能力，以及 storage loss 对层级成本的压力，都需要独立验证。

## 为什么存储增加、FPS 持平

聚类组平均少开约 47 个 GS 运动门，但这些运动 GS 涉及更多区域：

| 平均相关区域数 | 空间组 | 聚类组 |
|---|---:|---:|
| 根层 | 371.77 | 448.94 |
| 中层 | 665.49 | 807.57 |
| 细层 | 1,178.23 | 1,351.70 |

每动态帧的区域运动值增加约 **9,425 B**，旋转中心增加约 **4,713 B**，超过局部运动值减少的约 1,129 B，是存储增长的主要来源。两组存储均逐帧审计：实际文件大小与报告一致，参数数组与硬成本一致，NPZ 使用未压缩成员。

最终渲染仍处理约 21.5 万 GS。改归属和少量运动门不会自动减少栅格化工作，因此本轮没有得到 FPS 收益。训练时间不是本轮的主要目标；报告的每帧 wall 为 23.83 / 29.96 s，但聚类组前段存在其他训练争用，不能把全部差值归因于聚类算法。

## 下一步建议

1. **先修建树评分的尺度。** 用探针运动误差的实际尺度平衡空间项和运动项。先检查重新分组能否明显降低纯运动拟合误差，再做长序列。根层仍使用局部候选，保证计算量可控。
2. **加一个空间聚类对照。** 沿用当前重新分组、投影和刷新流程，单独去掉运动评分，区分空间划分收益与运动一致性收益。
3. **单独解决深度选择。** 先在小窗口验证关闭局部层后共享运动能否接替，再调整 z 的学习与成本压力。attribute gate 继续留到后续。

FPS 要另查可见 GS、屏幕覆盖和栅格化耗时。这轮建树实验本身不提供直接提速机制。新超参数尚未选定，没有启动新训练。

### 本地 S²GS 结果的口径差异

另一个 session 确认 `S2GS/output/standard_flame_steak_300/` 为其已有的完整 flame_steak 运行。`avg_metrics.json` 记录 PSNR 34.02 dB、FPS 237.19、Size 0.04 MB、平均 GS 数 59,745；20 个训练视角，cam00 留出。该任务没有保存可供重评测的渲染 PNG。

34.02 所在历史目录的 `cameras.json` 共 321 条记录，宽高全部为 **1345×1008**；文件时间为 2026-09-22 23:18:45，与该目录的配置、训练日志时间相符。当前 S²GS 顺序相机代码直接采用这些相机尺寸，并检查输入张量尺寸一致。这比当前图片尺寸更能说明该次运行的口径。但没有该次运行的源码快照或渲染 PNG，不能仅靠当前源码独立还原历史执行，也不能将该目录等同于作者提到的另一次全分辨率运行。本次恢复测速的实际图像为 **1600×1199**。

纠正此前对 `resolution=-1` 的笼统描述：S²GS 的 PIL 路径会自动缩小宽图，但 `loadSequentialCam` 和 `updateCam` 的预载入 Tensor 路径直接使用张量，绕过该缩放。因此 S²GS 设置 `-1` 时仍可能按 2689×2016 训练。当前 `standard_flame_steak_300/cam00/images/0000.png` 是 1345×1008；本项目 `frames/0000/cam00.png` 链接到 `frame000001/images/cam00.png`，该文件是 2689×2016，经本项目 libgs 加载后为 1600×1199。ReCon-GS 共享首帧目录的 `cameras.json` 记录原始尺寸 2689×2016，相机元数据本身不能证明其经过加载器后的渲染尺寸。`S2GS/output/dynerf` 当前为空；`S2GS/data/dynerf` 是数据软链接。本次核对未修改数据链接或历史产物。

S²GS 的 Size 是模型压缩参数估算，本记录的存储是必要文件实测。其 FPS 是同步单次渲染后逐帧求均值，我们的独占测速为预热后的批次计时。当前不能据此声称 PSNR、存储和 FPS 整体超过 S²GS。后续性能比较需要先确认作者所指的 S²GS 运行，并统一图像分辨率、存储和测速口径。

## 实现与复现信息

代码改动：

- `model/motion_clustering.py`：确定性的加权共享刚体拟合、局部候选归属更新、父子约束和诊断。
- `model/sparse_hierarchical.py`：探针阶段、不同训练相机可见性计数、重建/复用、探针姿态到层级运动的投影、恢复状态。
- `module.py` / `trainer.py`：探针调度、阶段偏移、可见性记录和阶段质量诊断。
- `tests/test_nested_prototype.py`：刚体拟合、嵌套关系、探针冻结、不同相机计数、姿态保持、checkpoint 恢复和配置预算测试。启动前通过 128 项数值检查及 32 项 unittest 检查。
- `scripts/analyze_rigid_tree_pair.py`、`scripts/benchmark_rigid_tree_pair.py`：窗口对照、曲线和配对测速。

配置：

- [空间组](../../config/fs_spatial_probe_p40_300_20261005.yaml) / [聚类组](../../config/fs_rigid_cluster_p40_300_20261005.yaml)。
- [本次只读测速](../../config/rigid_tree_pair_benchmark_150_20261005.yaml)。
