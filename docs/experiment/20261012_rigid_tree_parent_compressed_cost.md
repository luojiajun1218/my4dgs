# 换父节点的实际压缩费用检查

问题是当前换父评分按未压缩的定长残差块和区域 L1 相对运动计算，可能拒绝实际压缩后更小的码流。为核查这一点，只读加载 8192 可动区域完整实验的真实 **frame1 step1200** checkpoint，以其真实 frame0 解码状态为 codec 前态。挑选运动最强的 4 个区域，各检查现有空间邻居中的 8 个换父候选，共 32 个；这是独立的假设候选检查，没有伪造帧索引或触发生产树更新。

32 个候选全部通过与生产代码相同的 pose 误差界，并经过正式 `encode_motion → auto 压缩 → decode_motion` 校验。无出生的基准 motion 流为未压缩 72,874 B、实际压缩 50,715 B（RRL2-lzma）。候选的定长残差支持费用均未变，只新增 3–4 B 换父编辑；实际压缩包则全部增加 **8–80 B**。没有发现“实际包更小、却被旧评分拒绝”的例子。

旧 raw+L1 评分会接受其中 3 个候选，因为相对运动下降足以抵消编辑费用；它们的实际压缩包反而分别增加 **36、68、80 B**。在这 4 个强运动区域上，L1 变化折合的 raw 费用为 −13.45 到 +14.07 B，并非完全被 8192 区域的均值稀释；按当前权重，单节点 L1 下降约 0.0331 才能抵消 4 B 编辑。

本检查只覆盖 frame1 的 32 个候选和无出生的 motion 包。frame1 step1200 不是生产树编辑时点，因此不能据此判断 frame10 的实际换父结果，也不能推断其余区域或完整训练。现有证据不支持“raw 评分挡住更小压缩包”这一猜想，暂不改评分；后续如要改，应再用实际编辑帧验证。
