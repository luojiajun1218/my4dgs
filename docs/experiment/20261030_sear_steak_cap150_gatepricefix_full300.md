# Sear Steak：固定 15k / 150k 参考帧与 gate 码率梯度修复的完整 300 帧

日期：2026-10-30

## 核心想法

本实验把前 30 帧已经通过检查的 Sear Steak 配方原样扩展到完整 300 帧。首帧训练严格固定为 15,000 step；150k 只表示首帧 densification 的 GS 上限，动态阶段允许的 250k 容量不是首帧点数。首帧实际在 densify 后为 151,367 个 GS，透明度过滤后作为共享 reference 的状态为 143,460 个 GS。

动态表示仍是“候选空间层级中的区域共享运动 + 逐点残差”，并使用区域共享 DC、量化和完整更新 50,000B/帧的码率控制。`region_selection_rate_gradient_scale=1/3` 只缩放“选哪个层级”的码率梯度，不改变前向真实字节、控制器观测字节、残差自身的数值梯度或最终码流大小。研究假设是：gate 的选择价格不应被主导码率的逐点残差过早压制，但完整序列总指标不能单独证明自适应层级是收益的唯一原因。

## 与本地 `sota.png` 的关系

本地表格中 S²GS-full 的 Sear Steak 为 34.08dB / 0.962 SSIM、0.11MB、482FPS。本实验完整 300 帧为 34.092761dB / 0.966221，分别高 **0.012761dB** 和约 **0.0042 SSIM**。因此它在当前本地表格数值上略高于 S²GS-full，也满足项目“必须高于 34dB”的底线，但比 34.2dB 理想线低 0.107239dB；0.013dB 的优势很小，不能表述为有充分余量的画质领先。

动态完整更新是 0.049565MB/帧，连同共享 reference 摊销后为 0.090447MB/帧，数值上均低于表中 0.11MB。但论文表格是否包含与这里相同的 reference、manifest 和更新字段尚未核实，所以不能据此宣称存储口径已经严格超过论文 SOTA。

已解码渲染为 393.08FPS，达到项目要求的 ≥200FPS，但仍低于表中的 482FPS。完整播放 FPS 在下节单列，未用渲染 FPS 替代。

## 层级表示诊断

对 8 个已保存 checkpoint 做了只读重编码诊断：固定该帧的总量化逐点运动、survivor 和 birth，只把区域 frontier 换成统一深度，并用各区域坐标中位数作为代表运动。表中是 motion packet 的字节数；“最佳统一深度”只是这一定义下的对照，不是全局最优字节下界，也不是重新训练后的消融。

| 帧 | 学习 frontier | active regions | 最佳统一深度 | 学习值相对差异 |
|---|---:|---:|---:|---:|
| 29 | 40,782B | 201 | 41,350B（depth4） | -568B |
| 59 | 34,838B | 8 | 34,842B（depth1） | -4B |
| 89 | 43,242B | 226 | 43,842B（depth4） | -600B |
| 119 | 42,026B | 15 | 42,014B（depth2） | +12B |
| 149 | 42,182B | 56 | 42,634B（depth4） | -452B |
| 179 | 41,394B | 101 | 42,010B（depth4） | -616B |
| 269 | 40,650B | 8 | 40,642B（depth1/2） | +8B |
| 299 | 43,182B | 87 | 43,770B（depth4） | -588B |

在这一定义明确的表示对照中，学习 frontier 在 6/8 个采样帧更小，另外两帧只差 12B 和 8B；这说明学习结果至少没有被简单统一层级明显支配。它不能证明 gate 训练是全局最优，也不能把完整序列的画质或存储收益因果归到自适应层级。证据为 `/mnt/SSD500GB/my4dgs_diagnostics/sear_cap143_frontier_frame{029,059,089,119,149,179,269,299}_20261030.json`。

另一个优化现象是 frame60–89 中有 16/30 帧只保留 8 个 active regions，其中 12 帧出现 `open_gates>0` 但沿祖先链没有可达 open gate。由于 `spatial_open` bitfield 长度固定、不可达节点也不会进入 stored region support，这不等于存储浪费；它只提示独立 logit 与祖先约束之间可能存在优化不一致，当前没有证据证明其对画质或总字节有因果影响。frame59 的保持总运动重编码也显示粗层 34,838B 已与所有统一深度对照持平或更小，说明至少该帧回粗是合理的 RD 结果。

## 已验证结论、边界与下一步

已验证：固定 15,000-step、150k 点上限的共享首帧与当前动态机制可以在 Sear Steak 完整 300 帧上同时达到平均动态完整更新低于 50kB、PSNR 高于 34dB、已解码渲染高于 200FPS；它也以很小幅度高于本地 `sota.png` 的 S²GS-full 画质数值。码流、checkpoint、CPU/GPU 解码、实际渲染和完整播放均已独立核验。

尚未达到：全序列 34.092761dB 仍低于 34.2dB 理想目标；动态更新也不是严格逐帧低于 50kB，完整播放 54.07FPS 与已解码渲染 393.08FPS 有明显差距。

因果边界：本实验验证的是“150k reference + gate 码率梯度修复 + 区域 DC + 当前 birth/opacity 配方”的整体结果，不能把提升全部归因于自适应层级。8 帧 frontier 重编码只支持当前层级在定义明确的统一深度对照下具有竞争力，不是训练消融或全局最优证明。

下一步优先分析 210–239 的跨视角误差、GS 出生/退出和训练拟合，而不是全局继续加大首帧点数：前半程已经达到约 34.2–34.38dB，主要损失集中在后段。若要改机制，应该针对困难段的长期状态误差或动态训练容量，并继续保持首帧 15k、参考帧点数在 100k–200k 范围内；不应把动态 birth 的 250k 容量误当成首帧上限。

## 独立前30帧资格实验

固定15,000首帧步数，将densification上限由200k改为150k：透明度过滤后分别为187,804和143,460点，cam00首帧PSNR分别为33.497640和34.218506 dB。动态加入 gate 码率选择梯度系数1/3 和区域DC，前向实际字节没有折扣。相对旧200k动态前缀的33.609919 dB / 60.473690 KB，本轮frame1–29为 **34.379620 dB / 45.170310 KB**；含首帧30帧为34.374250 dB，SSIM 0.967336。首帧和动态机制同时变化，不能把整段改善归因于自适应层级或某一项机制。

前缀已解码渲染383.10 FPS，含读包、CPU解码、上传和渲染的完整播放12.25 FPS；CPU连续解码及逐帧重渲染核验通过。运行：`/mnt/SSD500GB/my4dgs_output/goal_n3dv_dynamic_20261030/sear_steak_cap143_gatepricefix_regdc_full30_20261030/20261030T123619_8239cb`，配置为 `config/sear_steak_cap150_gatepricefix_regdc_full30_20261030.yaml`。本文300帧运行从相同15k reference独立训练，**不是**该30帧运行的续接。
