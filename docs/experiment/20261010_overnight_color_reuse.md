# 夜间短对照：颜色复用减少出生，质量仍未改善

这次解决两个问题：每5帧调整树是否造成后段质量下降，以及外观变化是否必须用新增GS表达。已经完成动态帧1–63的两组新训练。两组都使用独立目录和冻结源码，没有修改历史结果或数据链接。

结果是：短对照未显示关闭树调整能提高平均PSNR。用稀疏颜色更新替代颜色候选克隆，存储减少21.5%，质量基本持平。后20帧仍退化，因此颜色复用目前只解决了部分存储问题。

## 方法和代码

两组保持初始3层、根目标96个GS、初始子区域至少12个、拆分每侧至少6个。运动200步、新增100步，storage权重0.002。颜色候选来自5个训练视角的DC梯度，预算为旧GS数量的0.2%。几何候选继续按位置梯度产生，没有200个保留上限。

固定树对照关闭编辑候选和梯度拆分；`direct_transaction.py` 的 `direct_reset_on_noop: false` 同时取消无编辑时的周期优化器重置。这是联合消融，不能单独把差异归因于树编辑或重置。

颜色复用组启用 `birth_appearance_action: color_update`。选中的旧GS只学习DC颜色增量；几何、透明度和其余SH保持冻结。`sparse_color.py` 对颜色增量进行量化感知训练，并用行号、int16增量和zlib封装导出。`module.py` 在新增阶段同时优化这部分颜色和几何新增GS。

`common_contrast.py` 增加v5码流标记；独立解码器先更新旧GS运动，再应用颜色增量，最后拼接新增GS。旧v1–v4读取路径保留。实际存储包含颜色侧流，不只计算运动文件。训练使用压缩前颜色参数成本作为可微代理，实际文件字节另外报告。

## 相同区间的结果

所有均值使用动态帧1–63、测试cam00、1600×1199；训练cam01–20。共享首帧不计入存储。KB使用1000字节。必要存储包含运动头、树编辑、颜色侧流和新增PLY；不含诊断JSON、checkpoint或图像。

![质量和实际存储](assets/20261010_overnight_color_reuse/quality_storage.png)

固定树对照比历史自适应树低0.063 dB，不能依据“每5帧有低点”就认定树调整整体无效。但这次收尾发现，历史300帧配置与64帧固定树配置的逐步相机顺序不同，前者只能作趋势参考，不能凭该差值判定树调整的因果收益。两组新的64帧配置才是相同加载长度的比较。原来的大批编辑仍需要单独检验拆分依据和参数继承。

颜色复用相对固定树克隆对照仅低0.00134 dB，平均新增数量减少52.2%。旧点可以承担一部分外观变化，减少了重复的几何表示。这没有证明火焰已经修好：后20帧的质量仍低，出生位置、运动误差和跨帧累积都可能限制效果。

最终导出平均约0.06秒/帧，已经包含在总时间中。当前主要时间在训练、树布局和评测，不在最终文件写入。不能把这里的训练日志FPS直接作为包含解码的播放FPS。

## 验证和下一步

颜色复用单帧冒烟和完整1–63帧序列均已完成真实CUDA独立解码，六项GS属性与训练checkpoint逐元素完全一致，逐帧状态哈希通过。长序列审计位于颜色复用运行的 `sequential_decode_audit_frame001_063.json`。数值回归、配置检查和原版流测试已通过。

下一轮检验更充分的运动拟合、上一帧运动初始化和无损运动封装。当前结果没有达到作者指定的34.2 dB／50 KB目标，也不能据此声称SOTA。公开ReCon-GS的Flame Steak结果约34.00 dB，比较前仍需对齐数据和评测协议，见[论文原文](https://arxiv.org/html/2509.24325v2)。
