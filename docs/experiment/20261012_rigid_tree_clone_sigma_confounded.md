# 克隆散布 2.0→1.0：受运动阶段漂移影响的诊断

新增 GS 的初始位置散布较大，部分帧新增阶段的测试收益很小。本轮尝试把 `birth.clone_sigma_scale` 从 2.0 降到 1.0，其余设置沿用存储权重 0.02 的第 250–252 帧诊断。

两组三帧均低于 50,000 B。散布 1.0 的新增点数为 376/391/396，散布 2.0 为 354/362/386。这里没有显示值得采用的画质或体积收益，但不能把差值单独归因于散布参数。

## 对照检查发现的限制

两组来自完全相同的第 249 帧最终检查点，旧 GS、区域归属、父节点和初始 RNG 都经过逐字段检查。实际保存的 YAML 仅散布参数、实验名和检查点路径不同；两份冻结源码的全部 135 个 Python 文件 SHA 相同。解码参考 `reference_frame249.npz` 的文件 SHA 也完全相同。

散布参数在活跃代码中只在第 1200 步 `_begin_births()` 调用克隆初始化时读取。可是日志从第 80 步就有小差异，第 720 步树编辑选择也出现差异。第 250 帧第 1200 步检查点中，旧 GS 的位置最大绝对差为 0.165024 世界单位，旋转四元数分量最大绝对差为 0.027133；SH、scale、opacity 逐值一致。该时点两组保存的 CPU/CUDA/Python/NumPy RNG 仍一致，出生候选数却分别为 818 和 811。

这说明新增初始化之前的运动优化已经分叉。训练没有启用确定性算法，CUDA 渲染器反传涉及原子累加；数值非确定性经多步优化、量化近端和离散树选择放大，是有依据的解释，但未被证明为唯一原因。相同输入和随机状态不能保证本训练逐位复现。

严格阶段审计保留了“第 250 帧新增前旧 GS 逐值一致”的检查，CPU 预检因此明确失败，未放宽断言或输出一份假装可归因的阶段对照结果。没有启动失败后的 GPU 阶段审计。

## 改动、检查与后续

没有修改生产模型代码。新 YAML 只调整散布参数；适配检查点只同步这个参数与已说明的诊断帧范围、保存安排、存储权重元数据。候选训练正常完成三帧，正式单帧评测和实际包大小保存在各帧汇总中。两份源码和配置校验通过；配对阶段可比性检查未通过。

本候选暂不采用。若后续需要严格判断新增初始化，应从同一个运动已提交的第 1200 步检查点分叉，只优化新增 200 步，保持候选来源、旧 GS 和运动完全相同；还应估计重复运行的数值波动。本轮没有执行该进一步实验。
