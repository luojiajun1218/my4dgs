# Flame Steak：多视角误差补点与贡献退役

2026-10-24完成短实验。新版已接入正式训练流程；第009帧新增阶段获得约0.1063 dB收益，但第001、010帧候选未通过验收。尚未运行新版完整30帧或300帧，不能据此判断全序列平均画质或存储达标。

## 核心idea与代码改动

让新点先有可信的三维位置和图像颜色，再判断整批增删是否有收益。

1. **从多个视角共同支持的误差位置补点。** 16台拟合相机各提出最多96条高误差像素射线，围绕当前渲染期望深度搜索9个深度；候选至少被3台相机支持，并通过颜色、遮挡和支持比例检查，再做三维去重。位置、SH1颜色和初始尺度由这些图像证据确定，真实初始alpha为0.1。最近的旧GS仅提供编码预测来源及固定旋转，不再按旧GS梯度直接复制或随机split。
2. **出生阶段专门拟合新点。** 保持180＋80＋40：180步运动，80步新点拟合与筛选，第260步提交增删，40步固定点集精修新点。出生后旧位置、透明度、颜色、尺度和旋转全部固定；新点的位置、SH、尺度、透明度可训练，旋转继承来源并固定。每步平均4个视角，出生损失改为MSE，学习率衰减到初值的0.2。最终40步也不再更新旧运动幅值，避免把运动精修损失混入新生收益。
3. **用实际合成贡献排序删除旧点。** 对每个旧点统计 `max_camera sum_pixel(alpha*T)`，取当前帧与上一帧贡献的较大值；优先退役贡献较低者。新点编码来源受到保护，上一帧的新点额外保护一帧。这里的两帧证据是短期保护，不代表永久保留或已解决长期遮挡。
4. **训练集内验收配套增删。** 新点先做量化alpha和尺寸筛选，存活数为K；尝试删除 `ceil(0.9K)`、K、`floor(1.1K)` 个旧点。4台出生验收相机要求平均PSNR增加超过0.005 dB、SSIM下降不超过0.0001，选通过者中PSNR最高的一项；没有通过则新点、旧点删除均撤回。不会只为了满足数量配额而提交一次有害替换。

cam04/08/12/16来自原训练集，出生初始化及属性拟合不用这4台相机；运动阶段仍使用全部20台训练相机。cam00始终只评价，不参与候选、属性优化、删除排序或验收。

代码主要在 [multiview_birth.py](../../pipeline/model/multiview_birth.py)、[birth_retirement.py](../../pipeline/model/birth_retirement.py)、[module.py](../../pipeline/module.py) 和 [trainer.py](../../pipeline/trainer.py)。checkpoint保存策略标识、准入结果和来源行，旧实验恢复仍保持配置检查；旧梯度clone策略保留供历史配置使用。诊断脚本增加同一多视角提案器和PSNR验收，独立诊断不等于完整码流训练。

首帧仍用原 `output/n3dv/flame_steak_1020/frame0.pth`：132,586 GS，加载初剪到128,963 GS。未重训或改写首帧，未恢复共享颜色。运动及旧透明度的storage loss保持3e-5，出生属性目前没有单独的码率正则。

## 同一运动终态上的候选验证

首先加载上一轮恢复出的frame009、step180 checkpoint，固定128,807个旧点，对比上轮误差像素＋单视角渲染深度原型。两者使用同一运动终态，因而下表的增益可以直接比较；它们仍是独立候选诊断，不是正式流程的最终编码成绩。

这个结果同时改变了三维候选、外观初始化和出生拟合目标，不能把全部收益单独归于其中一项。完整原始数值见 [fixed_motion_probe.json](assets/flame_steak_multiview_birth_20261024/fixed_motion_probe.json)。

## 正式180＋80＋40流程

第009帧从已完成的旧方案frame008 checkpoint显式分叉，完整重跑运动、出生、删除及编码。它重新进行了180步运动，因此运动终态与上一节不同；新增收益必须使用同一次运行的180→300差值。普通断点恢复没有放宽策略或配置检查。

随后从新版frame009的step260 checkpoint严格恢复，跑完40步，并连续训练第010帧。另从原生首帧直接启动新版，验证第001帧启动与编码。这两个分支不是一条完整新版前缀，不能将三个测试帧当作连续新版序列求平均。

| 正式测试帧 | 运动180步PSNR | 增删260步PSNR | 最终300步PSNR | 新生净收益/dB | 最终新增/删除 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 001，原生首帧启动 | 34.130470 | 34.130470 | 34.130470 | 0 | 0 / 0 |
| 009，旧frame008边界分叉 | 33.875347 | 33.969139 | 33.981644 | +0.106297 | 947 / 853 |
| 010，承接新版frame009 | 34.336685 | 34.336685 | 34.336685 | 0 | 0 / 0 |

第009帧新增947个、删除853个，净增94个，总数128,901。它没有强制一换一；允许删除区间为853–1041，3个试删数量在验收PSNR显示精度内相同，选了删除较少的853。内部验收PSNR为36.659762→36.717285 dB，SSIM下降约0.00008534，在容差内。新生候选最终没有因低alpha或尺寸被剪掉。

第001帧有939个候选通过alpha/尺寸筛选，但增删后内部验收PSNR为37.151139→37.133017 dB，下降约0.0181 dB；第010帧905个候选也没有低alpha/尺寸淘汰，内部验收PSNR为36.858334→36.831101 dB，下降约0.0272 dB。这两批都撤回，最终新增0、删除0，保留运动拟合结果。这里的失败不是透明度过低导致候选存活率差，而是跨视角净收益不足。

因此，目前能确认第009帧的新增有收益，也能确认新验收防止了另外两帧提交有害替换；不能说新增问题已经普遍解决。候选仍依赖旧渲染深度，且只在已有较高alpha覆盖的位置提出射线，对新露出或缺少可靠深度的位置覆盖有限。跨视角几何和外观拟合可能仍不稳定，这是后续方向，不是由这三个帧证明的唯一原因。
