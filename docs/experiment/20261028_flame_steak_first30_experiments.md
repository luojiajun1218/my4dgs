## 分阶段运动与候选预备

`fs_plan_30` 在 `pipeline/frame_plan.py` 和 `pipeline/model/frame_plan_birth.py` 中分阶段学习共享运动、gate、逐点残差与两批新点，共300步、每步四视角。相同动态帧的历史v19为34.253958 dB / 57.096483 KB；本轮画质相近但更新增至72.725 KB，motion及非零逐点残差增多。151–180步实际归属没有变化；检查发现未选区域无法继续拟合当前总运动。

`fs_ready_30` 在 `spatial_gated_motion.py` 中提前拟合未选候选，并在联合阶段开始时重启gate Adam。候选和gate有梯度，但29个动态帧仍无实际归属变化，码率与前版接近。对frame1/29固定已学运动与候选的离线树搜索未找到更低目标；这不证明整个层级全局最优，也不能仅凭零切换断言gate失效。

运行：`output/flame_steak_1027/fs_plan_30/20261027T235034_32c9ca`、`output/flame_steak_1027/fs_ready_30/20261028T003533_80c33b`。两轮均完成独立码流核验；未做完整序列FPS验收。

## 存活计费与完整字节反馈

`fs_rate_30` 在 `adaptive_birth_storage.py`、`rate_budget.py` 和 `frame_plan.py` 中让存活新点支付属性基础字节，并依据上一帧实际完整字节更新下一帧码率倍率。相对 `fs_ready_30`，动态更新下降18.69%，主要来自运动包与非零残差；两项机制同时变化，不能把收益归给其中一项。前5帧平均82.74 KB，frame14–29为53.10 KB，前缀仍未达到50 KB；困难帧21和27画质退化。

运行：`output/flame_steak_1027/fs_rate_30/20261028T014446_258b12`。续跑保存至frame179后主动停止，完整分析见[180帧记录](20261028_rate_stopped180.md)，不能用30帧趋势代替长序列结果。

## 残差支持与新点透明度

`fs_support_30` 利用训练视角的原生颜色Jacobian误差矩初始化新点位置、尺度和旋转，相关实现为 `residual_support_geometry.py`、误差矩采集和 `frame_plan.py`。相对 `fs_rate_30`，出生包从5.818降至0.743 KB/帧，但动态PSNR降低0.061665 dB，运动包反而增加；29帧仅保留844个新点，低码率也可能意味着过早退出。实际step201单步检查中，概率域透明度更新令500个新点中360个归零；这说明早期梯度风险，并不证明最终画质因果。

`fs_sparse_300` 补齐旧透明度末阶段支持收缩，并将新点透明度改为logit参数化；物理透明度、量化与删除阈值保持不变。动态PSNR仅增0.011751 dB，完整更新从54.929升至62.076 KB，因此在30帧后停止。新点属性包从0.743升至10.058 KB/帧；未校准的logit步长可能让晚出生点没有足够时间退出。后续校准及完整结果见[units 300帧记录](20261028_units_full300.md)。

运行：`output/flame_steak_1027/fs_support_30/20261028T045924_0b7b7d`、`output/flame_steak_1027/fs_sparse_300/20261028T053645_73b35b`。历史比较同时改变了多项参数。

## 首帧压缩及候选空间

`fs_ref150_30` 续训全部首帧属性后按图像影响裁至150,000点；首帧PSNR从33.952248升至34.186138 dB，但全30帧从34.235354降至34.021085 dB。`fs_ref150t_30` 改为保留原候选划分和离群点路由，仍为34.019742 dB；仅恢复旧划分没有恢复动态画质。位置、尺度、透明度和颜色均发生变化，无法单独确定原因。[ref150逐帧数据](assets/20261028_ref150_30.csv)、[三版逐帧比较](assets/20261028_ref150t_30.csv)。

`fs_cov150_30` 保留被选GS的原始属性，依据训练视角的影响分数裁点，并在原有非空最细区域保留有限覆盖，再填满150,000点；复用原候选划分，动态gate和运动重新学习。相对原206,237点units，完整动态更新从56.044345降至46.775172 KB，30帧PSNR只下降0.008186 dB，首帧参考从17.720236降至13.118597 MB。影响分数只是近似代理，不能把结果全部归因于覆盖约束或层级。该候选和原units均曾用cam00参与开发选择，不是独立泛化验证。[逐帧数据](assets/20261028_cov150_30.csv)、[三版比较](assets/20261028_cov150_compare30.csv)。

运行：`output/flame_steak_1028/fs_ref150_30/20261028T114002_7b38b0`、`output/flame_steak_1028/fs_ref150t_30/20261028T123227_47ec31`、`output/flame_steak_1028/fs_cov150_30/20261028T130843_517401`。这些前缀分别完成独立解码和渲染核验；覆盖裁点后从同一首帧独立完成的结果见[完整300帧记录](20261028_cov150_full300.md)。

## 10月27日：gate与逐点残差联合训练

`fs_gate_30` 在71–100步联合训练gate、共享运动和逐点残差，其他阶段保留300步、两训练视角。动态frame1–29为34.288971 dB / 62.168414 KB，同口径v19为34.320483 dB / 57.561414 KB；motion增加约4.665 KB/帧，非零残差行增加约11.7%。frame1和29的gate节点有编辑，但没有GS实际改变归属；只检查了两帧，不能外推到全序列。

代码检查发现两个可能原因：替代分组成本中共享预测detach，逐点残差代价没有直接驱动共享代表；开放逐点残差时还遗漏了v19的Adam动量清理。优化轨迹同时变化，不能把结果全部归因于联合阶段或某条梯度路径。运行：`output/flame_steak_1026/fs_gate_30/20261027T115427_c01e0f`；29帧独立顺序解码，未重新渲染全段或测速。[逐帧图](assets/20261027_gate_joint_full30.png)。

## 10月27日：联合训练与共享运动重分解

`fs_share_30` 修复阶段切换的优化器状态，在80/100步重分配共享运动与逐点残差，保持量化总运动不变，旧点运动包变大则回退。frame1–29的两次独立运行分别为34.2955 dB / 55.997 KB和34.2808 dB / 56.073 KB；v19为34.3205 dB / 57.561 KB。码率略降但画质未同时保持；阶段修正、联合训练和重分解一起改变，不能单项归因。短实验中重分解直接节省的字节很少。
