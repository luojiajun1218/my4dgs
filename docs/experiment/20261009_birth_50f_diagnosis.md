# 前50帧新增GS诊断：留下更多点，修补收益仍很小

本次分析已经完成的动态帧1–50，并对第49帧做只读渲染消融。没有启动训练、更新模型或修改历史产物。这不是完整300帧实验的结论。

核心问题是：取消新增候选的提前硬关闭后，留下的GS是否修补了实际误差？当前结果表明数量增加了，但本帧修补效率仍低。下一步需要检查出生位置，而不能只继续放宽保留数量。

## 已运行的机制与结果

本次来源为 `output/fs_adaptive_tree3_recon_birth_300f/20261009T214532_2ce91f`。配置启用 `birth_retention_mode: periodic_prune`：低透明度候选在周期剪枝前连续参与渲染，结束时保存剩余候选。代码改动位于 `residual_motion.py`，训练统计位于 `module.py`。旧GS属性仍冻结；候选仍主要通过位置梯度克隆生成。

初始3层、最多4层；每帧运动200步、新增100步；新增候选及保留数量无硬上限；storage权重0.002。训练cam01–20，测试cam00，图像1600×1199。共享首帧不计入以下均值。

| 区间 | 测试PSNR | 每帧保留新增GS |
|---|---:|---:|
| 1–10 | 34.3748 dB | 88.0 |
| 11–20 | 34.2187 dB | 110.7 |
| 21–30 | 34.0123 dB | 119.5 |
| 31–40 | 33.8243 dB | 157.7 |
| 41–50 | 33.5461 dB | 178.9 |

与先前提前硬关闭版本共同完成的前15帧相比，平均PSNR仅提高0.00698 dB。第9帧新增数从19增至95，PSNR提高0.09778 dB，不能把这一帧的改善扩展为全段结论。

## 第49帧只读消融

从 `ckpt-49-300.pth` 恢复六个原始GS属性。完整渲染复现记录中的PSNR，保存图像像素误差不超过一个8位灰度级。随后仅改变参与渲染的点集，不重新拟合。

| cam00渲染状态 | PSNR |
|---|---:|
| 完整模型 | 33.30319 dB |
| 移除本帧190个新增点 | 33.29637 dB |
| 移除过去6050个新增点，保留本帧新增 | 32.87003 dB |

本帧新增只提供约0.00682 dB增益。在锅附近矩形 `(700,980)-(940,1150)` 中，增益约0.00393 dB。5个训练探测视角的平均增益也仅约0.00378 dB。矩形包含锅、肉和周围区域，不是火焰分割。

当前删除操作的前后渲染，在检查的cam00与5个训练视角上没有可测指标差异。因此这次没有证据把第49帧的直接画质问题归因于删除。历史新增点整体仍有帮助，也不支持按年龄把它们全部删掉。

## 出生依据的探测与下一步

在第49帧固定的运动后旧GS状态上，只使用全部20个训练视角，比较位置梯度与颜色DC梯度。相同的小GS约束下，位置阈值产生358个候选；颜色梯度选取408个候选，只有30个重合。cam00锅附近矩形内的投影中心分别为3个和10个。中心统计不等于可见贡献，也不是实际171–200步候选的重放。

这支持一个待验证的解释：位置梯度不能完整覆盖外观变化，候选可能没有出现在最需要新颜色的位置。它不证明颜色候选已经改善画质。手和喷火枪的误差在本帧新增之前已经存在，运动与历史表示也仍需检查。

据此已准备 `birth_candidates.py`：只读训练视角的颜色梯度，不更新旧GS；保留几何候选，再补充颜色候选并去重。用户确定额外预算为旧GS的0.2%，使用cam01、05、10、15、20。真实CUDA只读调用保留了旧GS六个属性及CPU/CUDA随机状态。新候选版本尚未训练。

新配置为 [fs_adaptive_tree3_appearance_birth_300f.yaml](../../config/fs_adaptive_tree3_appearance_birth_300f.yaml)。报告新增几何/颜色候选数量、初始化源行号和探测开销；训练仍由用户手动启动。

完整数值、逐帧数据与输入哈希见 [summary.json](assets/20261009_birth_50f_diagnosis/summary.json)。数据继续通过本地软链接访问ReCon-GS与S2GS的标准300帧数据，未复制数据或修改链接目标。
