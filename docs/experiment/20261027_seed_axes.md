# 新增 GS 初始化的局部轴/世界轴不一致

本次已经完成只读几何诊断、修正和 CPU 回归检查。没有启动新训练，也没有将公式检查当作 PSNR 改善证据。

## 问题与修正

`pipeline/adaptive_birth.py` 的初始化注释为 local offsets，实际却执行 `seed_xyz += direction * exp(parent_logscale) * 0.25`。GS 的三个尺度对应旋转后的局部协方差主轴；直接把这三个分量加到世界坐标，生成的候选范围取决于世界轴，旋转后的薄片会在本应很薄的法向上产生很大的偏移。

修正为 `seed_xyz += rotate(parent_quaternion, direction * parent_scale * 0.25)`。保持同一确定性方向、0.25偏移幅度、0.7尺度收缩、候选数量、两个提议视角、全部量化步长及存储代价。随后仍把世界坐标偏移转换为已有的局部可训练参数，继续自由优化全部属性。没有新增传输字段、外部深度或运动旋转码流。

这是初始化坐标系一致性的修正；新 GS 在后续拟合中仍可移出父 GS 范围。新物体也不必位于旧协方差支持内，因此不能仅凭这项数学检查断言新的场景内容会更容易拟合。

## 保存状态中的实际偏移

读取正在进行的 v24 已保存 step70 checkpoint，使用其真实父点位置、旋转、尺度和已安装的 newborn seed。对记录位置做逆旋转，再检查局部位移相对于父尺度的椭球半径。为了避免极薄轴和 float32 相减误差造成误判，分母至少为 `16 * float32_epsilon * max(1, abs(parent_xyz).max())`；所以这里的异常数是保守检查。

“正确公式”只计算初始化位置，不渲染、不训练、不写回 checkpoint。记录位置与旧世界轴公式的 CPU 重建误差均在上述舍入范围内。

| 帧 | 候选 | 原位置超过3σ数 | 正确公式超过3σ数 | 原位置半径p99 | 正确公式半径p99 |
|---|---:|---:|---:|---:|---:|
| 1 | 1000 | 316 | 0 | 4152.90 | 0.3535 |

这说明相当一部分候选的实际起点不符合注释描述的父协方差局部偏移。大半径尤其出现在法向尺度很薄的 GS，不能把它直接等同于测试图像的火焰过高、最终坏点或实际渲染覆盖缺失。

## 验证

新增3项完整 adaptive 初始化测试：旋转父点时偏移同步旋转；旋转后的薄轴保持薄方向的初始位移界限；等价的正负/缩放四元数保持相同几何。前两项在未修正候选源码上明确失败，修正后全部通过；测试还检查绑定 live source 后初始世界位置保持一致。

修正分支 CPU 全套625项：616通过、9项CUDA检查跳过，耗时72.256秒。既有 newborn 量化梯度、共享Adam、空新增、清理、真实码流往返和跨帧恢复检查仍通过。渲染反传内核未因本项修改。

## 可能影响与下一步依据

错误的起点可能使有限230步优化花更多时间修正位置，或者使候选因低透明度被清掉，进而让旧点残差承担更多拟合。这仍是待验证的影响链，尚无整段画质/码率证据。

下一轮全300帧候选合并此前已验证的稳定协方差反传、这项初始化修正和状态等价的 CPU 解码提速。它是一轮修复组合后的完整实验，不能独立归因每项的PSNR或存储收益；当前阶段不额外启动训练消融。v24继续完成，历史输出保持只读。
