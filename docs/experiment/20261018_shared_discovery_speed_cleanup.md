# 共享发现流程的等价性能清理

本轮在完整300帧方案确定后处理重复计算，保持当前方法和训练配方。使用现有共享首帧、RTX 3090 Ti和206237个GS完成局部GPU微基准及数值核对；没有重新训练完整300帧。

## 核心改动

- `pipeline/model/spatial_gated_motion.py`：共享发现阶段不再构建随后被丢弃的全体GS候选残差和逐点路径权重；区域支持直接复用已有直方图，避免重新排序全部GS编号；最终诊断批量读取CPU表，并只计算一次gate概率，避免Python循环逐项等待GPU。
- `pipeline/trainer.py`：每10步统一回传已经detach的诊断标量，相关显式传输由300次/动态帧降为30次。继续按原先顺序在Python中累加均值和EMA，进度显示、阶段图、checkpoint时机以及末尾不足10步的处理保持一致；直接调用`_fit_views`的默认行为保持兼容。
- `tests/test_motion_view_updates.py`：覆盖立即/延后诊断的参数与数值等价、断点续跑、尾部及保存时机。`tests/test_pipeline_package.py`改用作者当前保留的配置文件名。

作者已将配置改名为`config/fs_shared_discovery_depth4_full300.yaml`。核对其module、data、trainer和共享首帧路径，与此前验证方案逐字段一致；本轮没有修改配置、数据和既有输出。

## 实测结果

比较优化前提交`d282223`与当前实现，GPU预热后同步计时，取3批的中位数。下表均为局部函数的CPU墙钟耗时，包含其GPU执行和同步开销：

| 局部工作 | 修改前/ms | 修改后/ms |
| --- | ---: | ---: |
| 共享阶段正则计算，每次 | 3.784 | 2.610 |
| 区域支持统计，每次 | 0.445 | 0.372 |
| 最终区域/gate诊断，每次 | 48.852 | 4.871 |
| 300步诊断标量回传合计 | 7.461 | 1.567 |

共享正则减少约31%的局部耗时，最终诊断约快10倍。它们仅占训练的一部分，不能据此声称整帧训练快10倍，也没有重新测量纯渲染FPS。
