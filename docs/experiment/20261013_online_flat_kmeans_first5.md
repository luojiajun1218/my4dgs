# 在线平面共享运动：Kmeans 前 5 帧

## 本次想法与实现

先自由拟合 GS 独立运动，再根据当前及最多 5 个已经观测的转移重新聚类。frame1 开始，每帧比较新划分与旧划分的完整、可解码、实际压缩 motion 包；通过同一量化误差门槛且更省字节才采用。此次只做身份 root 加平面区域，不建树，不利用未来帧，不改写共享 frame0。

主要代码为 `online_motion_clustering.py`（历史按稳定 GS ID 对齐、Kmeans 等四种候选方法）、`online_flat_motion.py`（重拟合、codec 字节门控）、`online_motion_diagnostics.py`（共享变换与组合后的独立残差），训练器保存逐帧结果。此前 frame1 日志中的 NumPy 布尔值不能直接写 JSON，已在评分来源转换为原生 bool，并用真实四种聚类路径验证完整 JSON 写入。

- 配置：`config/fs_online_flat_kmeans_first5_20261013.yaml`
- 完成目录：`output/fs_online_flat_kmeans_first5_20261013/20261013T182601_401a25`
- 命令：`conda activate ReConGS` 后 `python main.py --config=config/fs_online_flat_kmeans_first5_20261013.yaml`
- 数据：`flame_steak`，resolution=-1，实际配置 5 帧；加载共享首帧 checkpoint，每个动态帧训练 100 motion + 100 birth 步，种子 0。
- 共享首帧保留 206,237 / 214,996 个 GS，reference 文件 16,656,569 B，仅计一次。

四帧候选均通过量化误差检查，但全部因 `complete_packet_not_smaller` 拒绝。门控比较发生在出生阶段之前，故其包大小与上表最终 motion 文件大小不同。raw 归属字节是未压缩分项，最终决策使用整包压缩后的字节，不能直接从压缩总量中扣除 raw 分项。

实际每帧只有区域 0，覆盖 206,400 / 206,592 / 206,818 / 207,048 个 GS，均占全部 GS 的 100%；共享平移 `[0,0,0]`、范数 0，旋转四元数 wxyz=`[1,0,0,0]`、角度 0°。实际归属变化率为 0%，因此此轮质量和存储表现主要是独立运动的结果，不能称为共享运动已经生效。

## 独立残差与原因分析

以下区域 0 残差仅统计有观测的存活 GS；平移单位为场景世界坐标，旋转为组合目标与共享预测后得到的最短角度（rad），不是四元数分量相减。

| 帧 | 平移 mean / p50 / p90 / max | 旋转 mean / p50 / p90 / max rad |
|---|---|---|
| 1 | 0.001213 / 0 / 0.005661 / 0.016871 | 0.000369 / 0 / 0 / 0.015033 |
| 2 | 0.000549 / 0 / 0 / 0.016871 | 0.000151 / 0 / 0 / 0.015033 |
| 3 | 0.000418 / 0 / 0 / 0.016505 | 0.000118 / 0 / 0 / 0.015033 |
| 4 | 0.000361 / 0 / 0 / 0.015033 | 0.000093 / 0 / 0 / 0.015033 |

Kmeans 按完整运动历史分组，但统计上接近不保证当前共享刚体变换能抵消稀疏残差。首帧把 41,110 个点分配给区域，raw 归属成本 161,300 B，而独立残差只减少 4,422 B；随后候选残差反而增加，说明对原本不动/零残差的点引入共享运动后，需要额外抵消项。主要历史模式每帧选到 K=8 上限，加上不同观测模式产生更多小区域，仍没有产生可兑现的整包收益。

后续优先方向是按当前量化后的实际残差收益选择区域成员，并允许只接纳有收益的部分区域，同时保留完整 codec 门控。此记录只分析已完成实验，未据此修改算法，也没有把前 4 个转移当成 SOTA 证明。

## 训练完成后的统一速度测量

使用 `scripts/benchmark_rigid_residual_tree.py` 的 decoded stream，在所有训练结束后独占 RTX 3090 Ti，1600×1199 的 cam00，启用冻结 GS 属性缓存；缓存与不缓存图像完全一致，动态帧 PSNR 与训练保存值逐帧一致。sequence 每帧预热 10 次、计时 50 次，CUDA 前后同步，仅统计完整 `Module.forward(...).clamp(0,1)`，不含解码、上传、加载和质量评估。

- 动态帧 1–4 纯渲染：**201.924 FPS**，最低单帧 200.837 FPS；含 frame0 的 0–4 聚合 201.889 FPS。
- 额外 frame4 物化渲染，30 次 × 3 轮：200.646 FPS。
- 从共享参考依次播放动态帧 1–4，共 2 轮，包含本地 motion/birth 读取、CPU 校验解码、上传及完整渲染：**4.189 FPS**。平均文件读取/解码 230.70 ms/帧，上传+渲染约 8.05 ms，解码占计时约 96.63%；不含一次性 reference 加载、相机/GT 加载、manifest 预检查和质量评估，文件预读可能受 OS 缓存帮助。
- 新测得共享 frame0 PSNR=34.011318 dB，含 frame0 的 5 帧平均为 **34.24015 dB**；上文 34.29735 dB 仍是动态帧 1–4 平均。

报告：`output/online_flat_first5_benchmarks_20261013/kmeans_sequence.json`、`kmeans_frame4_playback.json`；精确命令和 exit=0 记录见同目录 `benchmark_commands.json`。约 202 FPS 仅是这 5 帧的缓存物化渲染速度，不能称端到端解码播放速度或全 300 帧速度。
