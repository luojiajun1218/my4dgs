# 第二轮代码冗余清理与等价核查

本轮目的为去掉重复分配、拷贝及计算，保持现有训练目标和码流语义。基于 `8d54c4f`，没有增加新的方法或训练配方；本轮不以短训练改写正式 300 帧 PSNR、存储、FPS 指标。

## 清理内容

- `pipeline/model/rigid_residual_tree.py`：`steps`、`gs_steps` 原先每次访问都创建一个 GPU 小张量，改为复用固定量化网格。配置、场景尺度、设备、类型改变或外部修改网格时重建；缓存不进入 checkpoint，也不会将推理张量带入训练图。
- `pipeline/model/birth_quantization.py`、`pipeline/module.py`：新增点的预测器只需少量源点，原先却先复制全部旧 GS 属性。允许 `model_raw(..., clone=False)` 提供临时只读视图，随后通过高级索引生成独立的源点副本。默认快照仍持有独立数据。帧结束时也省掉一次紧接着被再次复制的中间快照。
- `pipeline/model/spatial_gated_motion.py`：存储损失共用相同的连续残差和元数据字节数，移除重复表达式及重复计数。
- `pipeline/module.py`：合并新增阶段的重复 Adam 更新代码，保留中间步骤先增密再更新、末步先更新再删除的顺序。

## 完成的等价检查

全套 **365 项检查通过**，包含新增的缓存失效、推理后训练、数据所有权、预测器寿命、梯度一致性及新增末步执行顺序检查，也包括原有 CUDA 检查。

另将 Git 基线的 `loss_terms` 提取出来，在同一恢复状态上分别运行新旧函数。覆盖 6 类已有模式的 gate 冻结前后，共 **12 组**，包括共享运动重编码、相对区域、实际码流成本、软 gate 和层级私有残差；损失及参数梯度的最大绝对差均为 **0**。

真实 CUDA 核查加载正式版第 29 帧的 223374 个 GS，构造 256 个验证新增点。在相同源点和属性上，新旧路径的量化符号、6 类原始属性位模式、最终物化属性、逐点梯度及渲染像素均完全一致。源点被选出后拥有独立存储，后续原模型更新不会修改已构造的预测器。

## 局部性能测量

RTX 3090 Ti，同一场景，独占检查通过。每条路径预热后交替测试 5 轮，使用 GPU 同步后的墙钟中位数；每轮量化网格读取 2000 次、新增视图构造 40 次。

| 操作 | 原实现 | 清理后 |
| --- | ---: | ---: |
| 读取一对区域/GS 量化网格 | 29.657 微秒 | 3.330 微秒 |
| 构造新增点视图 | 555.392 微秒 | 487.694 微秒 |
| 构造视图的额外分配峰值 | 20.630 MB | 0.077 MB |

网格读取在此局部测试中约快 8.9 倍，新增视图构造耗时少约 12.2%。原实现重复复制的旧属性共 20.550408 MB；清理后主要只为选中的新增点分配缓冲。MB=1000000B。

这些是**局部操作的测试**，不是每帧训练提速、整机显存下降或新的完整序列画质结论。每帧仍是原 200 步运动和 100 步新增，正式配置和结果继续保留。没有进行新的完整训练。
