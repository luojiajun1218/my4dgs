# 8192 共享运动区域：完整 300 帧验证

本轮完整训练并重新解码了 flame_steak 的 300 帧。存储满足要求，画质和渲染速度仍未达标：全序列 PSNR 33.4712，完整渲染 198.90 FPS，动态增量平均 26.73 KB、最大 46.99 KB。不能用前段超过 200 FPS 的结果代表全序列。

## 方法与配置

沿用单一运动模型：每个 GS 硬归属一个区域，区域共享层级刚体运动，区域和 GS 各有量化平移、旋转残差。没有 gate 或混合权重。每 10 帧调整 GS 归属与区域父节点，不做区域分裂、合并。新增 GS 继承实际来源 GS 的区域，新增阶段冻结旧 GS 属性和运动。

本轮使用 8192 个运动区域和一个静止根。每帧运动优化 1200 步，前 600 步只拟合共享运动，新增阶段 200 步。存储权重 0.03，区域相对运动 L1 权重 0.006，学习率保持常数。首帧 opacity 筛选阈值 0.0075。其余参数完整保存在 YAML；这是此前短片段候选的完整验证，不能把收益单独归因于区域数量。

训练冻结源码提交为 `057ac3c9d47ad66ef5988235d3fad245d04d8c6e`。训练完成后，用 `a4fc7510eace122875f43cc36b38e39a22d9138d` 的稀疏行号差分编码器无损重打包。这里只改行号表示和压缩封装，不改变量化符号、树、出生属性或画质，也没有把新代码的树候选计费用于这次训练。

## 评测与检查

在 RTX 3090 Ti 上使用 cam00、1600×1199 图像。每帧顺序解码并验证 manifest，然后预热 10 次，计时 50 次完整 `Module.forward(cam00)['render'].clamp(0,1)`，计时前后 CUDA 同步。FPS 按总渲染次数除以总秒数计算；解码、上传、读图、预热和质量检查不计入用户要求的解码后渲染 FPS。

共测 300 帧、15,000 次完整渲染。训练已正常退出，未与评测并行。每帧缓存和非缓存渲染像素完全一致，重解码评测与保存的动态帧 PSNR 差值均为 0。

速度环境有明确限制：NVML 因驱动/库版本不匹配不可用，评测退回 `/proc` 设备句柄检查；未观察到其他可检查的计算进程，但部分进程 FD 表无权限读取，桌面图形进程也仍存在。因此不能声称 GPU 独占状态得到完整证明。没有更改系统驱动或关闭用户进程。

训练前完整数值测试 303 项、单元测试 55 项通过。差分编码改动另通过 CPU 数值测试 304 项、单元测试 58 项（跳过 1 项）及压缩相关测试 13 项。自动收尾在校验全部 299 个动态帧后运行重打包和全序列 benchmark，正常退出。

## 分析与下一步

与同数据、同 cam00、同分辨率的原生 ReCon-GS 保存评测逐帧对齐，动态帧原生均值 33.94223，本轮低 0.47284 dB；299 帧中有 288 帧更低。第 51–100 帧差距较大，平均低 0.70164 dB。第 168–172 帧是双方共同的困难时段，不能把本轮绝对低点直接解释为树更新故障。原生运行允许的属性优化与本法不同，因此这是质量参照，不是单变量消融；未比较原生 FPS。

GS 数持续增加与后段速度下降同时出现，但尚未用剖析证明因果。画质距约 34.20 仍有约 0.73 dB，速度也略低于 200，不能宣称整体达标。存储有余量，下一步先评测已保存检查点在运动结束和新增结束时的同视角画质，再决定是否降低运动存储约束；候选参数尚未作为有效改进确认。
