# Coffee：区域与逐点全属性更新，200 步

## 想法与实现

在上一版 200 步全点颜色更新基础上，101–200 步同时开放共享区域和逐点的位置、旋转、尺度、SH 颜色及透明度更新，测试共享全属性的画质与存储。前 100 步保持已有运动与 gate 调度，旋转参数在第 101 步开始训练；每步一个随机训练相机，不做显式选点、梯度探测或增点。使用相同的 160,000 点共享首帧和 depth-5 候选层级，frame 1–30 为 30 个动态帧。cam00 用作测试，已参与开发选型，并非独立最终测试视角。

区域与逐点位置、旋转复用现有运动优化和运动码流；新增区域尺度、DC、方向 SH 和透明度量化残差使用 `RFA1` 码流，逐点尺度及 SH 沿用 `FUA`，逐点透明度沿用 `OVX`。区域属性在逐点属性之后组合；区域透明度为 logit 增量，逐点透明度为 alpha 增量。区域所有权随运动 gate 的当前硬切分变化；属性误差和新增属性码率没有直接反传给 gate，因此 gate 的优化仍主要由现有运动机制驱动。本次实现是共享属性随运动层级分配，并非已验证的按全属性成本选择层级。

固定运动码率权重 `0.008` 保持不变，区域和逐点旋转计入运动码率。尺度和 SH 的区域与逐点块使用固定倍率 `4.0`；区域透明度按基础倍率 `1.0` 计价，逐点透明度沿用原有约束。区域属性的 L1 在占用节点上归一化，尺度与 SH 权重为 `0.005`，透明度权重为 `0.05`；固定块价格按未压缩行大小估计，逐帧另计真实压缩码流。块稀疏近端筛除在第 120、140、160、180、200 步执行；这些是固定惩罚，不使用反馈目标。真实包额外包含头部和压缩效应，不能将训练代理费用当成实际字节。

新增 `regional_full_200` 实验配置、区域全属性编码及解码；默认关闭，不改变现有默认稀疏路径。配置 `config/coffee_regional_point_full_200step_30dynamic_20261109.yaml`；输出 `output/experiments/coffee_regional_point_full_200step_30dynamic_20261109/20261109T113543_1fa403`。

逐点 logscale 平均 6,703 点非零，DC 平均 2,292 点，方向 SH 平均 16 点；运动码流中的逐点旋转平均 153 个非零块。将现有逐点属性包分别以单一字段重新编码，尺度约 17.57 KB/帧、DC 约 7.95 KB/帧、方向 SH 约 0.20 KB/帧；独立编码各含头部且压缩上下文不同，不严格等于联合包的逐字段字节。单点尺度更新是属性开销的主要来源。

区域尺度、DC、方向 SH 平均分别有 25.9、34.1、12.1 个区域非零；区域透明度仅 5/30 帧有一个区域非零，其余帧为零。区域透明度已开放训练但基本被当前优化与存储惩罚压掉；这些数据不能单独区分惩罚过强和区域透明度本身需求较小。区域属性包平均 0.315 KB/帧，空间节省不代表可以归因于共享设计，区域属性的画质贡献仍需受控验证。

## 核验

所有对照共享首帧数组一致。30 个 manifest 均记录每帧 200 次优化、100 次区域和全点属性优化、零探测和零增点；每帧记录 200 次单视角训练采样。第 101 步逐点尺度、区域与逐点旋转均有梯度；训练前向与解码图像逐帧最大差为零。区域属性实际数据包均计入动态存储。

从首帧独立顺序解码至 frame 30，逐帧状态摘要核对通过，末状态 SHA256 `defb6714bcf01e5344a03a60250040297f758d6d3b78b4dbf155e00e7efb240b`。属性码流、梯度、checkpoint、既有帧计划、属性及 pipeline 相关共 122 项检查通过。本次未测渲染或完整播放 FPS。
