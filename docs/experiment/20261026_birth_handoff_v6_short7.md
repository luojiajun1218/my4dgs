# 源点移交：让新点直接承接可见性，控制点数增长

完成日期：2026-10-26。实验从前一晚开始，首帧加6个动态帧，已训练完成并独立解码核验；仍未达到300帧目标。

## 核心想法

普通克隆与旧源点叠加，部分新点被高透明度源点遮挡。第四轮选中源点约40.2%的透明度超过0.9。这里改为“源点移交”：完整复制源点属性作为新点初始化，将对应旧点透明度钉为零，再充分训练新点。其他旧点的颜色、形状等属性不改。旧源行暂时保留，作为本帧码流预测器，下帧按已有低透明度规则退休。

这样既提供新点的直接图像梯度，也避免复制点不断累积。它是选择性替换，不是额外增加全部新点。

## 代码与配置

`pipeline/module.py`增加`birth.source_handoff`、源索引checkpoint状态与旧透明度钉零逻辑。旧alpha参考不是量化网格整数，因此用`-ceil(alpha_reference/step)*step`确保解码目标夹到精确零；只取整负alpha可能留下正残余。初始化先复制六组原始属性，再关旧点。新点极端opacity logits截到±9.21024，使饱和处仍有梯度，alpha扰动上限约1e-4。

`pipeline/trainer.py`记录完整的`handoff_initialization`和`handoff_final`画面。不能将故意删掉源可见性的old-only图当作收益基线。阶段增益也包含联合旧点透明度拟合，不是单独的新点消融结果。

每帧上限1000个替换点，其中320个额度来自跨训练视角一致的颜色梯度，外观源尺度上限0.05×extent；其余按原位置梯度选择。源点足迹初始化后不做额外分裂或大尺度剔除，透明度仍可训练。200步运动+600步新增、每新增步3训练视角；新点方向沿用源方向。旧透明度L1恢复0.05，保留末段学习率衰减和一个运动网格的最小位置余量。gate机制未改。

固定输入仍为132586 GS首帧checkpoint，初筛后128963 GS参考；1345×1008半分辨率监督，数据通过已有链接访问。

所有7帧重解码并核对质量、哈希。KB为十进制，共享首帧单独计费。FPS只计完整解码后的同步渲染+clamp，每帧10次预热后计时50次，不含预热、解码、上传、加载或质量指标。

初始化检查：非opacity源属性逐位相同；选中旧点logits为-100，量化alpha精确为零。将量化新点属性还原到源行的等价场景，与移交场景的最大/平均像素差均为0。该比较使用相同的量化新点opacity，并非对未截断的原始饱和opacity作逐位等价声明。

## 分析与下一步

点数没有累积膨胀，替换机制和码流可正确工作，短序列画质有所提高，但仍差34.2dB目标，1000点预算也使存储超标。第1帧初始化33.6313→34.0860dB，不能只凭这帧认定整体达标。

下一步用30帧检查累积趋势，刷新预算降至700，外观额度240，并允许新点调整方向。目的是在接近50KB的预算内验证足够的局部拟合，而不是直接放大到300帧。方向更新和预算改变后的效果需重新实测。
