29个动态帧平均日志PSNR为34.26929 dB，平均每帧29.4696秒。对比先前同旧首帧但因15万上限未保留候选的29帧34.25772 dB，平均增加0.01157 dB。两次训练轨迹、步数和新增/删除均不同，这不是隔离的新增消融。原baseline文件夹已无对应结果，本次比较使用此前保存的`tmp/oldref30_diagnosis_20261026/frames.json`及`analysis.json`。

低于34.2的动态帧为1、2、4、16、21、27、29。火焰帧16/21/24/27分别变化+0.094/+0.262/+0.160/+0.179 dB，其他帧有退化，整体平均收益较小。没有完整300帧或FPS测量。

固定锅内ROI(x590..729,y840..959，占1.239%图像)的8bit PNG均方误差相对旧运行在16/21/24/27降低36.6%/53.1%/39.7%/34.5%。ROI包含牛排及锅面，不是火焰分割。该指标是测试视角事后诊断，未用于训练。渲染仍有明显火焰欠亮/缺失，因此尚不能说质量问题全部解决。

## 新点为何累积

首帧有效206237点，第1动态帧降至204053，第29帧208559，较首帧净增2322(+1.13%)；从第1动态帧起净增4506。第10..29帧平均保留新点321.9、删除旧点128.25，平均净增193.65/帧。短段趋势不能直接线性预测300帧，但持续正增长需要控制。

每帧均提出1000候选，说明当前自适应主要体现在各空间组之间分配，总需求一直超过上限，实际总数没有随帧收缩。候选29,000个中，19,550个出生帧即被低alpha清除，保留9450个；后续又删除其中542个，最终8908个仍在。最终初始点199651个，初始点累计删除6586，二者之和与总数208559一致。新点总体存活率94.3%包含不同年龄，不能直接当固定时长存活率；第1帧397个新点到29帧仍保留369个，也说明较老新点保留很多。

删除机制确实执行；不是整个删除函数失效。真实逐帧解码检查表明，当帧新点引用的低alpha父点只有0..3个，不是点数增长的主因。最终alpha<.01共41点，其中新点5点；因此只追加一次同阈值全局扫描不会消除数千点。

代码因素：

- 当前birth.alpha_sparsity_weight=0；已有旧运动/旧透明度约束不等于新点属性存储约束。新点全属性offset经过量化，但没有直接的新点码率/支持稀疏损失。
- 无筛选版已移除按target_frame_bytes=50000准入的分支，该配置仍出现在resolved配置，但在当前路径不是硬约束或自动预算。
- alpha阈值只删除接近透明的点，不能识别多个有一定alpha但表达重复的GS。
- 残差阈值与90%组内残差覆盖的需求较高，全部帧打满1000候选，可能持续拟合旧背景残差，尚未证明候选都位于新内容处。

## 建议推进顺序

保留当前低开销、不做多视角筛选的训练流程。优先给新增分支补轻量训练期存储压力：新点alpha/存活稀疏项，以及相对父属性offset的量化符号代价；不能声称量化本身已经等价于storage loss。权重需观察图像损失与梯度尺度，不应简单沿用按20万旧点归一化后几乎无效的强度。

再让总候选预算对有效残差和近期净增长响应，而不仅在固定1000点间重新分配。先避免长时间净增长，不宜用强制每帧新增数等于删除数的方法，因为新物体确实需要容量。若仍有长期冗余，再检查低贡献新点的生命周期；目前没有依据直接提高全场alpha删除阈值或删除所有老新点。

不要重新引入逐组多次质量渲染/码率筛选。新方法首先应保持火焰帧收益，并检查其余帧的退化，不能只以点数和平均存储为优化目标。
