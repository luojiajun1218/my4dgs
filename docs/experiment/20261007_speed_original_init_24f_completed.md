# 原共享首帧的节点/缓存速度版：24帧完成记录

本轮保留原共享首帧和所有训练参数，仅开启已有执行优化。训练时间缩短54.2%，独立渲染FPS提高1.68%。PSNR低0.0237 dB、文件多0.35%，接近原结果，但未严格满足原PSNR和文件上限。

## 四项结果

动态帧1–24均在1600×1199训练和cam00评测，seed=0。

| 指标 | 原结果 | 本轮 | 变化 |
|---|---:|---:|---:|
| 平均PSNR | 34.273313 dB | 34.249659 dB | −0.023654 dB |
| 必要动态文件/帧 | 49,942.71 B | 50,115.25 B | +172.54 B / +0.35% |
| 独立前向+clamp FPS | 202.89 | 206.31 | +1.68% |
| 含准备与收尾训练/帧 | 37.1525 s | 17.0226 s | −54.18% |

SSIM为0.972505，原为0.972447；纯训练14.9424 s/帧，wall为19.7685 s/帧。必要文件包含运动流和补点PLY，计入头部，不包含共享首帧和诊断文件。

FPS独立恢复第5/10/24帧，3090Ti独占，同样10次预热、100次计时、5轮。纯光栅化208.99 FPS，原为208.54 FPS，基本接近；前向总耗时减少与属性准备缓存相一致。FPS不含加载、指标计算、码流解码及训练。

## 方法与参数

[配置](../../config/fs_storage_aware_speed_original_init_24f_20261006.yaml)直接使用原baseline：旧15000步首帧、214,996 GS，原300步调度、树96/12/4、storage=0.01及所有学习率、精度、相机和诊断设置保持原值。

仅开启五项已有优化：节点空间合成、静态layout缓存、固定阶段选定精度、补点阶段冻结运动成本、渲染属性缓存。原参考实现仍可选。联合阶段保留关闭分支的STE梯度，零路径精确保留原始XYZ和四元数；渲染缓存对有梯度及inference-mode读取自动绕过，并按源对象与版本失效。

节点合成避免逐层对全部GS和后代旋转中心重复变换，量化和成本缓存也减少重复计算，因此训练提速明显。最终渲染已经使用展开后的GS，节点优化不会直接改变光栅化工作量，这与仅小幅FPS提升相符。

训练后的运动和精度选择略有变化，非零运动记录和实际码流稍多。浮点算术顺序和CUDA训练波动都可能改变优化轨迹；本轮没有单独区分原因。因此不能声称完全保持了原数值结果，也不将PSNR差异当作新方法收益。

- 24帧顺序解码状态摘要全部匹配；第5/10/24帧checkpoint六类原始属性逐元素精确一致。硬成本与实际文件逐帧相同，树重建为1/6/11/16/21。
- 正式运行：`output/fs_storage_aware_speed_original_init_24f_20261006/20261006T235034_e8c2b3/`。汇总和FPS在`analysis_completed/`，顺序证据在`audit/sequential_001_024.json`。
- 源码冻结在同实验base的`source_snapshot/`，102个文件哈希核查无变化。冻结配置与工作区配置的模型/训练项一致，数据相对或绝对路径均解析到同一既有软链接目标。

这轮得到的明确收益是训练时间；渲染FPS收益较小。严格画质与文件条件仍留有小差距，保留原结果作为质量基线，后续只根据这四项结果决定是否进行一次算术顺序保留的修正。
