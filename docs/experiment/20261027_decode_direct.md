# 稀疏运动解码：复用已解析符号

本次已完成整段只读解码诊断，没有启动新的训练。它继承 `20261027_decode_fast.md` 的批量整数解析，继续处理 profile 中仍存在的重复 Python 解析。

## 想法与改动

当前 planar 码流先恢复原始交错字节并验证原校验和，随后 raw 解码器再次逐行读取同一组稀疏运动。本次在 `sparse_integer_codec.py` 中保留第一遍已解析的稀疏行和 int16 符号；`rigid_tree_codec.py` 验证完整原始校验和和前帧状态后复用这些符号，仍按原顺序执行相同 float32 运动组合。

保留的数据仅随本次函数调用传递，不是跨帧的隐式缓存。旧 raw/zlib/XZ 格式仍走原解码分支。量化、压缩选择、传输格式和前帧 SHA 检查不变。稀疏行的越界、标志、冗余零块以及帧末尾检查保留；在与前帧状态核对人口数量前不按不可信 header 分配稠密数组。

## 完成的验证与结果

只读使用既有 v21 完整300帧，从 frame0 开始独立顺序解码299个动态帧。与当前冻结主分支解码器轮换先后执行，两者均隐藏 GPU。全部状态哈希、六类 raw 属性哈希和 GS 数量相同，并分别符合原运行 manifest；历史结果没有修改。

| CPU 指标 | 冻结主分支 | 本次优化 |
|---|---:|---:|
| 299 次读包、检查、解码及材质化 | 136.863611 s | 36.427067 s |
| 每帧平均 | 457.738 ms | 121.830 ms |
| 顺序解码吞吐 | 2.185 帧/s | 8.208 帧/s |
| 另加 manifest/raw 核验的累计耗时 | 143.175545 s | 42.770619 s |

本轮配对计时约快 **3.757 倍**。这不能与上一条记录的两个独立运行直接相减，声称严格的额外百分比收益。两次诊断期间 v24 训练仍在运行，CPU/GPU负载并非独立基准环境。

`test_sparse_bulk.py` 的9项测试通过（含4项针对本次路径的新增检查）；相关 codec 测试共68项，66项通过、2项因无CUDA跳过。重点覆盖了复用路径与原始逐行解析一致、reader游标与trailer、原始checksum先于运动组合验证、零块不能绕过检查、声明巨大人口的空数据不提前分配稠密数组。

## 分析与限制

第一轮批量解析后，剩下的大量 `_sparse_read` Python 调用来自重复消费已解析的数据，本次直接复用消除了这部分调用。只读 profile 的 frame200 三次解码从0.802秒降到0.504秒；profile自带开销，不作为播放FPS。

本次实际 CPU 顺序解码仍约 **8.21 帧/s**，远未达到含解码的200FPS。它不提高画质，也不减少传输字节。完整GPU上传和逐帧渲染尚未在本次诊断中计时；训练完成后使用既有播放器对299次动态更新单独测量。
