# 该动的地方动，不该动的地方不动

算法与代码改造思路 · 2026-09-29

**当前状态：用户已完成首轮 20 个后续帧，画质低于 ReCon-GS。** 诊断显示运动区域过少、粗区域共享运动常被规则禁用；具体指标和下一步建议见 [20 帧结果分析](selective_motion_21_diagnosis.md)。新模式通过 YAML 中的 `motion_mode: selective` 开启，训练由用户手动启动。

想核对代码现在究竟怎样判断，直接看 [当前判断规则](selective_motion_current_rules.md)。UNKNOWN 是图像证据不足的标记，动作仍然只有 KEEP / SHARED / SPLIT。

针对硬规则过多的问题，已新增 `learned_selective` 模式，见 [让模型学会什么时候细分](learnable_motion_selection.md)：通过训练选择 KEEP / SHARED / SPLIT，无观测时默认 SHARED。代码尚未运行验证；下文保留原规则版的设计记录。

## 1. 我们想让它做到什么

想象画面里有一面墙，一个正在移动的人，以及他身上摆动的衣服。

- **墙没有变化：** 沿用上一帧的位置和朝向。
- **人的某一部分整体移动：** 用一份平移和旋转，让这片区域一起动。
- **衣服的不同部分动得不一样：** 把区域划小，分别处理这些运动。

我们希望算法自己选出合适的区域大小：**一份运动够用，就让大家共用；局部确实需要不同运动，再划分小区域。**

墙面依然可以由很多 GS 表示，保留原来的纹理和几何细节。这些 GS 可以一起保持不动。衣服上花纹很多，也不代表一定要细分运动；需要关注的是衣服是否发生了局部形变。

这一版先把“是否动、怎样一起动”做好。bitrate loss 和 attribute gate 放在后续考虑。

## 2. 用三种状态管理区域

| 状态 | 通俗解释 | 例子 |
| --- | --- | --- |
| `KEEP` | 这块区域沿用上一帧的位置和朝向 | 静止的墙面、地面 |
| `SHARED` | 这块区域共用一份平移和旋转 | 整体移动或转动的物体 |
| `SPLIT` | 大区域内部动得不同，交给小区域分别处理 | 摆动的衣服、局部褶皱 |

“分层”就是大区域包含小区域，小区域还可以继续划分。最终，一面墙可以停在很粗的层级，衣服的局部可以用更细的层级。

**第一版中，每个 GS 只跟随一份最终选中的运动。** 大区域选择 `SPLIT` 后，由小区域接管运动计算。划分区域时，是把原有 GS 分组管理。

如果某块区域被遮住、没有看清，就记录为“暂时不知道”。可以先沿用旧位置，等重新看见后再判断。

## 3. 原来的实现缺少什么

最需要解决的是三件事。

**第一，背景缺少明确的 KEEP。** 当前最粗的 L1 一直参与运动训练。即使细层关闭了，墙面也可能被粗层带着移动。需要让 `KEEP` 区域真正保留原来的位置和朝向。

**第二，粗层的旋转还不完整。** 现在旋转参数会改变 GS 椭球的朝向，但没有让这些 GS 的中心一起绕区域中心旋转。比如一个物体整体转身，粗层就可能表达不好，被迫用很多细层来补。

改造后，一块区域的旋转应像转动一块木板：木板上的点一起绕中心转，每个点的朝向也跟着转。

**第三，细层是否开启主要由排名决定。** 现在固定挑选一定比例的父区域；没被选中的区域，其内部细运动也失去了机会。我们需要判断的是：这个区域用当前的运动方式，是否已经足够准确。

梯度异质性可以继续帮助寻找值得检查的区域，但最终要看“不动、一起动、分开动”各自能否解释画面变化。

## 4. 建议每一帧按这个顺序处理

### 第一步：留住上一帧，看看哪里出现了新变化

把上一帧的模型作为参考。后面的尝试先在临时结果上进行，选好方案后再更新正式模型。

当前 flame_steak 数据的相机位置和参数在各帧保持一致，可以比较同一相机前后两帧的图像，并结合多个视角判断哪里可能变了。

这里有一个很重要的区别：**墙面上一帧就没拟合好的误差，不能直接当成这一帧墙面移动的证据。** 如果前后图像里的墙没有变，就要检查高误差是不是旧问题。

阴影、曝光变化和遮挡也会让图像变化，所以图像差分只用来找线索，还要检查运动方案能否在多个视角下合理解释这些变化。

### 第二步：在可能变化的区域，短时间试一试小区域的运动

先用数量有限的小区域试着拟合运动，看看哪些部分动得一致，哪些部分动得不同。这一步叫“细运动探测”。

这样做是为了给局部运动一个被发现的机会。例如左右两块分别向左、向右移动，大区域的平均位移可能接近零，但内部仍然需要运动。

探测结果是待选择的方案，只有最后被接受的运动才写入正式模型。探测也要占用训练预算，具体用多少步需要实验决定。

### 第三步：试着把小区域合成大区域

有了小区域的运动之后，从小到大检查：

- 整片区域保持原样，画面是否已经足够准确？可以就选 `KEEP`。
- 整片区域一起平移、旋转，是否已经足够准确？可以就选 `SHARED`。
- 只有分开运动，画面才能明显更准确？就保留 `SPLIT`。

三个方案使用相同的视角和图像范围来比较。**在画面质量相差不超过允许范围的方案中，选择运动参数更少的那个。** 这个“允许范围”要通过实验确定。

例如，衣袖的几个小区域虽然分别学了运动，但最后都差不多向右移动，就可以合成一个共享运动区域。若袖口还在单独摆动，就保留袖口的小区域。

### 第四步：训练选中的运动，再更新模型

剩余训练时间用于选中的运动参数。`KEEP` 区域的位置和朝向直接沿用旧值，旧的优化器动量也不能继续推动它。

最后再检查一次画面质量，以及应该保持不动的区域是否真的保持原样。

### 第五步：下一帧重新检查

上一帧静止的区域，这一帧可能开始运动；一直运动的区域，也可能停下。三种状态应当能够随观测变化切换。

已有运动可以帮助下一帧开始训练，但不能因此默认物体会一直按原方向移动。

## 5. 怎样知道它真的做对了

先用运动已知的简单例子检查，再看真实场景。

| 检查情形 | 希望看到的结果 |
| --- | --- |
| 整个场景静止，模型还留有少量拟合误差 | 静止区域的位置和朝向保持原样 |
| 一整块区域共同平移 | 一份粗粒度运动就够 |
| 一整块区域共同旋转 | 点的位置和朝向一起转，一份粗粒度运动就够 |
| 两个小区域反向运动，平均位移为零 | 两边的运动仍能被发现 |
| 墙面旁边的衣服发生局部形变 | 墙面保持不动，细运动集中在衣服形变处 |
| 物体先静止、再运动、再停下 | 能开启运动，也能回到 KEEP |

在真实数据里，除了 PSNR、SSIM，还要看三件事：

1. **分得是否合理：** 墙面是否保持不动，整体运动是否使用粗区域，局部形变是否使用细区域。
2. **是否更省：** 实际使用多少运动参数，探测、方案比较和训练一共花了多少时间。
3. **长期是否稳定：** 连续多帧后，背景有没有慢慢漂移。

需要对比“全部用粗区域”“全部用细区域”和“自动选择区域大小”，并匹配首帧模型、训练视角、随机种子与总训练预算。

## 6. 代码改在哪里，接下来怎么跑

原型保留原来的训练入口，新增的逻辑集中在以下位置：

| 顺序 | 位置 | 要做的事 |
| --- | --- | --- |
| 1 | 新增 `model/region_rigid.py` | 实现一整块区域的平移和旋转，让点中心与椭球朝向一起变化 |
| 2 | 新增 `model/selective_motion.py` | 管理三种状态，实现细运动探测、区域合并与最终运动选择 |
| 3 | `model/selective_motion.py` | 先分粗区域，再在各区域内部细分；限制小区域的总数 |
| 4 | `data.py` | 按同一相机读取前后帧图像，固定训练与方案比较所用的视角 |
| 5 | `module.py`、`model/gaussian.py` | 接入训练流程，只把接受的运动写入模型，并记录比较耗时和 GS 增删情况 |
| 6 | 配置和 `tests/test_nested_prototype.py` | 新建独立实验配置，检查上面的行为和训练恢复是否正确 |

参数统一放在 [`config/archive/rule_selective_21.yaml`](../config/archive/rule_selective_21.yaml)，代码从中读取。文档讲思路，具体数值以 YAML 为准。这是历史配置，重跑需使用新的实验名。

首轮已与用户确定：**共享已有首帧，再跑 20 个后续帧，并保留新增 GS 阶段。** 因此配置中的总帧数是 21。每帧分配为探测 40 步、粗区域拟合 60 步、选中运动优化 50 步、新增 GS 50 步。

每帧最多比较 16 个小区域和 16 个内部区域，用 4 个训练视角检查，最多额外渲染 384 次；证据收集和最终复核另计。参数讨论后，训练由用户手动启动：

```bash
conda activate ReConGS
python main.py --pipeline=ReCon-GS --config=config/archive/rule_selective_21.yaml experiment_name=rule_selective_new_run
```

第一阶段先检查三种状态和整体旋转。随后再看画质、运动参数量和实际耗时。方案比较需要额外渲染，不能只用训练步数判断是否更快。

## 实现时再看的补充

**区域旋转的计算。** 设区域中心为 `c`，GS 原来的中心为 `x`，旋转为 `R`，平移为 `t`：

```text
新位置 = R × (x - c) + c + t
```

椭球朝向也要跟着旋转。代码中需核对四元数的乘法顺序，用整体旋转的例子验证。

**比较方案需要控制成本。** 每试一个区域都完整渲染，会很慢。可以先按小区域运动是否接近筛选合并方案，再用少量固定训练视角检查，最后复核完整画面。测试视角留作最终评价。局部检查要覆盖物体移动前后的位置；区域之间的遮挡会互相影响，局部结果不能简单相加。

**还有几种情况要单独处理。** 新出现的内容可能需要新增 GS；现有代码也会合并和删除 GS。这些操作要记录是否影响了静止背景。训练中还需保存区域归属、所选状态和优化器状态，保证中途恢复后能继续正确训练。

**判断能力有边界。** 缺少视角、光照变化或探测时间太短，都可能让运动判断出错。只有图像证据时，不能保证找到了真实物理运动。因此，上面的流程和阈值仍需验证，不能仅凭参数变少就认定成功。
