# V2：四层共享运动 + 逐点修正 + 动态增密

## 每帧训练顺序

首帧保持 S²GS 的原始流程、同一 Flame Steak 配置、3600 step；不创建共享运动层，也不运行 V2 新增点阶段。后续每帧共 400 step：

1. 前 100 step：冻结 S²GS 参数，优化 4 层区域共享位移/旋转及细层启用权重。每个新帧开始时，按当前 anchor 坐标重新分组；该帧的 100 step 内不改变节点成员。“改树”在本版指学习当帧的层级启用和区域形变，不是可微分地增删拓扑节点。
2. 中间 200 step：冻结共享运动，优化已有 GS 的 S²GS 可训练属性和 Gate。
3. 最后 100 step：按 S²GS 的观测次数、层级梯度阈值、体素去重和相机可见性规则选择新增点；若本帧没有合格候选，就不强行增加。每帧最多检查 128 个高梯度候选；这一阶段只优化新增点的 latent，冻结旧点、共享 decoder 和 Gate。下一帧开始前恢复 decoder 的可训练状态。

V2 的 4 层使用 V1 六层的粗层前缀 `[0, 1, 2, 3]`，第 3 层与 S²GS root 对齐。也测试了覆盖更细尺度的 `[0, 2, 3, 5]`，但它在 60 帧预检中画质和存储都不如前缀方案。每帧新点接入同一个 S²GS GaussianModel，并扩展 residual decoder 基准、Gate 索引和已累计的共享形变，使下一帧可以继续使用。

代码入口是 `scripts/run_v2_300.sh`；新增点适配在 `scripts/v2_growth.py`。结果写入 `output/v2_300`，包括逐帧指标、共享运动参数和新增 GS 参数。当前写出的是研究实验数据，还没有独立解码/回放器。

## 首帧与基线的关系

V2 首帧算法路径与当前 S²GS 仓库对齐：数据、配置、随机种子、3600 step、原始训练与增密流程一致；无 V2 共享运动或动态新增点。此前 V1 在无共享运动时多做一次旋转归一化，V2 已移除。

**数值并未严格复现历史基线。**已有 S²GS 300 帧运行的首帧为 35.15 dB、59,745 点；同仓库同配置重新只跑首帧得到 32.3 dB、59,849 点；本仓库去掉额外归一化后的一次首帧是 34.76 dB、59,738 点。本次 V2 300 帧运行的首帧是 34.03 dB、59,919 点。故不能把单次首帧差异直接归因于 V2 方法，也不能宣称位级一致。

## 验证状态

单元测试 7 项通过，短程训练检查了跨帧尺寸与 decoder 解冻。60 帧 Flame Steak 预检的平均测试 PSNR：S²GS 33.63 dB，V2 四层但不增密 34.11 dB，最终候选（S²GS 阈值 + 去重增密）33.83 dB。独立训练的首帧有明显数值波动，短程数字只作方向判断。

初版 V2 因 decoder 跨帧未解冻且增密缺少阈值/去重，到第 100 帧跌至 21.3 dB；该失败运行原样保存在 `output/v2_300_failed_first_attempt`。

## 完整 300 帧结果

正式运行已完成，逐帧数据在 `output/v2_300/training_metrics.json`，汇总在 `output/v2_300/avg_metrics.json`，日志在 `output/v2_300/train.log`。共享运动和新增点各有 299 个逐帧 `.pt` 文件；总计新增 466 个 GS。

| 指标 | V2 | S²GS | 结论 |
| --- | ---: | ---: | --- |
| 平均测试 PSNR | 34.06 dB | 34.02 dB | V2 +0.04 dB |
| 平均 FPS | 168.98 | 237.19 | V2 更慢 |
| 估计每帧存储 | 0.33 MB | 0.04 MB | V2 更大 |
| 完整训练时间 | 3398.98 s | 2883.68 s | V2 更久 |

V2 前 150 帧平均 34.61 dB，S²GS 34.09 dB；后 150 帧 V2 33.51 dB，S²GS 33.96 dB。也就是说，早期的画质优势在后期明显衰减，最终仅剩约 0.04 dB 的名义领先。加上两次首帧不严格相同，**当前不能宣称稳健优于 S²GS**。FPS、存储和训练时间均未达到“至少一项明显更好”的目标。下一步最值得检查的是第三阶段只训练新点是否使旧点无法补偿新增点的扰动。
